# 实例导入

> **学习目标**：把业务数据（Excel/CSV/JSON/文本）导入平台，理解「导入 ≠ 入库」：导入先做**预览校验**，生成**待审核候选**，人工审核后才真正落库。

![实例导入页](assets/ingest-page.png)
*实例导入页：顶部选对象，左侧文件导入/多对象批量/LLM 文本抽取/MCP 连接读取四个入口，右侧结果与候选区*

## 1. 入口与前置

- 实例导入页 → 顶部选中目标**对象**（本体须已发布）；
- 四种导入方式（页内子页签）：

| 方式 | 输入 | 说明 |
|---|---|---|
| **文件导入** | Excel/CSV（带表头） | 列 → 属性字段映射 |
| **多对象批量导入** | 多 sheet 的 Excel/CSV | **一个 sheet 对应一个对象**，sheet 名即对象 `id`，逐个上传 |
| **LLM 文本抽取** | 粘贴业务文本 + 选对象 | LLM 按对象约束抽候选（需配置 LLM） |
| **MCP 连接读取** | 已配置的 MCP 连接 | 从外部 MCP 数据源拉实例（连接在 MCP 页配置，见第 16 章） |

## 2. 字段映射（file 或 field_map 两种形态）

- **文件形态**：上传后平台显示列名 → 属性的**映射表**：把表格列对应到对象的属性/关系字段；关系字段直接填目标实例的业务主键值（如 `产品编码` 列填 `P001`）；映射错了会在预览阶段暴露。
- **field_map 形态**（V2.0 大批量推荐，API 直调）：
  - `POST /api/ingest/preview`，`source = {"kind":"field_map","records":[{...},{...}]}`（**JSON dict 列表**，每行一个对象）；
  - **空字段直接省略该键**——写空字符串 `""` 会触发 SHACL 枚举/必填报 `Value Literal("") not in list`；
  - `object_type` 放 **body**；`mapping.field_map` 放 **body 且必须非空**（列名与属性名一致时用恒等映射 `{k:k}` 即可）；
  - 适合脚本化：从 Excel 读**单元格原值**（不是显示值）转 records 后逐批预览。

## 3. 预览（Preview，不入库）

- 点「预览」：平台对每条记录做**前后端双校验**（必填/类型/约束）；
- 预览通过 → 可「生成候选」（每批一个 candidate，逐条实例 + 健康度可见）；
- 预览失败 → 返回 `violations`（哪条记录、哪个字段、什么错），**当场可见**，改完重传。

## 4. 批准入库

- 审核区（或候选队列）逐批 `approve`：响应返回 **`imported / inserted / dedup / violations`** 四个数——imported 为校验通过条数、inserted 为新入库条数、dedup 为主键重复跳过数、violations 为约束违例数；
- 全部批次 `violations=0` 才算干净入库（V2.0 案例 11 张基线表 + 33 行结果基准，全部 0 违规，见第 20 章）。

## ⚠️ 常见坑

- **导入 ≠ 入库**：预览生成的是「待审核」候选，不入库；必须到审核区批准（第 10 章）；
- **主键不在文件里也可以**：代理主键（如 `IL-DOM-001`）可在生成文件时按规则拼好放进主键列；
- **宽表要先转长表**：一行横跨多列的宽表，导入前按「同一度量被维度切开 → 拆多行」转换（口诀与实例见第 20 章）；
- **空值跳过**：源表「——」空值行/列导入时跳过，别留空字符串（field_map 直接省略键）；
- **列偏移**：表头视觉对齐 ≠ 实际列位（V2.0 案例：人天成本基线 国家=列1/实施主体=列2/产品线=列3-5；人员驻场 等级=列2/服务商从列3 起）——逐列核对再映射；
- **多行表头截断**：服务商/供应商表头可能是多行文本（如 `华夏\n（北京）`），**勿用 `split("\n")[0]` 截断**，否则会把「华夏(北京)/华夏(津鲁冀)」合并导致 lookup 歧义；
- **显示值 vs 精确值**：读单元格**原值**——0.2189 的显示值与原值 0.218895427866865 曾造成 ~0.01 元偏差。
