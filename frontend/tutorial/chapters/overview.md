# 平台总览与主线

> **学习目标**：30 秒看懂平台是什么、解决什么问题；一张表记住 9 个功能页各自的角色；理解「两条质量门」为什么是平台的核心设计。

## 1. 平台是什么

企业业务本体平台 = 企业业务的**语义底座**：

- 把业务流程建模成**可校验、可推理、可被 AI 直接调用**的本体（对象 + 属性 + 关系 + 约束）；
- 业务数据入库前必须过**审核与 SHACL 约束校验**，入库后**不可变**——数据带来源、可审计；
- 通过 **MCP（Model Context Protocol）**把本体与实例暴露给大模型/AI 助手：AI 查的是**结构化事实**，而不是靠训练数据猜——这就是平台对「降低模型幻觉」的定位。

## 2. 六步主线

```
建模 → 校验发布 → 实例导入 → 审核入库 → 视图/图谱 → MCP/AI 调用
```

| 步骤 | 做什么 | 关键约束 |
|---|---|---|
| ① 建模 | 定义对象/属性/关系/约束 | 每个对象必须有主键 |
| ② 校验发布 | 两道门校验 | 未发布不能导入实例 |
| ③ 实例导入 | 文件/字段映射/LLM 抽取/MCP 连接 | 导入≠入库，先出候选 |
| ④ 审核入库 | 人工确认 + SHACL 校验 | 入库后不可变 |
| ⑤ 视图/图谱 | 实例列表/图谱三视图/自然语言查询/推理 | 只读 |
| ⑥ MCP/AI | 发布本体 + token + 4 个工具 | 按项目鉴权 |

## 4. 两条质量门（平台核心设计）

1. **模型门**：本体发布前必须通过校验（每个对象有主键、关系引用不悬空）——坏模型进不了系统；
2. **数据门**：实例必须走 `导入 → 候选（待审核）→ 人工 approve → SHACL 校验 → 入库`，LLM/映射输出**禁止直落库**——坏数据进不了系统。

入库实例**不可变**（不提供写回接口）：要纠正错误数据 = 导入修正版（新实例），旧的留痕可追溯。

## 5. 部门与项目（多租户）

- 右上角「部门 → 项目」两级选择；所有数据接口都按 `?project_id=` 隔离；
- MCP 端点同样**按项目**：`/mcp/{项目id}`，一个项目一个 token。
