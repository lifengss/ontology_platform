# 平台总览与主线

> **学习目标**：30 秒看懂平台是什么、解决什么问题；一张表记住各功能页各自的角色；理解「两条质量门 + 计算铁律」为什么是平台的核心设计。

## 1. 平台是什么

企业业务本体平台 = 企业业务的**语义底座**：

- 把业务流程建模成**可校验、可推理、可被 AI 直接调用**的本体（对象 + 属性 + 关系 + 约束）；
- 业务数据入库前必须过**审核与 SHACL 约束校验**，入库后**不可变**——数据带来源、可审计；
- 用**能力层（公式引擎）**把「取数 + 计算」固化成可解释、可溯源的表达式能力（`lookup` 查基线、`ref` 组能力链）——**一切数值经能力产出，拒绝直接取数**；
- 通过 **MCP（Model Context Protocol）**把本体、实例与能力暴露给大模型/AI 助手：AI 查的是**结构化事实**，而不是靠训练数据猜——这就是平台对「降低模型幻觉」的定位。

## 2. 七步主线

```
建模 → 校验发布 → 实例导入 → 审核入库 → 能力定义（计算） → 视图/图谱 → MCP/AI 调用
```

| 步骤 | 做什么 | 关键约束 |
|---|---|---|
| ① 建模 | 定义对象/属性/关系/约束 + **显式主键（stable_key）** | 每个对象必须有主键 |
| ② 校验发布 | 两道门校验；已发布本体改版走**变更提案**（自动升版） | 未发布不能导入实例 |
| ③ 实例导入 | 文件/字段映射（field_map）/LLM 抽取/MCP 连接 | 导入≠入库，先出候选 |
| ④ 审核入库 | 人工确认 + SHACL 校验 | 入库后不可变 |
| ⑤ 能力定义 | `lookup`/`ref` 公式能力 + 发布锁版 + `dry_run` 试算 | 下游 ref 上游须先发布 |
| ⑥ 视图/图谱 | 实例列表/图谱三视图/自然语言查询/推理（双引擎） | 只读 |
| ⑦ MCP/AI | 发布本体 + token + 9 个工具（含 `capability_call`） | 按项目鉴权 |

## 4. 两条质量门 + 计算铁律（平台核心设计）

1. **模型门**：本体发布前必须通过校验（每个对象有显式主键、关系引用不悬空）——坏模型进不了系统；
2. **数据门**：实例必须走 `导入 → 候选（待审核）→ 人工 approve → SHACL 校验 → 入库`，LLM/映射输出**禁止直落库**——坏数据进不了系统。

入库实例**不可变**（纠正错误数据 = 导入修正版，旧的留痕可追溯）。

V2.0 在此基础上加**计算铁律**（V2.0 案例实践，见第 20 章）：

3. **结果对象只承载「输入维度」**：输出由能力 computed，目标值**永不作为实例导入**（只在比对层读取）；
4. **拒绝直接取数**：任何数值都必须经能力 `lookup + 计算式` 产出，不能读预存结果。

## 5. 登录与部门项目（多租户 + RBAC）

- **V2.0 起启用登录鉴权**：设置页 → 登录（初始管理员 `admin`），登录后右上角显示当前用户与权限矩阵（角色/租户/资源授权）；
- 角色四级：**admin（管理员）/ modeler（建模人）/ reviewer（审核人）/ viewer（查看人）**；权限变更**免重登即时生效**；
- 右上角「部门 → 项目」两级选择；所有数据接口都按 `?project_id=` 隔离；数据共享四级，**实例数据绝不跨租户共享**；
- MCP 端点同样**按项目**：`/mcp/{项目id}`，一个项目一个 token。

> 第 3 章起的示例主要使用「维保服务产品成本模型」项目；第 20 章完整案例使用 V2.0 实战项目「服务产品部-服务器原厂维保成本核算」（19 对象 + 能力链 + MCP 核验），方便你对照真实数据操作。
