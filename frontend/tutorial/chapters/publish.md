# 校验与发布

> **学习目标**：理解「校验并发布」是模型质量门——通过后本体状态变**已发布**，才能开始导入实例；V2.0 起已发布本体不能再直接编辑，改版走**变更提案**（自动升版）。

![发布后的本体](assets/ontology-published.png)
*本体列表：状态徽标「已发布」（绿色）*

## 1. 入口

- 建模页 → 选中目标本体 →「校验并发布」（草稿状态）。

## 2. 两道门

| 门 | 校验什么 | 失败表现 |
|---|---|---|
| **g1 对象主键** | 每个对象都有**显式 stable_key**（指向本对象已存在的 string 属性） | 列出「主键缺失/无效」的对象清单 |
| **g2 关系引用** | 关系的源/目标对象都存在 | 列出悬空引用的关系 |

- 两道门全过 → 状态 `草稿 → 已发布`，列表徽标变绿；
- 任一门失败 → 状态保持草稿，页面列出具体违例，**修完重新点「校验并发布」**即可；
- **warning 不阻断**：校验产出 warning（如语义定义偏短）随响应返回、不卡发布；只有 error 阻断（V2.0 修复，此前 warning 会被当阻断）。

## 3. 变更提案（changeset，V2.0）：已发布本体如何再改

- **active 本体不可直接编辑**——建模页对该本体只有「变更提案」入口；
- 操作：建模页 → 该本体 →「变更提案」→ 提交**完整新模型**（model 为全量对象/属性/关系，不是增量）；
- 平台做**版本 diff**：列出新增/删除的对象与属性，判定 `兼容(true)/破坏(false)`：
  - **兼容变更**（如新增对象/新增属性）→ **自动升小版本并直接发布**（如 v1.0 → v1.1）；
  - **破坏变更**（如删属性/改类型）→ 走**变更审批流**，审批通过才生效；
- 版本演进留痕：V2.0 案例的本体就是 `v1.0（10 对象）→ v1.1（19 对象）→ v1.2/v1.3/v1.4（补字段 + 现场人工基线）` 一路自动升版（见第 20 章）。

![变更提案版本演进](assets/v2-changeset.png)
*变更提案：提交完整新模型后生成版本 diff（新增对象/属性清单、兼容判定、自动升版发布）*

## ⚠️ 常见坑

- **未发布的本体不能导入实例**：实例导入页选不到/选了也导不了；
- **改了模型必须走变更提案**：active 本体没有直接编辑入口；提交的是**完整新模型**，别只传改动部分；
- 校验失败不是玄学——按页面列出的对象/关系名逐个修，别整本体推翻重来。
