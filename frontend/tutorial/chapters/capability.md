# 能力层（派生公式能力）

> **学习目标**：掌握 V2.0 的「能力层」——把「取数 + 计算」固化成可解释、可溯源的表达式能力：`lookup` 回指基线实例、`ref` 串联上游能力组成能力链、发布锁版、`dry_run` 试算与批量执行。这是平台「拒绝直接取数、一切数值经能力产出」的落点。

![能力列表](assets/v2-capability-list.png)
*能力页：已建能力清单（名称/对象类型/版本/状态草稿或已发布）*

## 1. 能力是什么

**能力 = 绑定对象类型的表达式（opl-expr）**：给一个实例 + 一组输入维度，能力按公式**现算**出一个值——读的是已入库基线实例，算的是确定性公式，全程可溯源。

表达式可用的积木：

| 积木 | 作用 | 例 |
|---|---|---|
| `lookup('对象', {维度:值}, '属性')` | **回指基线实例**：按维度键查已入库实例的属性 | `lookup('onsite_rate_baseline', {product_line:'SV', region:'国内'}, 'rate')` |
| `ref('cap_xxx')` | **引用其他已发布能力**，组能力链 | `ref('cap_onsite_rate_d')` |
| `if(cond, a, b)` / `if_null(x, d)` | 条件分支 / 空值守卫 | `if_null(rate, 0)` |
| `+ - * /`、常量 | 四则运算 | `e + k + n` |

**null 传播铁律**：算术遇 null 得 null（**禁止当 0**），要显式 `if_null()` 守卫——宁可算出 null 暴露缺数据，不可静默出 0。

## 2. 能力编辑器

- 「能力」页 →「＋ 新建能力」：填 **name（cap_id）/ 显示名 / 对象类型 / 表达式**；
- 编辑器内可用 lookup/ref/if/if_null/四则运算，提供**校验**（语法 + ref 是否可解析）与**发布**按钮；
- **AI 生成**：用自然语言描述业务场景（如「维保成本 = 工时成本 + 备件成本；成本 = 上门率 × 标准工日 × 日费」），AI 结合所选本体的对象模型生成公式能力草稿——生成后**必须人工核对**再发布。

## 3. 能力链案例（五大核算域）

V2.0 案例（第 20 章）用一条能力链把《成本核算说明》的取数关系全部固化：

```
cap_onsite_rate_d = 现场服务率基线(产线×客户×区域).rate × 年限系数(3年1.0/4年1.4/5年1.88)
cap_labor_cost_e  = ref(cap_onsite_rate_d) × 售后人工成本基线(u_group×客户×区域×服务等级).unit_cost
cap_spare_aux_k   = ref(cap_onsite_rate_d) × 备件辅助成本基线(国家).unit_nd/unit_4h/unit_rma/unit_arma
cap_mgmt_cost_n   = ref(cap_onsite_rate_d) × 管理成本基线(客户×售后×区域).value
cap_total_o       = cap_labor_cost_e + spare_direct(F) + cap_spare_aux_k + cap_mgmt_cost_n
cap_ratio_s       = ref(cap_total_o) / machine_cost(R=37672)
```

模式：**叶子能力 `lookup` 基线 → 中间能力 `ref` 叶子做乘法 → 汇总能力加法 → 比例能力除法**。后续核算域（人天/驻场/海外出差/焕新/单次维修）同构扩展。

## 4. 执行：dry_run 试算与批量

- **`dry_run: true`（只读试算）**：选实例 + 填输入维度（`inputs`）→ 只算不写回。核验/验收一律用 dry_run——**待测结果不落为实例**；
- **写回执行**：`dry_run: false` 把结果写回实例属性（V2.0 接回写风险分级门禁，见第 14 章）；
- **批量执行（execute-batch）**：大批量实例逐条执行（大批量注意服务端分块与限流）；
- 执行返回**溯源四要素**：**能力版本 + 输入维度 + lookup 命中（matched_record_id 与原始值）+ 计算值**——结果可逐项解释、可复算。

## 5. 版本与发布

- 能力草稿 →「发布」：**锁定引用版本**（如 v1.0.0），之后才能被下游 `ref`、被 MCP `capability_call` 调用；
- 已发布能力**内容变更自动发新版**（minor+1，旧版可溯源）；**被引用的能力不可删除**；
- **下游 ref 上游，必须先发布上游能力**，否则 `REF_NOT_RESOLVED`（见下坑③）。

## ⚠️ 常见坑（实战高频，必记）

1. **`binds` 无条件预求值**：`binds` 里 `a = this.x` 即使没被命中分支用到也会先求值——键缺失即报 `MISSING_INPUT_ATTR`；**可选属性要内联进 `if()` 条件表达式**，不要放 binds；
2. **尾位避免多行嵌套 `if()`**：先 bind 变量、final 只放单层选择，嵌套过深易出错难读；
3. **ref 解析失败**：下游 `ref` 的上游能力**未发布** → `REF_NOT_RESOLVED`；先 `发布` 上游再建下游；
4. **按 cap_id 调用**：能力执行/调用一律用 **cap_id**（如 `cap_total_o`），按显示名/name 会 `NOT_FOUND`；
5. **`inputs` 合并语义 = 覆盖 + 缺失回落实例值**：调用方漏传某个输入键会**静默沿用实例上已存的值**——脚本/Agent 侧必须显式传全所有输入键，否则批量结果静默失真。
