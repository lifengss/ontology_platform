# 设置约束与关系

> 学习目标：能为属性配置约束（长度 / 正则 / 取值范围 / 枚举值），正确建立对象关系（含多对多），并理解约束在后续环节的作用。

## 1. 属性约束

在属性表的某行点**「约束」**链接，展开该属性的约束编辑器（已配置的约束行会有 ● 标记）：

| 约束 | 字段 | 适用类型 | 示例 |
|---|---|---|---|
| 长度 | 最小长度 / 最大长度 | string | `2 ~ 16` |
| 正则 | pattern | string | `^[0-9]+$` |
| 取值范围 | 最小值 / 最大值 | integer / float | `0 ~ 100` |
| 允许值 | 枚举值（逗号分隔） | 与数据类型匹配 | `美元, 欧元, 日元` |

![属性约束展开](assets/constraint-editor.png "属性行「约束」展开：最小/最大长度、正则、最小/最大值、枚举值")

## 2. 约束在哪里生效

- **候选审核 / 入库**：确认候选时，字段值对照约束做合法性检查（必填、长度、正则、取值范围、枚举），不合格的会被拦截
- **AI 查询**：MCP 工具描述包含属性定义与约束信息，AI 按枚举值 / 范围过滤作答

> 枚举值适合**可枚举**的字段（币种、国别、状态、类别）；连续值用取值范围；string 用长度 / 正则收紧格式。

## 3. 关系（含多对多）

对象卡片的**关系**区（见第 3 章 §4）：

1. **＋ 关系**：关系 ID + 显示名称 + 目标对象 + 基数
2. 多对多基数选 **`N:N`**——平台自动创建**隐藏中间对象类**承载关系（RDF 存储要求）
3. `1:1` / `1:N` / `N:1` 按实际业务选择

> ⚠️ 高频坑：多对多关系基数误选单值（`1:1` / `N:1`）。导入后多对多数据按单值存储，AI 查询只返回一个值，且无法纠正——建模阶段就要选对。

## 4. 全局约束（可选）

表单底部的**全局约束**区可定义跨属性的 **unique 唯一**约束：约束 ID + 名称 + 作用对象（scope）+ 目标属性。例：SKU 唯一（scope=产品，attribute=attr_sku）。
