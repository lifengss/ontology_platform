# 属性约束与关系

> **学习目标**：给本体的属性加「约束」（值域规则），给对象间加「关系」（含多对多 N:N）。约束是**数据质量门**的一部分：导入时平台按约束校验，不合格的实例进不了库。

![约束编辑器](assets/constraint-editor.png)
*约束编辑器：左侧对象/属性树，右侧约束类型、参数与说明*

## 1. 什么是约束（Constraint）

约束 = 属性取值必须满足的规则。本体清单（如 `attribute.csv`）里 `length` 列非空的行就是约束，建本体时**必须落实**，否则清单与本体会不一致。

- 入口：建模页 → 选中对象 →「约束」编辑区（属性行右侧的约束图标）；
- 一条约束属于「某个对象的某个属性」，可加多条（AND 语义）。

## 2. 四类约束

| 类型 | 参数 | 语义 |
|---|---|---|
| **长度** `length` | `min` / `max` | 字符串长度范围（如编码 4～32 位） |
| **正则** `pattern` | 正则表达式 | 值必须匹配（如 `^[A-Z]{2}\d{3}$`） |
| **范围** `range` | `min` / `max`（数值） | 数值区间（如价格 ≥ 0） |
| **枚举** `enum` | 值列表 | 值必须在列表内（如 `["1U","2U","4U"]`） |

> 注意：约束编辑器**没有「单位」字段**——单位/量纲语义写在属性「描述」里，不要另造字段。

## 3. 关系与多对多（N:N）

关系在对象间定义（源对象 → 目标对象 + 关系名 + 基数）：

- 基数三选一：`1:1`、`1:N`、`N:N`；
- **多对多就是基数 `N:N`**，没有单独的「多对多」开关；
- 例：`成本项 —适用→ 产品` 与 `成本项 —适用→ 物料` 均为 `N:N`；
- 关系两端对象必须已存在，否则「校验并发布」会报悬空引用。

## ⚠️ 常见坑

- **清单里有约束却漏建**：对照清单 `length` 非空的行逐条检查，一条都不能少；
- **枚举值与材料不一致**：材料/业务表里的枚举文字与本体枚举不一致时，要按本体为准做映射（如 `3U/4U/5U` → `2U高密度及3U4U5U`），导入前处理；
- **约束是校验依据**：加了约束后，导入不合规值会被 preview 阶段拦下（422 + violations），不是入库后才报错。
