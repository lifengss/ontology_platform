# 建模：表单建模

> **学习目标**：掌握「表单建模」——平台最基础、最可控的建模入口。本例以「维保服务产品成本模型」为例：3 个对象（产品/物料/成本项）+ 成本项多对多引用产品/物料；完整案例背景见第 19 章。

![本体列表](assets/modeling-list.png)
*本体列表：左侧列出当前项目的本体，状态徽标「已发布/草稿」*

## 1. 入口

- 点左侧「建模」页 → 右上「＋ 新建」（已有本体可直接点击进编辑区修改）。
- 编辑区顶部有三个子页签：**表单建模 | AI 生成 | 文档逆向**（后两者分别见第 4、5 章），本章用「表单建模」。

![表单建模](assets/modeling-form.png)
*新建本体：表单建模子页签，右侧为对象/属性编辑区*

## 2. 本体的元信息

- **名称**：业务可读名（如「维保服务产品成本模型」）。
- **描述**：一段话说明本体的业务范围——AI 生成与自然语言查询都依赖它理解语义，建议写清「覆盖哪些对象、核心关系」。
- 保存时先落**草稿**（状态徽标「草稿」），校验通过并确认后才是「已发布」。

## 3. 对象（ObjectType）

点「＋ 添加对象」，每个对象填：

| 字段 | 说明 |
|---|---|
| `id` | 系统生成 `obj_xxx`，唯一 |
| `name` | 对象名（如 `产品`） |
| 描述 | 业务含义（AI 会读） |

- 对象**不能重名**（同本体内）；
- 对象是实例的「类」：导入的每条实例都归属某个对象。

## 4. 属性（Attribute）

对象下点「＋ 添加属性」：

| 字段 | 取值 |
|---|---|
| 名称 | 如 `产品编码` |
| 数据类型 | `string` / `integer` / `float` / `boolean` / `date`（**只有这 5 种**） |
| 必填 | 是/否 |
| 描述 | 业务含义（AI 会读） |

**主键规则（自动判定，不是手动勾）**——三级回退：

1. 对象的**第一个「必填 + string」属性** → 主键（行内 🔑 徽标，推荐显式这样排）；
2. 没有则退化为**第一个 string 属性**；
3. 再没有则退化为**第一个属性**（此时强烈建议补一个字符串主键属性）。

想让某个属性当主键 → 把它设为必填、string 类型、并排在属性列表**第一行**；不要在其前面插入其他「必填 + string」属性，否则主键会漂移。

> ⚠️ 数据类型**没有** decimal/money 之类——金额用 `float`，精度语义写在「描述」里。

## 5. 关系（Relation）

对象间点「＋ 添加关系」：

| 字段 | 说明 |
|---|---|
| 源对象 / 目标对象 | 关系两端 |
| 关系名 | 如 `使用`（产品 —使用→ 物料） |
| 基数 | `1:1` / `1:N` / `N:N`（**多对多就是 N:N**，没有单独的"多对多"选项） |

- 关系两端对象都必须已存在，否则校验报「悬空引用」；
- 实例导入时，关系字段填**目标实例的主键值**（如 `M001`）。
