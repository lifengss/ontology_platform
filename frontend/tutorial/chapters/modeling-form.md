# 建模：表单建模

> **学习目标**：掌握「表单建模」——平台最基础、最可控的建模入口。本例以「维保服务产品成本模型」为例：3 个对象（产品/物料/成本项）+ 成本项多对多引用产品/物料；完整案例背景见第 20 章。

![本体列表](assets/modeling-list.png)
*本体列表：左侧列出当前项目的本体，状态徽标「已发布/草稿」*

## 1. 入口

- 点左侧「建模」页 → 右上「＋ 新建」（已有本体可直接点击进编辑区修改）。
- 编辑区顶部有三个子页签：**表单建模 | AI 生成 | 文档逆向**（后两者分别见第 4、5 章），本章用「表单建模」。

![表单建模](assets/modeling-form.png)
*新建本体：表单建模子页签，右侧为对象/属性编辑区*

## 2. 本体的元信息

- **名称**：业务可读名（如「维保服务产品成本模型」）。
- **描述**：一段话说明本体的业务范围——AI 生成与自然语言查询都依赖它理解语义，建议写清「覆盖哪些对象、核心关系」。
- 保存时先落**草稿**（状态徽标「草稿」），校验通过并确认后才是「已发布」。

## 3. 对象（ObjectType）

点「＋ 添加对象」，每个对象填：

| 字段 | 说明 |
|---|---|
| `id` | 系统生成 `obj_xxx`，唯一 |
| `name` | 对象名（如 `产品`） |
| 描述（业务语义定义） | 业务含义（≥5 字，AI 会读） |
| **稳定键 stable_key** | **显式选择**本对象的一个 string 属性作业务主键（🔑 徽标）；组合维度没有单一主键时，先加一个合成 `code` 属性（string、必填）再选它 |

- 对象**不能重名**（同本体内）；
- 对象是实例的「类」：导入的每条实例都归属某个对象；
- 每个对象**必填**「业务语义定义」与「稳定键 stable_key」——缺了校验卡发布。

## 4. 属性（Attribute）

对象下点「＋ 添加属性」：

| 字段 | 取值 |
|---|---|
| 名称 | 如 `产品编码` |
| 数据类型 | `string` / `integer` / `float` / `boolean` / `date`（**只有这 5 种**） |
| 必填 | 是/否 |
| 描述 | 业务含义（AI 会读） |

**主键规则（V2.0 起显式指定）**：

- 在对象详情的「稳定键 stable_key」下拉里**直接选**一个本对象的 string 属性作为业务主键（行内 🔑 徽标）；
- 主键指向的属性必须已存在且类型为 string，否则校验报「稳定键未指定/指向不存在属性」；
- **组合维度**（如 区域+服务等级）没有单一业务主键的对象 → 先加一个合成 `code` 属性（string、必填），取值拼维度（如 `IL-DOM-001`），再把 stable_key 选为 `code`——这是平台约束，不是材料字段；
- 存量旧本体（V1 时代未显式指定）仍按三级回退兜底判定：第一个「必填 + string」属性 → 第一个 string 属性 → 第一个属性。

> ⚠️ 数据类型**没有** decimal/money 之类——金额用 `float`，精度语义写在「描述」里。

## 5. 关系（Relation）

对象间点「＋ 添加关系」：

| 字段 | 说明 |
|---|---|
| 源对象 / 目标对象 | 关系两端 |
| 关系名 | 如 `使用`（产品 —使用→ 物料） |
| 基数 | `1:1` / `1:N` / `N:N`（**多对多就是 N:N**，没有单独的"多对多"选项） |

- 关系两端对象都必须已存在，否则校验报「悬空引用」；
- 实例导入时，关系字段填**目标实例的主键值**（如 `M001`）。
