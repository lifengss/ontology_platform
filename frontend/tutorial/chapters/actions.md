# 业务动作

> **学习目标**：理解「业务动作（Action）」——把业务流程中的可执行操作（审批、派单、结算…）建模成对象，供后续写回与 MCP `action_invoke` 使用。**MVP 现状：动作只定义与展示，写回未开发。**

## 1. 动作是什么

- 动作 = 本体中可被触发、有输入参数（参数 schema）、有执行语义的操作定义；
- 入口：左侧「业务动作」页 → 列表查看 /「＋ 新建动作」编辑名称、描述、参数 schema。

## 2. MVP 边界（重要）

- 页面已明示：**写回未开发**——MVP 阶段动作只做**定义与展示**，不会被真正执行；
- 已预留的能力：
  - `dry-run` 语义（试算不落地）；
  - MCP 工具 `action_invoke`（参数 `action_id` + `confirmation_token`）作为**确认执行入口**的协议位。
- 不要假设当前版本里"点一下动作就会改数据"——平台的实例数据本身也是不可变的（第 10 章）。

## ⚠️ 常见坑

- 给 AI 配了 MCP 后，`action_invoke` 在 MVP 下不会产生写回——调用会得到协议层响应，但**数据不变**；
- 动作参数 schema 写清楚（字段名/类型/必填），后续写回开发时直接复用。
