数据健康度（V2-21 核心四维）

          

            完整性（键/必填填充率、关系指向解析率）· 唯一性（stable_key 重复率）· 合规性（SHACL 违规率按属性细分、枚举值域命中率）· 新鲜度（按来源连接，陈旧阈值可配）。
            指标观测/告警为主，不阻断；恒伴随规模展示；趋势线标注口径/规模变化（caliber_changed 不等同于质量下降）。
            执行通道：local_snapshot（键/关系/新鲜度）· local_full（上传值全量）· governance_sampled（源连接治理身份采样）· source_required（显式标记未读源）。

MCP 接入

            

          

          

          

          
    
            
  • 接入 token（必配）：外部客户端连接本端点需携带 Authorization: Bearer <token>（或 URL ?token=）；未配置/失效时端点一律 401。token 在本页生成/轮换/吊销，旧 token 立即失效。
    • 
            
  • Streamable HTTP 端点（推荐，2025-03-26 / 2025-06-18 协议）：POST /mcp/{项目id} 直接发 JSON-RPC（initialize / tools/list / tools/call…），响应头带 Mcp-Session-Id；带 session 头 GET 同路径打开事件流，DELETE 结束会话。会话空闲 30 分钟自动失效（重新 initialize 即可）。
    • 
            
  • SSE 端点（2024-11-05 兼容）：GET /mcp/{项目id}（Accept: text/event-stream）建立 SSE 长连接获知消息端点；POST /mcp/{项目id}/messages/ 发 JSON-RPC。旧版客户端无需改造，同样需要 token。
    • 
            
  • 每个项目一个 MCP Server：按项目区分，不同项目端点独立、可同时发布互不影响。
    • 
            
  • 发布粒度是「单个本体」：在本体发布清单中逐项发布/取消发布；同一项目多个已发布本体共享同一端点（工具按 ontology_id 参数区分本体），项目内无任何已发布本体时端点自动下线（连接返回 404 NOT_PUBLISHED）。
    • 
            
  • 发布态保存在磁盘：后端重启后发布关系自动恢复，无需重新发布（本体与实例数据不受影响）。

MCP Server 接入配置（当前项目，可直接粘贴到 AI 平台）

            
          

          

            

              

            

            

              

              
    
                
  • 端口：后端固定监听 0.0.0.0:8000，配置中的 http://127.0.0.1:8000 即本机直连地址；若 AI 平台不在本机运行，把 127.0.0.1 换成运行本平台的机器局域网 IP 即可（后端已监听所有网卡）。
    • 
                
  • 粘贴位置：AI 平台的 MCP / MCP Servers 设置（Claude Desktop 的 claude_desktop_config.json、Cherry Studio、CodeBuddy、Cursor 等），结构即 mcpServers。
    • 
                
  • 默认生成 "type": "streamableHttp"（Streamable HTTP，推荐，WorkBuddy / Cherry Studio / Cline 等）；Claude Desktop / Cursor 把 type 改成 "http"；只支持旧版 SSE 的客户端改成 "sse"（URL 不变，/messages/ 由客户端握手时自动协商）。
    • 
                
  • 配置中的 Authorization 头即上方接入 token（静态 Bearer，粘贴即连、无 OAuth 授权页）；token 轮换/吊销后旧值立即失效，需刷新本页面重新复制并同步 AI 平台侧配置。
    • 
                
  • 本地 WorkBuddy 特例：其连接器 UI 把自定义 HTTP MCP 一律当作 OAuth 型（会卡在「授权中…」，平台无 OAuth 端点，属 WorkBuddy 客户端限制）——本地接入请改用 stdio 桥：WorkBuddy mcp.json 配 "type": "stdio" 指向 backend/mcp_stdio_bridge.py + --project <项目id>（token 由桥内部读取，WorkBuddy 侧无鉴权环节；stdio 配置勿写 env 字段），详见 docs/MCP接入配置-方案C静态Token.md §三。
    • 
                
  • 发布态已持久化：后端重启后发布关系自动恢复，本配置内容不变。
