MCP 接入

            

          

          

          
    
            
  • SSE 端点（GET /mcp/{项目id}）：AI 客户端的「连接入口」——建立一条 Server-Sent Events 长连接，客户端在此接收服务端事件，并从中获知消息端点地址。
    • 
            
  • 消息端点（POST /mcp/{项目id}/messages/）：握手完成后，客户端把 JSON-RPC 请求（initialize / tools/list / tools/call 等）发到该地址，响应经 SSE 通道返回。配置 AI 平台时一般只填 SSE 端点，消息端点由客户端自动协商，无需手填。
    • 
            
  • 每个项目一个 MCP Server：按项目区分，不同项目端点独立、可同时发布互不影响。
    • 
            
  • 发布粒度是「单个本体」：在本体发布清单中逐项发布/取消发布；同一项目多个已发布本体共享同一端点（工具按 ontology_id 参数区分本体），项目内无任何已发布本体时端点自动下线。
    • 
            
  • 发布后，支持 MCP 的外部 AI 助手/系统即可通过端点读取本项目的本体与实例。
    • 
            
  • 发布状态保存在内存中：后端重启后需重新发布（本体与实例数据不受影响）。
    •

MCP Server 接入配置（当前项目，可直接粘贴到 AI 平台）

            
          

          

            

              

            

            

              

              
    
                
  • 端口：后端固定监听 0.0.0.0:8000，配置中的 http://127.0.0.1:8000 即本机直连地址；若 AI 平台不在本机运行，把 127.0.0.1 换成运行本平台的机器局域网 IP 即可（后端已监听所有网卡）。
    • 
                
  • 粘贴位置：AI 平台的 MCP / MCP Servers 设置（Claude Desktop 的 claude_desktop_config.json、Cherry Studio、CodeBuddy、Cursor 等），结构即 mcpServers。
    • 
                
  • 只需填 SSE 端点；消息端点 /messages/ 由客户端在 SSE 握手时自动协商，无需手填。
    • 
                
  • 发布状态在内存中：后端重启后需在上方清单重新发布，本配置内容不变。
