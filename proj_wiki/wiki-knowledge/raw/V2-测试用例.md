## 一、架构不变式横切用例（P0，全部渠道执行）

#### TC-INV-01 实例数据模型：源连接型值不落地 【P0/功能+负向】
- **前置**：本体含源连接型对象（接 3 mock）与上传型对象（2297 实例）；已完成入库
- **步骤**：① dump 平台侧存储（Jena 命名图/关系快照存储/上传值存储）→ ② 检查源连接型实例字段构成 → ③ 本地读取上传型值抽查
- **预期**：源连接型实例仅存关系快照（stable_key/类型/关系边/治理元数据），**无非键内容值**；快照字段完整；上传型值本地可正常读取

#### TC-INV-02 实例永不共享 【P0/安全】
- **前置**：同一源连接型本体，账号 A（owner）/B（共享范围内、C（范围外）；B/C 在源系统权限范围不同
- **步骤**：① 设本体"部门共享"→ ② B/C 经 API＋UI 读 schema → ③ B/C 查实例 → ④ 以 A、B 身份分别发起源连接内容联邦读
- **预期**：B 可见 schema、C 不可见；实例两者均不可见；源连接内容按访问者权限返回（A、B 返回范围不同）；共享变更留审计

#### TC-INV-03 AI 只在构建侧、不在执行侧 【P0/安全】
- **步骤**：① 同一编排同一触发连跑 3 次，记录每次执行路径（节点序列/分支选择/参数值）→ ② 经 API 向编排传代码/任意表达式字段 → ③ 检查编排 UI 有无脚本入口
- **预期**：3 次执行路径完全一致（可复现）；API 拒绝代码字段（422）；页面无脚本/任意表达式入口；运行时 LLM 不参与分支决策/工具选择/参数填充

#### TC-INV-04 审计不可篡改 【P0/安全】
- **步骤**：① 依次执行建模/审批/入库/删除/回写/权限变更，逐一验证产生审计 → ② 经各类接口尝试修改/删除既有审计记录
- **预期**：审计含 who/when/what/前后值；所有修改/删除尝试被拒绝，且尝试本身留痕

#### TC-INV-05 版本引用机制统一 【P1/功能】
- **前置**：存在融合本体与 schema 已发布版本 v1
- **步骤**：① 消费方固定引用 v1 → ② 提供方升级到 v2（含不兼容变更）→ ③ 消费方再读取 → ④ 另一消费方未指定版本读取
- **预期**：固定引用始终读 v1 内容且旧版可用；未指定默认最新稳定版（v2）

#### TC-INV-06 外部对接统一 MCP 【P1/功能+负向】
- **步骤**：① 盘点平台对外部系统的对接接口清单 → ② 尝试调用数据库直连类接口（JDBC/SQL 适配器路径）
- **预期**：全部外部对接经 MCP 工具完成；不存在数据库直连类接口（404/未定义）

## 二、V2-01 数据字典与联邦查询

#### TC-01-01 术语查找：PN码三系统合并 【P0/功能】
- **前置**：3 mock 在线（字段名各异：PN/PN码/PN_Num）；字典已配置规范术语"PN码"→三系统字段
- **步骤**：① 调 term_lookup"PN码 xxxxx 的备件"→ ② 检查合并结果与来源标记
- **预期**：三系统均命中并合并返回，每条记录带来源系统标记

#### TC-01-02 未配置系统显式提示不覆盖 【P0/负向】
- **步骤**：① 移除水库系统"PN码"字典映射 → ② 查同一术语 → ③ 检查返回
- **预期**：显式提示"水库系统未覆盖"，不静默漏查；其余系统正常返回

#### TC-01-03 field_map 收敛引用字典 【P0/功能】
- **步骤**：① 盘点入库/查询方向 field_map 配置来源 → ② 修改字典一处映射 → ③ 分别执行入库与查询验证
- **预期**：field_map 单点引用字典、无双处维护；字典变更后入库/查询行为一致

#### TC-01-04 同义表达解析到规范术语 【P0/功能】
- **步骤**：① 分别以"PN码/PN/PN号"查询 → ② 比对三次结果 → ③ 查看术语解析路径
- **预期**：三者均解析到同一规范术语、结果一致；解析路径（输入词→规范术语、匹配方式、置信度）可见

#### TC-01-05 歧义返回候选不自动选取 【P0/功能】
- **前置**：构造两个相近规范术语（"PN码"与"PN码(旧)"），输入词"PN"同时高相似
- **步骤**：① 输入"PN"查询 → ② 人工晋升"PN"为"PN码"同义词 → ③ 再输入"PN"查询
- **预期**：第一次返回候选列表＋置信度、不自动选取；晋升后走精确匹配路径

#### TC-01-06 全量拉取型工具成本提示 【P1/功能】
- **前置**：某 mock 工具仅支持全量拉取
- **步骤**：① 发起会触发全量拉取的查询 → ② 检查预览成本提示 → ③ 传递分页/limit 参数验证
- **预期**：声明拉取上限＋预览给成本提示（可取消）；分页/limit 向下传递生效

#### TC-01-07 同键跨系统值不一致 【P1/功能】
- **前置**：准备同 PN 跨系统值不一致样本（数据集"三系统 PN 码联邦查询集"）
- **步骤**：① 未配权威源时查询 → ② 为该术语配置权威来源系统 → ③ 再查询
- **预期**：未配→双值并存＋来源标记、不静默覆盖；已配→按权威源取值、另一值仍可查

#### TC-01-08 联邦查询失败路径 【P1/故障演练】
- **步骤**：① mock CRM 超时（超熔断阈值）→ 查询 → ② 停掉全部 3 系统 → 查询
- **预期**：单系统故障不影响其他系统结果（显式标记）；全失败显式报错、不返回空伪装成功

#### TC-01-09 联邦查询全过程可审计 【P1/功能】
- **步骤**：① 执行 TC-01-01 查询 → ② 检索审计
- **预期**：全过程（输入词、解析路径、命中系统、返回规模、成本）可审计

### V2-01 异常流

#### TCE-01-01 单系统 MCP 超时 【P0/故障演练】
- **步骤**：① mock 单系统超时/不可用 → ② 发起联邦查询
- **预期**：该系统显式报错标记，其余系统结果正常返回，整体不失败（与 TC-01-08 互证）

#### TCE-01-02 全部系统不可用 【P0/故障演练】
- **步骤**：① 停掉 3 个 mock → ② 发起联邦查询
- **预期**：显式错误返回，**不返回空结果伪装成功**

#### TCE-01-03 源端返回脏数据 【P1/负向】
- **步骤**：① mock 返回缺键字段/类型不符/多余嵌套数据 → ② 发起联邦查询
- **预期**：拒收并报错定位（指明系统/字段），不进入合并结果

#### TCE-01-04 全量拉取触上限 【P1/负向】
- **步骤**：① 构造触发拉取上限的全量拉取请求 → ② 检查预览与执行
- **预期**：预览阶段成本提示明确，用户可确认继续或取消，不静默截断

#### TCE-01-05 术语无命中 【P1/负向】
- **步骤**：① 输入字典中不存在的词（无任何相似命中）查询
- **预期**：提示"未匹配"＋候选建议（如有弱相似），**不猜测映射**

#### TCE-01-06 字典冲突配置 【P2/负向】
- **步骤**：① 将两个规范术语绑定到同一系统字段 → ② 保存字典
- **预期**：保存时校验告警，指出冲突项，不静默接受

## 三、V2-02 多本体对齐与融合

#### TC-02-01 等价声明后跨本体合并查询 【P0/功能】
- **前置**：双本体"供应商"对齐集（键重叠 1200/1380）；会签已生效的等价声明
- **步骤**：① 查询键值相同的供应商（跨两本体）→ ② 查询键值不同的供应商
- **预期**：键值相同→一条合并记录（双来源标记）；键值不同→两条独立记录

#### TC-02-02 同键属性值冲突处理 【P0/功能】
- **前置**：对齐集中含值冲突样本
- **步骤**：① 未配权威源查询冲突键 → ② 配置权威源后查询
- **预期**：未配→双值并存＋冲突标记；已配→按权威源取值、另一值可查；均不静默覆盖

#### TC-02-03 融合不改原本体数据（负向断言） 【P0/负向】
- **步骤**：① 记录融合前原本体实例集/键/关系/血缘 → ② 完成融合 → ③ 比对原本体数据 → ④ 检查平台侧有无源连接内容快照、上传型值有无被复制发放
- **预期**：原本体数据不变、血缘保持到源系统；源连接内容永远源端按需取；上传型值不因融合复制发放

#### TC-02-04 冲突检测属性级报出 【P1/功能】
- **步骤**：① 触发融合冲突检测（含值域/必填/主键冲突样本）
- **预期**：报出属性级冲突明细（冲突属性/类型/两侧值）

#### TC-02-05 融合本体版本管理 【P1/功能】
- **步骤**：① 对融合本体连续发布 v1/v2 → ② 查历史版本 → ③ 语义 diff v1↔v2 → ④ 回滚到 v1 → ⑤ 消费方固定引用 v2
- **预期**：历史可查；diff 输出语义级差异；回滚成功且数据一致；固定引用生效

#### TC-02-06 候选对齐检测四类信号 【P1/功能】
- **前置**：双本体"供应商"对齐集（含共同来源、语义/结构相似样本）
- **步骤**：① 运行候选对齐扫描 → ② 检查提案证据 → ③ 接受一条提案 → ④ 拒绝一条 → ⑤ 再次扫描
- **预期**：四类信号（键重叠/共同来源/语义相似/结构相似）均产出提案（证据＋置信度）；接受→预填等价声明；拒绝→不再提示（证据显著变化才重现）

#### TC-02-07 候选对可见性约束 【P0/安全】
- **前置**：用户 X 同时可见本体 A/B，不可见本体 C；B、C 存在可对齐对象
- **步骤**：① 以 X 身份运行候选扫描 → ② 检查提案清单 → ③ 以 X 身份对不可见本体发起手动声明
- **预期**：提案仅含 X 同时可见的本体对；C 的名称/对象名不出现；键值比对同样限可见范围

#### TC-02-08 跨 owner 会签规则 【P0/安全】
- **步骤**：① 发起跨 owner 等价声明 → 部分 owner 通过、一个驳回 → ② 全部通过后验证生效 → ③ 同 owner 场景声明 → ④ owner 缺位由租户管理员代行 → ⑤ 非 owner 绑定公开本体
- **预期**：任一 owner 驳回→不保存生效（一票否决）；全通过→生效；同 owner 直接生效；代行使留审计；公开本体不可被非 owner 绑定；共享等级不携带审批权

#### TC-02-09 实例数据模型分渠道 【P0/负向】
- **步骤**：① 融合后 dump 平台侧源连接型实例 → ② 检查上传型实例
- **预期**：源连接型只存关系快照（INV-1 负向断言）；上传型值落地本地

#### TC-02-10 联邦读代查与权限 【P0/功能】
- **前置**：访问者 A/B 在源系统权限范围不同；身份映射（V2-14）已配置
- **步骤**：① 以 A 身份联邦读 → ② 以 B 身份联邦读 → ③ 检查合并方式 → ④ 触发源端超时/超成本
- **预期**：均以访问者身份代查、源端按该访问者权限返回（同本体 A/B 范围不同）；按键合并＋来源标记；超时/熔断/成本护栏生效

#### TC-02-11 跨本体虚拟融合查询 【P1/功能】
- **步骤**：① 对已声明等价的本体对发起虚拟融合查询 → ② 检查 join 依据与去重 → ③ 比对源本体实例/快照
- **预期**：按等价声明＋键对齐做快照 join；内容分渠道获取；合并去重正确；实例/快照不动

#### TC-02-12 物化快照（派生图） 【P2/功能】
- **步骤**：① 默认状态下检查有无派生图 → ② 显式开启 → ③ 检查派生标记 → ④ 源本体变更后重建
- **预期**：默认关闭不生成；开启后标注"派生数据非权威"；源变更后按触发重建

#### TC-02-13 手动等价声明兜底通道 【P2/功能】
- **步骤**：① 手动创建等价声明（跨 owner、含不可见对象各一次）
- **预期**：与自动通道同样校验可见性规则与会签规则（不可见被拒、跨 owner 走会签）

#### TC-02-14 对不上键保持独立记录 【P2/功能】
- **步骤**：① 查询对齐集中键不重叠的实例 → ② 查看治理指标
- **预期**：保持两条独立记录（来源本体标记）；实例对齐率作为治理指标展示

### V2-02 异常流

#### TCE-02-01 会签驳回与撤回 【P0/功能】
- **步骤**：① 发起跨 owner 会签 → ② 某 owner 驳回（填原因）→ ③ 检查状态/通知 → ④ 发起新会签后由发起人撤回
- **预期**：驳回→声明不保存生效、通知发起人、可重新提交、留痕；撤回后状态归位、无悬挂"待审"

#### TCE-02-02 属性级冲突显式决策 【P1/功能】
- **步骤**：① 触发含值域/必填/主键冲突的融合 → ② 检查冲突报告 → ③ 分别执行"配权威源"与"放弃该属性"决策
- **预期**：冲突报告完整展示；用户显式决策后生效；不自动合并

#### TCE-02-03 回滚到非法版本 【P2/负向】
- **步骤**：① 对融合本体回滚到不存在的版本号
- **预期**：拒绝并提示可用版本列表

#### TCE-02-04 跨可见范围手动声明 【P0/安全】
- **步骤**：① 对不可见对象发起手动等价声明
- **预期**：拒绝（同 TC-02-07 安全断言）

#### TCE-02-05 源端无权限联邦读 【P0/安全】
- **步骤**：① 访问者在源端对目标数据无权限 → ② 发起联邦读
- **预期**：返回空/权限标记；不泄露源端他人数据、不暴露源端错误细节

#### TCE-02-06 已拒提案不再提示 【P2/功能】
- **步骤**：① 拒绝某本体对提案 → ② 再次扫描 → ③ 制造证据显著变化后再扫描
- **预期**：不再提示；证据显著变化才重现（见 TC-02-06）

## 四、V2-03 显式指定业务主键

#### TC-03-01 主键下拉选项与回显 【P1/功能】

- **预期**：新入库实例按显式主键匹配/去重

### V2-03 异常流

#### TCE-03-01 已有实例时变更主键 【P1/功能】
- **前置**：对象已有存量实例
- **步骤**：① 变更业务主键 → ② 检查影响提示与存量 stable_key
- **预期**：明确提示影响（存量实例 stable_key 不静默改写；迁移策略需显式确认），不产生键断裂（需求未细化处，以评审确认口径为准）

#### TCE-03-02 并发修改主键 【P2/负向】
