# 源摘要：MVP 阶段 PRD（产品需求文档）

> 原始文件：`raw/PRD-需求文档.md`（不可变）。本文为 LLM 提炼摘要。

## 文档性质
产品需求基线。基于已确认的 v1.1 设计稿，把技术设计翻译为可验收的产品需求：用户场景、功能清单（含 P0/P1/P2 优先级）、非功能需求、范围边界、验收标准。

## 核心内容
- **用户与角色**：[[ITBP]]（建模人）、平台开发者、外部智能体平台（MCP Server 调用方）、外部数据平台（MCP Client 被接方）。多部门协同用户 V2 才支持。
- **6 个用户场景（UC1–UC6）**：建模、归化、外部查询、读外部数据、受控回写、可视化。
- **功能清单优先级**：P0 含 4 种建模、SHACL/快照、归化人工审核、MCP 双向发布与接入、Action 受控回写、凭据本地管理；P1 含模板网络预览、外部接入健壮性；明确不做多租户/审批/审计/RBAC/自动回写。
- **非功能需求**：本地网页服务 + Docker Compose；外部凭据不落库不打印；回写每次确认；兼容 stdio/streamable_http。
- **验收标准**：P0 全绿即 MVP 通过；价值指标为"接入本体前后 Agent 错误率对比"。

## 与设计的对应
PRD 的功能点逐条关联设计章节（如 MCP 双向→[[MCP双向能力]]、Action→[[Action受控回写]]、外部接入→[[外部数据源MCP接入]]）。
