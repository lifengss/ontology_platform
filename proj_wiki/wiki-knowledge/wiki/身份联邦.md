# 身份联邦（V2-14i / M2-B）

> 平台用户 → 各外部系统凭据映射（V2-14 需求 6，按偏差决策 D1 从 V2-14 编排拆出前移 M2-B）。**不仅用于编排回写，也用于实例内容联邦读**（平台以访问者身份代查源系统，V2-02）。

## 核心设计

- **映射粒度**：`(project_id, user_id, connection_id)` → `auth_type` + 非敏感 `principal` + `secret_ref`。同一三元组重建为覆盖写（secret_ref 幂等：`IDFED_<project>_<conn>_<user>`）。
- **凭据存储**：走 `credential_store` 本地加密存储——`CREDENTIAL_ENCRYPTION_ENABLED=1` ＋ `CREDENTIAL_MASTER_KEY`（或 `secrets/.master.key`）时 Fernet 加密落盘、chmod 600；明文 secret 仅一次性经请求传入，**不入平台存储、不回显 API、不进日志/审计**。
- **解析契约**：`resolve_credential()` 返回**引用式** auth override（`bearer_token_ref` / `api_key_ref` / `client_id`+`client_secret_ref` / `username`+`password_ref`），由 `mcp_client` 就地解析为请求头；平台内部不持有明文。
- **缺失映射**：抛 `IDENTITY_MAPPING_MISSING`（403），错误信息指明缺失的外部系统，**不回落匿名/默认账号**（TCE-14-04）。
- **审计**：`identity_mapping_create` / `identity_mapping_delete` / `identity_resolve`，detail 中 principal 脱敏；grep 日志/审计/数据目录无凭据明文（TC-14-11）。

## 支持的凭据类型

`bearer_token` ｜ `api_key` ｜ `oauth2_client_credentials`（principal=client_id）｜ `basic`（principal=用户名）

## API（详见 docs/API-INTERFACE-DOC.md §23）

| 方法 / 路径 | 说明 |
|---|---|
| `POST /api/identity/mappings` | 创建映射（body 含一次性 `secret`） |
| `GET /api/identity/mappings` | 列表（默认当前用户；admin 可查任意） |
| `GET /api/identity/mappings/{id}` | 详情（无 secret_ref） |
| `GET /api/identity/mappings/{id}/resolve-status` | 完整性（`has_secret`，无凭据值） |
| `DELETE /api/identity/mappings/{id}` | 删除映射并吊销 secret |
| `GET /api/identity/auth-types` | 凭据类型清单 |

RBAC：本人可管理自己的映射；`role=admin` 可管理任意用户（越权 403）。

## 集成点

- `McpClient.invoke_tool(config, tool, params, auth_override=...)`：传入映射身份调用（覆盖连接自带 auth）。
- `identity_federation.delegated_auth_header(connection, user_id=..., project_id=...)`：编排回写（M3-F/V2-14）的接入点，缺失映射即拒绝。
- `identity_federation.federated_read(project_id, *, user_id, connection, tool, params)`：**源连接型内容联邦读统一调用点**（TP-06-06 / M4 V2-02 / M2-C 内容共享复用）——以访问者身份代查并返回 `source_connection / resolved_as / result` 来源标记；平台侧租户/schema 过滤由 M2-C/M4 在其上叠加。
