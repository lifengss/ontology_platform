# 软件形态与部署

## 形态（已明确）
MVP 为**本地网页服务（Local Web Service）**，**非桌面应用（Electron 类）、非云 SaaS**：
- Python 后端（建议 FastAPI）+ 浏览器前端（localhost 访问）；
- Jena / Neo4j / Postgres(pgvector) 同机部署。

## 为何是 Web 服务而非桌面应用
1. 后端天然是多服务进程（Jena/Neo4j/Postgres），server 形态比 Electron 打包更自然；
2. 要对外发布 [[MCP双向能力|MCP Server]] 供外部智能体平台**网络调用**，web 服务可达性最好；
3. ITBP 用浏览器即用，免装重客户端。

## 部署方式（建议）
- MVP 用 **Docker Compose** 一键拉起全部组件（单机即可），V2 再迁移 K8s。
- 本机前置依赖：装一次 Docker。

## 远端 vs 本地
- 本地：后端 + Jena/Neo4j/Postgres + 前端。
- 远端：外部 MCP 数据平台（不在本机，平台通过网络调用，见 [[外部数据源MCP接入]]）。
