# 技术实现方案（MVP）

> 本文把 [[范围与版本规划]] 与 [[技术选型]] 的设计基线落地为**可编码的模块划分、接口约定、数据流、目录结构与测试策略**。开发排期与切片顺序见 [[开发进度规划]]。
> 形态基线：本地网页服务 + Docker Compose（见 [[软件形态与部署]]）。外部凭据/回写决策见 [[外部数据源MCP接入]]、[[Action受控回写]]。

## 1. 总体技术架构（落地视图）

### 1.1 部署拓扑（单机 Docker Compose）
```
┌──────────────────────── 本机（Docker Compose） ────────────────────────┐
│  Browser (localhost:UI)                                                  │
│        │ HTTP/JSON                                                        │
│        ▼                                                                 │
│  backend (FastAPI, Python)  ←编排中枢→  ┌─────────────────────────┐      │
│     ├─ modeling_translator   　　　　　 │  Apache Jena/Fuseki      │      │
│     ├─ jena_adapter (HTTP)   ─────────► │  OWL/SHACL/推理/SPARQL  │      │
│     ├─ neo4j_sync            ─────────► │  (独立 HTTP 服务)        │      │
│     ├─ ingestion            　　　　　 │  Neo4j Community        │      │
│     ├─ reasoning             　　　　　 │  ABox 实例 + 图谱        │      │
│     ├─ mcp_server(FastMCP)  　　　　　 │  PostgreSQL + pgvector  │      │
│     ├─ mcp_client            　　　　　 │  向量索引               │      │
│     ├─ action_engine         　　　　　 └─────────────────────────┘      │
│     └─ credential_store                                                 │
└────────────────────────────────────────────────────────────────────────┘
        │ MCP (stdio / streamable_http)
        ▼
  外部数据平台 MCP Server（远端，不在本机，对接方已提供）
```
要点：Jena 以**独立 HTTP 服务（Fuseki）** 部署，Python 后端只做 HTTP 调用，避免 Java/Python 深度混编（见 [[混合存储]]）。

### 1.2 后端模块划分（对应 §3.2 七层裁剪）
| 模块（包名） | 职责 | 关键依赖 | 对应能力 |
|---|---|---|---|
| `modeling_translator` | 业务层↔OWL2-RL/SHACL 双向翻译；逆向建模（DB schema→候选 OWL）；模型导出/导入 | Jena | [[双层建模架构]]、[[本体建模]] |
| `jena_adapter` | 封装 Fuseki：上传/读取 OWL、SPARQL 查询、SHACL `validate`、OWL 推理（rule reasoner） | Jena HTTP | [[推理与SHACL校验]]、[[混合存储]] |
| `neo4j_sync` | ABox 实例写入/读取；TBox 仍存 Jena；图谱遍历查询 | Neo4j | [[混合存储]] |
| `ingestion` | 归化流水线编排：LLM 候选 / 字段映射 → 人工审核卡 → SHACL 校验 → 落 Neo4j + 溯源标记 | LLM、Jena、Neo4j | [[实例归化流水线]] |
| `reasoning` | 调用 Jena 推理；提取 `inference_trace` 推导链路 | Jena | [[推理与SHACL校验]] |
| `mcp_server` | FastMCP 由本体 Schema **自动生成**工具：`ontology_query` / `inference_trace` / `instance_get` | MCP SDK、FastMCP | [[MCP双向能力]] |
| `mcp_client` | 多连接配置管理；transport（stdio/http）；鉴权；工具调用；健壮性（超时/重试/401 阻断/漂移停库） | MCP SDK、credential_store | [[外部数据源MCP接入]] |
| `action_engine` | Action 定义解析；`human_required` 确认流；幂等键；dry-run；执行日志；失败熔断 | mcp_client、credential_store | [[Action受控回写]] |
| `credential_store` | 外部凭据以 env/本地配置文件管理；不入库、不打印；`chmod 600`；`.gitignore` | 本地 FS、env | [[外部数据源MCP接入]] |
| `viz` | 本体/图谱（外部溯源着色）/推理链路三视图数据接口 | Neo4j、reasoning | 可视化 |
| `template` | 预置模板（LinkML）；网络加载预览外部模板 | LinkML | 模板管理 |
| `api` | FastAPI 路由聚合、配置加载、健康检查、日志 | 全部 | — |

## 2. 模块实现要点

### 2.1 双层建模翻译器（modeling_translator）
- 业务层对象/属性/关系/约束在 DB 中以**业务语义表**存储（不暴露 Class/Property 原语，见 [[双层建模架构]]）。
- **建模前轻量校验门（借鉴补丁 P-01）**：`validate_business_layer` 在翻译为 OWL **之前**对业务层做本地纯逻辑校验（id 唯一、父级继承无环、data_type/基数合法、枚举定义合法、属性/关系名禁用敏感词 password/secret/token 等，配合 §2.8 P-03），不通过返回 422，省一次 Jena/SHACL 调用。该门管模型级完整性，与 SHACL（实例级语义约束）互补。
- 保存时翻译为 OWL2-RL（类层次→`owl:Class` + `rdfs:subClassOf`；对象属性→`owl:ObjectProperty`；数据属性→`owl:DatatypeProperty`；约束→ `sh:PropertyShape`；枚举→ `sh:in`）。
- 逆向建模：读源库 `information_schema` → 生成候选表/字段 → 映射为候选对象/属性 → 允许人工二次修正后翻译落库。
- 四种建模（手工/逆向/Schema/混合）共用同一翻译入口，差异仅在"候选来源"。

### 2.2 Jena 适配层（jena_adapter）
- Fuseki 暴露 SPARQL 端点；通过 `dataset` 上传 `.ttl`/`.owl`。
- SHACL 校验：用 Jena 的 `shacl` 命令行/`arq` 校验本体数据图，返回 violations JSON。
- 推理：启用 OWL2-RL rule reasoner，对 TBox 推理派生隐含公理；为 `inference_trace` 提供"前提→结论"步骤。

### 2.3 ABox 同步（neo4j_sync）
- TBox 在 Jena，ABox（实例）在 Neo4j（见 [[混合存储]]，Neo4j 社区版不做 OWL-DL 推理）。
- 归化审核通过后，将实例以节点+关系写入 Neo4j，并打 `source` 属性（内部 / 外部 MCP）供图谱溯源着色。
- 查询类请求优先走 Neo4j（图遍历/可视化），语义约束类走 Jena。

### 2.4 归化流水线（ingestion）
- 源：业务文档 / 数据表 / **外部 MCP 读取结果**。
- 路径 A（LLM）：`源 → LLM 候选实例(JSON) → 人工审核 UI → 通过 → SHACL 校验 → Neo4j`。**LLM 输出禁止直落库**；支持自定义 LLM endpoint。
- 路径 B（字段映射）：外部结构化数据按 `field_map` 映射 → SHACL 强校验 → 首次/变更需人工确认卡，低风险可自动入库。
- 溯源：实例带 `source=外部MCP` + `connection_id` + 读取时间戳。

### 2.5 MCP Server（mcp_server）
- 用 `FastMCP` 注册工具，工具 schema 由当前本体 Schema **自动生成**。
- 工具：`ontology_query`（语义查询，转 Jena SPARQL）、`inference_trace`（转 reasoning 模块）、`instance_get`（读 Neo4j，受本体约束）。
- **工具契约声明（借鉴补丁 P-02）**：每个工具附带 `reads/writes/preconditions/postconditions/side_effect` 元数据（`mcp_server.TOOLS_CONTRACT`、`docs/mcp_tools_contract.yaml`），供外部 Agent 静态判断读写与副作用，降低误调风险，亦为 RBAC 打底。
- 通过 FastAPI 挂载 `/mcp` 端点（streamable_http），供外部智能体平台注册（见 [[MCP双向能力]]，UC3）。

### 2.6 MCP Client 连接管理（mcp_client）
- 每条连接 = 一条配置（见 [[外部数据源MCP接入]] §4.7.1）：transport、endpoint、auth、tool_allowlist、field_map、read_schedule。
- 鉴权：持有外部凭据（bearer/api_key 或 oauth2_client_credentials 换 token 缓存）；**平台自身不鉴权**（见决策）。
- 健壮性：健康检查 + 超时(10s) + 指数退避重试(≤3)；401/403 阻断告警不降级；schema 漂移即停自动入库转人工。

### 2.7 Action 受控执行引擎（action_engine）
- Action 定义见 [[Action受控回写]] §5.3：`target_connection`、`invoke(mcp_tool/webhook/rest)`、`input_map`、幂等键 `idempotency_key`、`confirmation=human_required`、`dry_run_supported`。
- 执行流：触发 → 渲染 input_map → **弹人工确认** → 确认后调外部写工具/webhook（带鉴权）→ 结果回填实例/写执行日志。
- 护栏：每次确认；幂等键防重；dry-run 优先；失败指数退避+熔断；外部不可回滚→优先幂等 upsert。

### 2.8 凭据管理（credential_store）
- 外部凭据**不落库**：存于本地配置文件或环境变量，`chmod 600`，加入 `.gitignore`。
- **凭据只存 `secret_ref` 间接引用（借鉴补丁 P-03）**：连接配置中仅出现 `${ENV_NAME}` 形式引用，绝不明文落盘；违禁字段名（password/secret/token/api_key/raw_key）在建模层被 P-01 校验门硬性拒绝，从机制上杜绝误填明文。
- 日志中严禁打印凭据明文；加密落盘（cryptography.Fernet）作为**生产建议项**，Demo 可不启用。

### 2.9 操作审计日志（V2 储备，借鉴补丁 P-04）
- MVP 用 Jena 快照 + SHACL 即可回退到某版本，"操作级回放/审计/血缘"属 V2（见 [[范围与版本规划]]）。
- V2 可统一记录本体变更、[[Action受控回写]] 执行、外部读取落库为 **append-only JSONL 操作日志**，作为审计/血缘/误操作回滚的统一底座；该日志是旁路补充，**不替代** Jena(THox)+Neo4j(ABox)+PG 主存储。
- P-05（schema fragment append/merge）**不采纳**：模板/扩展已由 LinkML 覆盖且更强。

## 3. 关键接口约定（草案，待实现确认）

> 以下为 REST 草案；MCP 工具（`ontology_query` 等）走 `/mcp` 协议端点，不在此列。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/ontologies` | 创建/保存业务层本体（翻译落 Jena） |
| GET | `/api/ontologies/{id}` | 读取业务层模型 |
| POST | `/api/ontologies/{id}/validate` | SHACL 一致性校验，返回 violations |
| POST | `/api/ontologies/{id}/snapshot` | 版本快照 |
| GET | `/api/ontologies/{id}/snapshots` | 历史快照列表 |
| POST | `/api/ingest/preview` | 归化候选（LLM/字段映射），不入库 |
| POST | `/api/ingest/{candidate_id}/approve` | 人工审核通过 → SHACL → 落 Neo4j |
| GET | `/api/graph/{id}` | 图谱数据（含 source 溯源着色字段） |
| GET | `/api/inference/trace/{id}` | 推理链路 steps |
| POST | `/api/mcp/connections` | 新建外部连接配置 |
| POST | `/api/mcp/connections/{id}/test` | 连通性测试（含鉴权） |
| POST | `/api/mcp/connections/{id}/read` | 触发读取 → 候选实例 |
| POST | `/api/actions` | 定义 Action |
| POST | `/api/actions/{id}/execute` | 执行（返回需确认令牌，确认后回写） |
| POST | `/api/actions/{id}/confirm` | 人工确认后真正回写 |
| GET | `/health` | 健康检查（后端 + 依赖服务可达） |

**连接配置 JSON（与 §4.7.1 对齐）：**
```json
{
  "connection_id": "crm-sf-mcp",
  "display_name": "销售易 CRM（MCP）",
  "transport": "streamable_http",
  "endpoint": "https://mcp.crm-vendor.com/mcp",
  "auth": { "type": "oauth2_client_credentials", "token_url": "…",
            "client_id": "${CRM_CLIENT_ID}", "client_secret": "${CRM_CLIENT_SECRET}",
            "scopes": ["mcp.read","mcp.write"] },
  "tool_allowlist": ["query_account","upsert_contact"],
  "maps_to_ontology": { "object_type": "Customer",
                        "field_map": { "account_name": "name", "industry": "industry" } },
  "read_schedule": "manual"
}
```
**Action 定义 JSON（与 §5.3 对齐）：**
```json
{
  "action_id": "sync_customer_to_crm",
  "target_connection": "crm-sf-mcp",
  "invoke": { "kind": "mcp_tool", "tool": "upsert_contact" },
  "input_map": { "name": "$.Customer.name", "email": "$.Customer.email" },
  "idempotency_key": "customer::{Customer.id}",
  "confirmation": "human_required",
  "dry_run_supported": true
}
```

## 5. 测试策略（应对单人 + AI 编码风险）
- **单测**：翻译器（业务层↔OWL 往返一致）、SHACL 校验、字段映射、幂等键生成。
- **集成**：Jena 推理链路、Neo4j 落库、图谱溯源着色。
- **外部 MCP mock**：本地起一个 mock MCP Server（stdio + http 两种），覆盖读取/写工具/401/超时/schema 漂移，保证 Client 与 Action 不依赖真实外部源即可测（见 [[外部数据源MCP接入]]、[[MCP双向能力]]）。
- **Action dry-run**：回写前 dry-run 返回将发送的内容，确认流与真实回写分离。
- **回归集**：随本体演进维护 SHACL/推理回归用例。

## 6. 关键风险与缓解（引用基线）
完整风险见 [[范围与版本规划]] 与两份源摘要。实现阶段最需盯的 3 条：
1. **AI 生成代码质量**：靠模块边界 + 复用 Jena/MCP SDK + 上述测试集兜底。
2. **Action 误/重复回写**：每次确认 + 幂等键 + dry-run + 熔断（见 [[Action受控回写]]）。
3. **外部 MCP 不稳定/漂移**：超时重试 + 漂移停库 + 401 阻断告警（见 [[外部数据源MCP接入]]）。
