# 范围与版本规划

## MVP（本地单人模式）包含
建模（4 种）、推理+校验+快照、归化（人工审核）、可视化三视图、模板、[[MCP双向能力]]（Server 发布 + Client 接入外部含鉴权源）、[[Action受控回写]]（每次确认）、[[混合存储]]、凭据本地管理。详见 [[软件形态与部署]]。

## MVP 明确不包含（后置 V2）
多租户 / 部门隔离 / 审批流 / 细粒度血缘 / 完整审计 / RBAC / 无条件自动回写 / 复杂 Action 编排 / 流式 CDC / **平台自身登录鉴权**。

## 版本路线
| 阶段 | 关键交付 |
|---|---|
| MVP | 本地单人闭环：建模→查询→读外部→受控回写（优先验证价值假设） |
| V2.0 | K8s、多租户、治理（审批/血缘/审计/权限）、Action 增强（编排/自动回写/身份联邦）、SPARQL/REST/GraphQL |
| V3.0 | BI 消费、资产市场/模板库、更多适配器 |

## 设计原则
仍优先验证"本体约束降低 Agent 幻觉"核心价值；治理能力分层，MVP 只保留快照/一致性校验，重治理后置 V2。

## 借鉴补丁吸收记录（ontology-skill）
对 `oswalpalash/ontology` skill 研判后的可复用点（来源：`借鉴补丁建议-ontology-skill.md`）：
- **P-01 建模前轻量校验门**、**P-02 MCP 工具契约**、**P-03 凭据 secret_ref**：已吸收进 MVP 代码与文档（见各对应 wiki 页与《技术实现方案》）。
- **P-04 JSONL append-only 操作日志（审计/血缘/回放）**：**V2 储备**。MVP 已有快照 + SHACL 可回退，不写代码；V2 可把本体变更 / Action 执行（[[Action受控回写]]）/ 外部读取落库统一记为旁路操作日志（非主存储，主存储仍是 Jena+Neo4j+PG）。
- **P-05 schema fragment append/merge**：**不采纳**。模板/扩展已由 LinkML 覆盖且更强，避免"两套 schema 来源"分裂。
