# 开发进度规划（MVP，按垂直切片）

> 配套 [[技术实现方案]]。本文把 MVP 拆成**垂直可端到端测试的功能切片（Vertical Slice）**：每个切片都从 UI→后端→存储（或外部）打通，独立可验收；优先 P0，P1 在 P0 全绿后补。
> 周期未定（与 PRD §10 一致），下表人日为**单人 + AI 辅助的估算量级**，非承诺排期。

## 1. 切片原则
- **垂直**：每切片交付一条完整用户价值链路，可独立 e2e 测试，不等全部模块齐了才测。
- **可测**：每切片明确"端到端怎么验"，并配套测试（含外部 MCP mock / Action dry-run）。
- **优先级驱动**：P0 切片全绿即 MVP 通过（对应 PRD §9.1）。

## 2. 切片总览
| 切片 | 对应 UC / 优先级 | 端到端验收（一句话） | 主要依赖 |
|---|---|---|---|
| VS0 运行基座 | 地基 / P0 | `docker compose up` 后 localhost 可访问、依赖服务可达、`/health` 200 | — |
| VS1 建模全闭环 | UC1 / P0 | UI 建对象/属性/关系 → 落 Jena OWL → 重开可见、可导出 | VS0 |
| VS2 推理与校验 | P0 | 模型可 SHACL 校验报错、可推理、链路可展示、可快照回溯 | VS1 |
| VS3 归化流水线 | UC2 / P0 | 文档/表→候选→人工审核→落 Neo4j；LLM 无直落库；可切模型 | VS1 |
| VS4 可视化三视图 | UC6 / P0 | 本体/图谱（外部溯源着色）/推理链路三视图可用 | VS2,VS3 |
| VS5 模板管理 | P1 | 预置模板可新建；外部模板可网络预览 | VS1 |
| VS6 MCP Server 发布 | UC3 / P0 | 本体自动生成工具；mock Agent 可注册调用 `ontology_query`/`inference_trace` | VS2 |
| VS9 凭据管理 | P0 | 外部凭据不落库/不打印；配置文件 `chmod 600` 入 `.gitignore` | VS0 |
| VS7 外部 MCP 接入 | UC4 / P0 | 配置连接→连通(stdio/http)→读取→映射→SHACL→人工确认→落库+溯源 | VS3,VS9 |
| VS8 Action 受控回写 | UC5 / P0 | 定义 Action→执行弹确认→幂等→日志；重复不重复回写 | VS9,VS7 |

> VS9（凭据）提前到 VS7/VS8 之前，因其为外部读取与回写的硬前置；VS5（P1）可在任意 P0 间隙插入。

## 3. 推荐实施顺序
```
VS0 → VS1 → VS2 → VS3 → VS4 → VS6 → VS9 → VS7 → VS8 → (VS5 并行/后置) → VS10
```

## 4. 各切片详细

### VS0 运行基座（P0，地基）
- **范围**：`docker-compose.yml`（Jena/Fuseki、Neo4j、Postgres+pgvector、backend、frontend）；FastAPI 骨架；配置加载；`/health`；结构化日志；`.gitignore` 脚手架。
- **端到端验**：`docker compose up -d` → 浏览器开 localhost → `/health` 返回 200；三依赖服务端口可达。
- **测试**：compose 启动脚本 + 健康检查集成测试。
- **估时**：3–5 人日。

### VS1 本体建模全闭环（UC1，P0）
- **范围**：四种建模（手工/逆向/Schema/混合）；业务层 UI 屏蔽 OWL 术语；`modeling_translator` 翻译落 Jena；模型保存/读取/导出（见 [[本体建模]]、[[双层建模架构]]）。
- **端到端验**：ITBP 在 UI 创建"客户"对象+属性+关系 → 保存 → 重开可见 → 导出 OWL 含预期公理。
- **测试**：翻译器往返单测；保存/读取集成。
- **估时**：8–12 人日（逆向建模含源库 schema 读取，较重）。

### VS2 推理与 SHACL 校验（P0）
- **范围**：`jena_adapter` 封装推理与 SHACL；`reasoning` 提取 `inference_trace`；版本快照；UI 展示推导过程与违规项（见 [[推理与SHACL校验]]）。
- **端到端验**：构造含矛盾/约束的模型 → 校验报错项明确；推理派生关系可在 UI 链路展示；可回溯历史快照。
- **测试**：SHACL violations 单测；推理链路集成。
- **估时**：5–8 人日。

### VS3 文档/表归化流水线（UC2，P0）
- **范围**：`ingestion` 编排；LLM 候选与字段映射两路径；人工审核卡 UI；SHACL 校验；落 Neo4j；自定义 LLM endpoint（见 [[实例归化流水线]]）。
- **端到端验**：上传文档/表 → 生成候选 → 审核 UI 通过 → 实例出现在 Neo4j；LLM 路径**未经审核不得落库**；切换模型生效。
- **测试**：审核卡点单测（未审核拒绝落库）；字段映射单测。
- **估时**：6–9 人日。

### VS4 可视化三视图（UC6，P0）
- **范围**：`viz` 提供本体视图、知识图谱视图（外部来源溯源着色）、推理链路视图数据（见设计 §4.4/§4.8）。
- **端到端验**：建模+归化后有数据 → 三视图渲染正确；外部 MCP 来源节点着色区分。
- **测试**：图谱数据接口单测（含 source 字段）。
- **估时**：4–6 人日。

### VS5 模板管理（P1）
- **范围**：`template` 预置行业模板（LinkML）+ 网络动态加载预览外部模板（见设计 §4.5）。
- **端到端验**：从模板新建本体；网络模板可预览不报错。
- **测试**：模板加载解析单测。
- **估时**：3–5 人日（可后置）。

### VS6 MCP Server 发布（UC3，P0）
- **范围**：`mcp_server` 用 FastMCP 由本体自动生成 `ontology_query`/`inference_trace`/`instance_get`；UI 一键发布；挂载 `/mcp`（见 [[MCP双向能力]]）。
- **端到端验**：发布后，本地 mock 智能体平台注册并成功调用 `ontology_query` 拿到语义结果、`inference_trace` 拿到链路。
- **测试**：用 MCP SDK 客户端连本地 `/mcp` 做工具调用集成测试。
- **估时**：4–6 人日。

### VS9 凭据管理（P0，前置）
- **范围**：`credential_store` 外部凭据本地配置文件/env 管理；不入库、不打印；`chmod 600`；`.gitignore`（见 [[外部数据源MCP接入]] §4.7.2）。
- **端到端验**：配置含 `${CRM_CLIENT_ID}` 的凭据文件 → 启动读取成功且日志无明文；git 状态不包含该文件。
- **测试**：凭据加载/脱敏日志单测；gitignore 校验。
- **估时**：1–2 人日（轻，但为 VS7/VS8 硬前置）。

### VS7 外部 MCP 数据源接入（UC4，P0）
- **范围**：`mcp_client` 连接配置 UI（endpoint/auth/工具白名单/字段映射）；兼容 stdio/streamable_http；读取→映射→SHACL→人工确认卡→落 Neo4j+溯源；健壮性（超时/重试/401 阻断/ schema 漂移停库）（见 [[外部数据源MCP接入]]）。
- **端到端验**：连本地 mock MCP Server（两种 transport）→ 读取记录 → 映射候选 → 人工确认 → 实例带 `source=外部MCP` 落库；模拟 401/超时/漂移均被正确处理不静默。
- **测试**：mock MCP Server（stdio+http）+ 上述异常用例集成测试。
- **估时**：7–10 人日。

### VS8 Action 受控回写（UC5，P0）
- **范围**：`action_engine` 定义解析；`human_required` 每次确认；幂等键；dry-run；执行日志；失败熔断（见 [[Action受控回写]]）。
- **端到端验**：定义 `sync_customer_to_crm` → 触发返回确认令牌 → 确认后调外部 `upsert_contact` 回写 → 日志有记录；相同幂等键重复触发不产生重复回写；dry-run 不真正外发。
- **测试**：确认流分离单测；幂等键单测；dry-run 集成（连 mock MCP 写工具）。
- **估时**：5–7 人日。

### VS10 集成验收与测试集（收尾）
- **范围**：P0 切片串联跑通；固化测试集（mock MCP + Action dry-run + SHACL 回归）；编写运行/部署 README；对照 PRD §9.1 验收清单逐项勾选。
- **端到端验**：从零起一个部门本体 → 发布 MCP → 读外部 → 审核入库 → 定义并回写 Action，全链路无阻塞。
- **估时**：3–5 人日。

## 5. MVP 通过门槛
P0 切片（VS0、VS1、VS2、VS3、VS4、VS6、VS9、VS7、VS8）全绿，且 PRD §9.1 四条验收全部满足：
- [ ] ITBP 用 4 种方式建模并发布 MCP Server，外部 Agent 成功查询；
- [ ] 归化 LLM 输出必经人工审核，无直落库；
- [ ] 可连通一个外部 MCP Server（stdio 或 http），读取归化入本体；
- [ ] 可定义并触发一个 Action 回写，每次弹确认、重复不重复回写、有日志。
