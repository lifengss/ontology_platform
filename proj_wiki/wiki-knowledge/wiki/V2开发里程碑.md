## 开发范式（与 MVP [[开发进度规划]] 一致）

1. **按需求垂直验证**：每个切片 = 一项功能需求，完整「UI → API → 存储/外部系统」链路，独立 E2E 可测；退出 = 该需求 P0 测试点全绿 + E2E 检查点。
2. **不分层**：无"先全部后端再统一 UI"阶段；每切片自带前端/后端/mock 集成/测试脚本。
3. **测试点驱动**：TP/EP（大纲）↔ TC/TCE（用例）↔ 脚本三级映射；脚本开发后在 [[source-V2-测试用例]] 页登记链接。
4. **依赖显式化**：跨需求依赖只允许调序或拆前置切片（D1/D2）。
5. **回归保护**：每里程碑退出跑 L5 全量回归 + E2E 检查点；INV-1~6 随切片逐步验证、终验全矩阵。

## 主要风险
- **M4-A 数据模型改造+存量迁移**波及 M1–M3 已验收行为（最高风险）：拆步实施（数据模型先行＋INV-1 验证后再做融合）、迁移前备份＋回退底、迁移后 L5 全回归。
- 语义 diff 组件质量不足拖累 M4-A：M2-E 验收含 diff 语义断言，预留缓冲。
- golden dataset 冻结延迟：M3-F 开发期内并行推进，引擎/编辑器可先按 mock 场景验收。
- TCE2E-08/09 外部平台环境不可得：可用本地 Agent 客户端替代验证 MCP 链路并登记说明。
- 工作量超估：每里程碑退出复估；P2 项（V2-19/V2-10/反向暴露/物化快照）可降 V2.1。
