# 数据模型速查（本体业务层）

> 本页是**建模操作的权威字段参考**，供交互式教程每一步引用。
> 平台把业务层模型自动翻译为 OWL2-RL / SHACL（见 [[双层建模架构]]），业务人员无需接触 OWL 术语。
> 字段名以下划线命名（snake_case），ID 一律用字符串。与 `docs/API-INTERFACE-DOC.md` §2 逐字段对齐。

## 1. 总结构（本体 = 对象 + 约束）

一个**本体（Ontology）**由若干**对象类型（Object）**与**约束（Constraint）**组成；每个对象类型拥有若干**属性（Attribute）**与**关系（Relation）**。

```
Ontology
 ├─ name / description / modeling_type / version / status
 ├─ objects[]  ── OntologyObject
 │    ├─ name / business_definition / stable_key
 │    ├─ attributes[]  ── ObjectAttribute
 │    └─ relations[]   ── ObjectRelation
 └─ constraints[]  ── OntologyConstraint
```

## 2. 本体 Ontology（顶层）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | ✅ | 本体名称（如"客户本体"） |
| `description` | string | — | 业务域说明 |
| `modeling_type` | enum | — | 见 §6，默认 `manual` |
| `version` | string | — | 默认 `"1"` |
| `objects` | Object[] | — | 对象类型列表 |
| `constraints` | Constraint[] | — | 本体级约束（如"客户名称唯一"） |
| `functions` | Function[] | — | 元模型预留（无副作用计算，V2 执行）；MVP 仅存储 |
| `status` | enum | — | `draft`（草稿）→ `active`（已发布）；见 §7 |

## 3. 对象类型 OntologyObject

> 对象类型 = 业务域里的"一类事物"（如 采购订单、计划节点、客户）。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 对象标识（如 `obj_customer`），创建后用于关系指向 |
| `name` | string | ✅ | 业务名称（中文，如"客户"） |
| `description` | string | — | 补充说明 |
| `business_definition` | string | ✅ | **一句话业务定义（≥5 字符）**：说明该对象代表什么、边界在哪 |
| `stable_key` | string | ✅ | **业务主键**：指向本对象某个属性 `id`（如 `"attr_order_no"`），禁止用内部自增 id |
| `namespace` | string | — | 部门/域命名空间，默认继承所属项目 |
| `parent` | string | — | 父对象（继承用，MVP 可选） |
| `attributes` | Attribute[] | — | 属性列表 |
| `relations` | Relation[] | — | 关系列表 |

## 4. 属性 ObjectAttribute

> 属性 = 对象"自身携带的信息"（如 客户的"名称""行业""成立日期"）。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 属性标识（如 `attr_name`） |
| `name` | string | ✅ | 业务名称（如"名称"） |
| `data_type` | enum | — | 见 §5，默认 `string` |
| `required` | bool | — | 是否必填，默认 `false` |
| `constraints` | object | — | 取值约束，见下 |

**`constraints` 子字段**（全部可选）：`min_length` / `max_length` / `pattern`（正则）/ `minimum` / `maximum` / `enum`（枚举白名单，生成 SHACL `sh:in`）。

> 例：`{ "id":"attr_name","name":"名称","data_type":"string","required":true,"constraints":{"min_length":1,"max_length":128} }`

## 5. 数据类型枚举（data_type）

| 值 | 含义 | 示例 |
|---|---|---|
| `string` | 文本 | "腾讯" |
| `integer` | 整数 | 3 |
| `float` | 浮点 | 0.85 |
| `boolean` | 布尔 | true / false |
| `date` | 日期 | 2026-10-23 |
| `datetime` | 日期时间 | 2026-10-23T10:00:00+08:00 |

## 6. 关系 ObjectRelation

> 关系 = 对象"指向另一个对象"（如 计划节点 **属于** 采购订单）。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 关系标识（如 `rel_belongs`） |
| `name` | string | ✅ | 关系名（如"属于"） |
| `target_object` | string | ✅ | 目标对象 `id`（如 `obj_order`）；前端录入有**自动联想** |
| `cardinality` | enum | — | 见 §6.1，默认 `many_to_one` |
| `inverse_name` | string | — | 逆向关系名（如"拥有节点"），用于推理补全 |

### 6.1 关系基数枚举（cardinality）

| 值 | 中文 | 含义 |
|---|---|---|
| `one_to_one` | 1:1 | 一个源对应唯一一个目标 |
| `one_to_many` | 1:N | 一个源对应多个目标 |
| `many_to_one` | N:1 | 多个源指向同一个目标（如 多个计划节点属于同一订单） |
| `many_to_many` | M:N | 多对多 |

> 录入数据时，关系字段直接填**目标实例的业务主键值**（即目标对象 `stable_key` 对应的那个值），无需填系统内部 id。

## 7. 约束 OntologyConstraint（可选）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 约束标识 |
| `name` | string | ✅ | 约束名（如"客户名称唯一"） |
| `scope` | string | — | 作用对象 `id` |
| `rule` | string | ✅ | 规则类型，如 `unique` |
| `params` | object | — | 规则参数，如 `{ "attribute": "attr_name" }` |

## 8. modeling_type 枚举

| 值 | 含义 |
|---|---|
| `manual` | 手工建模（默认） |
| `reverse` | 逆向（从文档/表结构抽取） |
| `schema` | Schema 约束驱动 |
| `hybrid` | 混合 |

> 实际用户入口见 [[本体建模]]：手动表单、AI 自然语言（from-text）、文档逆向（from-doc）、Excel 导入（from-excel）、模板。

## 9. 创建前校验门（轻量业务层校验）

`POST /api/ontologies` 在翻译为 OWL **之前**先跑以下门禁，不通过返回 `VALIDATION_ERROR`（HTTP 422，含 `violations`）：

- 对象/属性/关系 `id` 唯一，无重复；
- 父级 `parent` 无环；
- `data_type` / `cardinality` / `modeling_type` 取值合法；
- 枚举定义合法；
- 属性/关系名**禁用敏感词**（`password` / `secret` / `token` 等）；
- `business_definition` 必填且 ≥5 字符；
- `stable_key` 必填且指向本对象已存在的属性 `id`。

## 10. 状态生命周期

```
draft ──(发布 POST /api/ontologies/{id}/publish)──▶ active
```

- 所有建模/逆向生成结果**默认先为 `draft`**，可编辑后发布；
- 发布（`active`）后翻译器才写入 Jena，方可被 MCP/图谱消费；
- 校验：`POST /api/ontologies/{id}/validate`（业务层门 + pyshacl 真实 SHACL）；
- 导出：`POST /api/ontologies/{id}/export`（默认 turtle）；
- 快照：`POST /api/ontologies/{id}/snapshot`（版本留痕）。
