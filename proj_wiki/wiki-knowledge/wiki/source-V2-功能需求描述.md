# source-V2-功能需求描述（V2 需求基线摘要）

> 源文档：`raw/V2-功能需求描述.md`（2026-11-06 审核通过入 wiki，基线版本）。完整 21 项需求以源文档为准，本页为摘要索引。

## 基线定位
V2 从"本地单人闭环"升级为"多部门多用户平台 + Agent 语义底座增强"：在 MVP（建模→查询→读外部→受控回写）之上叠加治理（权限/审批/血缘/审计）、数据新鲜度（CDC/漂移）、写回自动化（风险分级/编排）、开放接口（SPARQL/REST/GraphQL/stdio）与 K8s 部署。

## 六条架构不变式（INV-1~6，V2 全程守护）
1. **INV-1 值分渠道**：源连接型实例只存关系快照（键/关系/血缘），内容值永不落地平台侧；上传型值落本地。
2. **INV-2 租户隔离**：跨租户不可见不可访问；共享只授 schema 只读，实例永不共享。
3. **INV-3 无代码红线**：编排无脚本/任意表达式入口；无法表达的能力标"能力缺口"；运行时 LLM 不参与分支/工具选择/参数填充。
4. **INV-4 审计不可篡改**：无修改/删除 API。
5. **INV-5 查询接口数据边界**：开放接口不返回源连接型非键内容（走 MCP 联邦读或直连源）。
6. **INV-6 溯源链完整**：任何结果可回溯到来源系统/实例/能力版本/原值。

## 关键决策与依赖
- **三渠道消费模型**：浏览器 UI / 平台 API / MCP（外部 Agent），权限矩阵三渠道一致。
- 依赖链：V2-01 前置 V2-04 取值与 V2-08 血缘；V2-05/06 前置上线；V2-07 复用 V2-02 语义 diff（实现上 diff 组件先建于 V2-07）；实例内容联邦读依赖 V2-14 身份联邦＋V2-01 机制；V2-21 核心四维零依赖可先行。
- 实现顺序建议（四批）：价值闭环（04/01/03）→ 上线前置（05/06/09/07）→ 能力扩展（11/08/21/12/13/14）→ 底座生态（15/16/17/18/02/10/19/20）。
