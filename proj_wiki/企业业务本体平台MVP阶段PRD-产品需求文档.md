## 2. 产品概述

### 2.1 背景与痛点
- 智能体平台中大模型**幻觉严重**、数据使用逻辑链路不可信。
- 公司 40+ 部门数据分散在 ERP/CRM/PLM 等多套系统，字段不统一、同义异写、填写不一致，**数据质量参差不齐**。
- 目标是用**业务本体**作为大模型 Agent 的**语义底座**，约束其数据使用逻辑、降低幻觉。

### 2.2 产品定位
- 现阶段优先作为**大模型 Agent 语义底座**；远期扩展数据治理、BI。
- **不做业务系统开发**，只做"让 Agent 用对数据、说对话"的语义约束层。
- MVP 形态：**本地网页服务**（Python 后端 + 浏览器前端，Jena/Neo4j/Postgres 同机，Docker Compose 一键起）。

### 2.3 核心价值假设（待 MVP 验证）
- 假设：用本体约束后，Agent 在"该用哪个对象/属性/关系、能否这样推导"上的错误率显著下降。
- MVP 目标不是功能完备，而是**快速拿到业务侧真实反馈**，验证该假设。

## 5. 功能需求清单（按优先级）

> 优先级：P0=必须（MVP 验收门槛）；P1=建议（强烈建议但可后置）；P2=可选（锦上添花）。

| 模块 | 功能点 | 优先级 | 验收标准 | 关联设计 |
|---|---|---|---|---|
| 本体建模 | 4 种建模方式（手工/逆向/Schema/混合） | P0 | 均能创建可保存的本体模型 | §4.1 |
| 本体建模 | 业务层屏蔽 OWL 术语（对象/属性/关系/约束） | P0 | ITBP 不直接接触 Class/Property 原语 | §3.1/§4.1 |
| 推理校验 | 概念约束/关系推导 + 推理链路可视化 | P0 | 可展示推导过程 | §4.2 |
| 推理校验 | SHACL 一致性校验 + 版本快照 | P0 | 非法模型报错；可回溯历史版本 | §4.2 |
| 归化 | 文档/表生成候选实例，人工审核卡点 | P0 | LLM 输出**不能直接落库** | §4.3 |
| 归化 | 支持自定义 LLM endpoint | P0 | 可切换模型 | §4.3 |
| 可视化 | 本体/图谱/推理链路三视图 | P0 | 三视图可用；外部来源着色 | §4.4/§4.8 |
| 模板 | 预置模板 + 网络加载预览外部模板（LinkML） | P1 | 可新建并预览 | §4.5 |
| MCP-Server | UI 一键发布 MCP，输出查询/推理工具 | P0 | 外部 Agent 可注册调用 | §4.6 |
| MCP-Client | 接入外部含鉴权 MCP Server 读取数据 | P0 | 可配置连接并读入归化 | §4.7 |
| MCP-Client | 兼容 transport（stdio / streamable_http） | P0 | 两类 transport 均可连通 | §4.7 |
| 外部接入 | 连接配置 UI（endpoint/auth/工具白名单/字段映射） | P0 | 可保存并校验连接 | §4.7.1 |
| 外部接入 | 读取健壮性（超时/重试/401阻断/ schema 漂移停库） | P1 | 异常可被正确处理不静默 | §4.7.4 |
| Action | 受控执行引擎（定义/触发/回写） | P0 | 可按定义调用外部 | §5.3 |
| Action | **每次回写人工确认** | P0 | 无确认不执行 | §5.3 |
| Action | 幂等键 + 执行日志 | P0 | 重复触发不产生重复回写；有记录 | §5.3 |
| 凭据 | 外部凭据本地 env/配置文件管理（不入库不打印） | P0 | 凭据不落库、不打印 | §4.7.2 |

**MVP 明确不做（P-，后置 V2）**：多租户、部门隔离、审批流、细粒度血缘、完整审计、RBAC、无条件自动回写、复杂 Action 编排、流式 CDC。

## 6. 关键能力详细需求

### 6.1 本体建模（UC1）
- 4 种建模方式：手工建模、逆向建模（从数据库表导入 Schema）、Schema 约束配置、混合建模。
- 业务层语义（对象/属性/关系/约束）由平台自动翻译为 OWL2-RL + SHACL 标准层。
- **创建前轻量校验门（借鉴补丁 P-01）**：翻译为 OWL 之前，对业务层做本地纯逻辑校验（id 唯一、父级继承无环、data_type/基数合法、枚举定义合法、属性/关系名禁用敏感词 password/secret/token 等）。不通过则创建失败并返回明确错误，避免"每次击键都跑一趟推理引擎"。
- 逆向建模产出的 Schema 允许人工二次修正。

### 6.2 推理与校验（UC2 支撑）
- 概念约束、业务关系推导推理；推理链路**可追溯可视化**。
- SHACL 一致性校验；本体**版本快照**（支持历史回溯）。

### 6.3 实例归化流水线（UC2）
- 源数据（文档 / 数据表 / **外部 MCP 读取结果**）→ LLM 或字段映射生成**候选实例** → **人工审核 UI** → 审核通过入库。
- **硬约束：LLM 输出禁止直接落库**。
- 外部 MCP 读取的结构化数据走「字段映射 + SHACL 校验」路径；**首次接入或映射变更须人工确认卡**。

### 6.4 MCP 双向能力（UC3 / UC4 / UC5）
- **Server 端（向外）**：由本体 Schema **自动生成**工具，供外部智能体注册调用：
  1. `ontology_query` 本体语义查询
  2. `inference_trace` 获取推理解释链路
  3. （可选）`instance_get` 实例读取
- **Client 端（向内）**：作为 MCP 客户端连接外部数据平台 MCP Server（**对接方已提供**），读取数据并支撑 Action 回写。
- 实现：复用官方 **MCP Python SDK**，不自研传输/协议层。

### 6.5 外部数据源 MCP 接入（UC4）
- **连接配置**：每条外部源 = 一条连接配置（UI 表单落库），含 transport、endpoint、auth、工具白名单、字段映射（`field_map`）、读取方式（手动）。
- **鉴权**：本体平台 Demo **不实现自身登录/鉴权层**；鉴权由外部数据平台负责。平台调用外部时持有外部凭据：
  - `bearer_token` / `api_key`：本地 env/配置文件管理（`chmod 600`、不入 git）
  - `oauth2_client_credentials`：client 模式换 token 并缓存刷新
  - 不采用 authorization_code 等需人工浏览器登录流程
- **凭据只存 secret_ref（借鉴补丁 P-03）**：连接配置中凭据仅以 `${ENV_NAME}` 引用形式出现，**绝不写入明文**；平台建模层亦硬性拒绝 password/secret/token/api_key/raw_key 等敏感字段名，从源头杜绝误填明文（与"不落库/不打印"立场一致）。
- **读取归化**：外部工具返回 → 按 `field_map` 映射候选实例 → SHACL 校验 → 人工确认卡或自动入库（低风险）。打「数据来源=外部 MCP」溯源标记。
- **健壮性**：健康检查 + 超时（10s）+ 重试（指数退避≤3）；schema 漂移停自动入库转人工；401/403 阻断并告警，不静默降级。

### 6.6 Action 受控回写（UC5）
- Action 定义字段：`target_connection`、调用方式（`mcp_tool`/`webhook`/`rest`）、入参映射（`input_map`）、幂等键（`idempotency_key`）、确认模式（`confirmation`）。
- **执行路径**：本体 Action 触发 → 解析为外部 MCP 写工具/webhook 调用 → 带鉴权 → 结果回填本体实例/执行日志。
- **安全护栏（P0）**：
  1. 默认 `human_required` **每次执行均需人工确认**，MVP 不做自动回写；
  2. 幂等键防重复回写；
  3. 执行结果本地日志（无完整审计但留记录）；
  4. 失败指数退避 + 熔断；
  5. 外部通常不可回滚，优先幂等创建/更新。

### 6.7 可视化（UC6）
- 本体视图、知识图谱视图（区分外部 MCP 来源溯源着色）、推理链路视图。

### 6.8 模板管理
- 预置行业模板随包附带；LinkML 声明式管理；支持网络动态加载预览外部模板。

## 7. 非功能需求

| 类别 | 需求 | 说明 |
|---|---|---|
| 部署 | 本地网页服务，Docker Compose 一键起（Jena/Neo4j/Postgres/后端同机） | 浏览器访问 localhost |
| 性能 | 单次本体查询/推理响应可接受范围待压测；外部 MCP 调用超时 10s | MVP 不硬性 SLA |
| 安全 | 外部凭据不落库、不打印；回写每次人工确认；幂等 | 平台自身不鉴权（外部负责） |
| 兼容 | MCP transport 兼容 stdio 与 streamable_http | 外部 Server 形态不一 |
| 可维护 | 模块化（MCP/存储/推理/归化/Action/前端）；核心语义复用开源；测试集 | 应对单人+AI 编码风险 |
| 许可 | 允许 GPL 组件自用（Neo4j 社区版），禁对外分发修改版 | 内部自用 |

## 8. 范围边界

**MVP 包含**：本地单人建模（4 种）、推理+校验+快照、归化（人工审核）、可视化三视图、模板、MCP 双向（Server 发布 + Client 接入外部含鉴权源）、Action 受控回写（每次确认）、混合存储、凭据本地管理。

**MVP 不包含（V2）**：多租户/隔离、审批流、血缘、完整审计、RBAC、无条件自动回写、复杂 Action 编排、流式 CDC、平台自身登录鉴权。

## 9. 验收标准与成功指标

### 9.1 功能验收（P0 全绿即 MVP 通过）
- [ ] ITBP 可用 4 种方式建模并发布 MCP Server，外部 Agent 成功查询。
- [ ] 归化流水线 LLM 输出必经人工审核，无直落库。
- [ ] 可配置并连通一个外部 MCP Server（stdio 或 http），读取数据归化入本体。
- [ ] 可定义并触发一个 Action 回写外部平台，**每次均弹人工确认**，重复触发不重复回写，有执行日志。

### 9.2 价值验证指标（核心假设）
- 在相同 Agent 任务集上，接入本体约束前后，错误率/幻觉率对比（建议内部测试集 + badcase 统计）。
- ITBP 单人可在 X 小时内完成一个部门本体的搭建并跑通查询（上手时效）。

## 11. 风险与依赖

| 风险 | 影响 | 缓解 |
|---|---|---|
| ITBP 上手难、见效慢 | 价值难落地 | 业务层封装 + 模板 + 小范围试点 + 强制审核 |
| 单人+AI 编码质量差 | bug/逻辑错 | 模块化 + 复用开源 + 测试集（含 MCP mock / Action dry-run） |
| 源数据质量差→脏实例 | 加剧幻觉 | 人工审核 + SHACL + 外部接入确认卡 |
| Java/Python 混合栈 | 部署复杂 | Jena 独立 HTTP，Python 只调 API |
| 外部凭据管理 | 泄露隐患 | Demo 本地 env/配置（600/不入库不打印）；生产 KMS |
| Action 误/重复回写 | 污染外部 | 每次确认 + 幂等 + dry-run + 熔断 |
| 外部 MCP 不稳定/漂移 | 失败/脏数据 | 超时重试 + 漂移停库 + 401 阻断告警 |
