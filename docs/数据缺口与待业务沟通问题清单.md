## 结论先行（三句话）

1. **源表已定位、已逐格核对，BOM 明细在源表内完整存在**：「通用服务器原厂维保」`U~Z` 行 2~61 共 60 行 BOM（PN/描述/数量/单价/小计，`Z62=37,672`），单价由 `成本基线.xlsx`「备件成本」表按「工厂 1600 + PN」双条件查得，故障率由「部件故障率」表提供。**F 在源表内是一条完整、可复算的三级链路，不是源表逻辑缺失。**

### B3. 【v2 新增】海外 K 的税项是否启用

**需要业务部确认**：AL 列的原设计意图、未来是否补 I 值并按公式启用税项。

> **平台实现红线**：现阶段一律按 `K = H×G`，**不要按 docx「在基线上叠加额外税/保险等系数」的文字直接实现**（会凭空多算 5%~100%+，巴西税率 1.02 翻倍）。赛题包生成端 `K = H×G×(1+税率)×1.02` 是仿真数据的有意设定，三方互不等价，勿混用。

## C 组：建模 / 约束口径待明确（非阻断，但影响查询与校验）

### C1. 物料唯一约束建错了键（18 条唯一约束中唯一一处错误）

- 现状：`cst_u_material`（物料PN唯一）建在 `attr_pn` 上，但 **PN 不是唯一键**——同一 PN 在 1100 / 1600 两个工厂各一条、单价不同。
- 实测：93 条物料中 **37 个 PN 重复**；真正的业务主键 `attr_material_code`（工厂-PN 复合）93 条零重复。
- 影响：按 PN 查单价会命中 2 条 → 触发 `LOOKUP_AMBIGUOUS`。
- **v2 佐证**：源表 Y 列 XLOOKUP 实测为 `(A:A="1600")×(B:B=PN)` 双条件，确实按工厂过滤；认知文件 D8 判定「平台判断正确，保留，建议按 工厂+PN 复合键修正约束」。
- **需要业务部确认**：唯一口径是「PN 全局唯一」还是「工厂 + PN 唯一」？若是后者，建议改约束为复合键或 `attr_material_code`（`cost_baseline_kit/` 的 v2 模型采用后者，生产本体**暂未改**；两者择一，不要同时实施）。

### C2. 国内 / 海外维度组合不同（影响 lookup 分叉）

- 售后人工基线：国内 `U数×客户×产品类别×响应等级`，海外 `U数×区域×产品类别×响应等级`（**无客户列**，1132 条）。
- 若用统一维度匹配，海外会塌成 48 组重复 → 必然 `LOOKUP_AMBIGUOUS`。
- **需要业务部确认**：海外用「区域」而非「客户」作为维度是否准确（源表结构如此）；未来公式 lookup 需显式声明维度组合。当前六公式已按 `attr_domestic` 分支处理，L1 零差异。

### C3. 【v2 新增】区域建模口径：枚举实体 vs 自由标签

`obj_region` 枚举已于 11-10 傍晚扩为 36 国家/地区（见 §四、及 `docs/成本核算本体-实体枚举核查报告.md` §五），但**实例仍为 2 条**，且主表实际取数粒度由 `attr_region_label` / `attr_domestic` / `attr_country` / `attr_c_region` 四个内嵌字段承载。

**需要业务确认**：区域到底是「枚举实体」还是「自由标签」，二者主从关系如何；实例是否需要补齐到 36 条。此项只影响区域作为可复用维度实体的完整性，**不在成本复算主链路**，不影响 L1。

## 支撑材料与分级基线

- **L1 硬基准**（引擎上线必须复现，87 项）：国内 25 行 + 海外三年行，源表与复算 0 差异（容差 1e-9）。
