## A 组：必须先由业务部提供数据 / 明确口径

### A1. 【核心缺口】整机 BOM 明细缺失 → F 备件直接成本无法重算

**现象**：成本清单 33 行的 `F 备件直接成本` 全部**引用主表原值**，无法在平台内重算。

**原因（已核实本体与实例）**：
- 计算公式为 `F = Σ(物料数量 × 单价 × 故障率)`，逐部件聚合；并有附加规则（4H × 1.15、介质保留走不返还、海外 ARMA/RMA 组合口径）。
- 但本体中**没有「产品配置明细 / BOM」对象，也没有「数量」属性**。
- 「维保服务产品」虽有 `rel_product_material`（配置部件，many_to_many）关系的**定义**，但实例层**未落地**为「每台机器配了哪些部件、各多少个」的明细。
- 主表导入文件 `instance_import_batch3.xlsx` 只有 11 个成本结果列，**不含 BOM 明细列**（部件 PN / 数量 / 单价 / 故障率等）。
- 物料对象 `obj_material` 只有 `material_code / pn / desc / unit_price / factory`，**没有数量**，也不能单凭它聚合。

**清单一句话**：主表 c21 之后的 BOM 区（部件 PN、数量、单价、故障率、RMA、厂商、保修期限、返修政策、上游返修地点…）**从未建对象、从未导入**。

**需要的输入（请业务部提供）**：
1. 每个维保服务产品**对应的整机配置明细**：机器型号 → 各部件 PN × 数量；
2. 部件与**故障率 / RMA / 保修期**的对应关系（是否有现成 BOM 表或配置清单 Excel）；
3. 明确介质保留、海外 ARMA/RMA 组合是否走"不返还"、4H 是否 ×1.15 等口径。

**可能的影响**：在 BOM 补齐并建模前，平台内计算 F 只能引用主表给定值；无法独立校验其准确性。建议作为 **V2 阶段「产品配置明细对象（第 18 个对象）」** 落地，见《能力层元模型设计》与 P2 附录 D。

## B 组：口径需业务部确认（当前已用过渡口径出数）

### B1. 【已确认待定】海外四年/五年现场服务率的上浮基数

**现象**：主表海外（欧洲德国）四年/五年行的现场服务率 `D`，上浮基数**统一用了国内 D3（0.218895427866865）**，而同区域三年行实测 D3 = 0.215653093423419。

**受影响的 8 行**（全部为欧洲德国四年/五年）：r19 / r20 / r22 / r23 / r25 / r26 / r28 / r29。

**当前处理**：业务确认前，复算版清单按 **MOCK 口径**出数（`D_mock = 同区域三年实测 D3 × 年限系数`，四年 1.4 / 五年 1.88），已在「口径状态」列标注 **MOCK**。MOCK 三法校验一致（区域 D3×系数 / 主表D×区域比 / 主表海外三年D×系数）。

**影响量化**：8 行合计源表 O = 7970.69 元 → MOCK 口径 7858.20 元，**差 112.50 元（1.43%），源表偏高**；单行差异 1.38% ~ 1.47%。

**需要业务部确认**：海外四年/五年的上浮基数，应该用**本区域的 D3**（MOCK 口径）还是维持主表的**国内 D3**？确认后 L2 升级为 L1 或按业务口径替换。

## C 组：建议一并处理（非阻断，但影响查询/校验）

### C1. 物料唯一约束建错了键（18 条唯一约束中唯一一处错误）

- 现状：`cst_u_material`（物料PN唯一）建在 `attr_pn`（PN）上，但 **PN 不是唯一键**——同一 PN 在 1100 / 1600 两个工厂各一条、单价不同。
- 实测：93 条物料中 **37 个 PN 重复**；真正的业务主键 `attr_material_code`（工厂-PN 复合）93 条零重复。
- 影响：按 PN 查单价会命中 2 条 → 触发 `AMBIGUOUS`。
- **需要业务部确认**：业务上的唯一口径是「PN 全局唯一」还是「工厂 + PN 唯一」？若是后者，建议把约束改为 `attr_material_code`。
- 注：此前已决定"暂不改"，但本项仍建议跟业务部对齐，影响未来 `lookup(物料)` 的使用方式（**必须带工厂维度**）。

### C2. 国内 / 海外维度组合不同（影响 lookup 分叉）

- 售后人工基线：国内 `U数×客户×产品类别×响应等级`，海外 `U数×区域×产品类别×响应等级`（**无客户列**，1132 条）。
- 若用统一维度匹配，海外会塌成 48 组重复 → 必然 `AMBIGUOUS`。
- **需要业务部确认**：海外用「区域」而非「客户」作为维度是否准确（源表结构如此）；未来公式 lookup 需显式声明维度组合。
