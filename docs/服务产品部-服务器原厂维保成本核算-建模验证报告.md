## 三、能力模型（计算链，全部基于基线实例 lookup 驱动）

```
cap_onsite_rate_d  = 现场服务率基线(产线×客户×区域).rate × 年限系数
                     年限系数：3年=1.0；4年=×1.4；5年=×1.88  （对应 D4=D3+D3/3×1.2；D5=D3+…+D3/3×1.2×1.2）
cap_labor_cost_e   = ref(cap_onsite_rate_d) × 售后人工成本基线(u_group×客户×区域×服务等级).unit_cost
cap_spare_aux_k    = ref(cap_onsite_rate_d) × 备件辅助成本基线(国家).unit_nd/unit_4h
cap_mgmt_cost_n    = ref(cap_onsite_rate_d) × 管理成本基线(客户×售后×区域).value
cap_total_o        = cap_labor_cost_e + spare_direct(F) + cap_spare_aux_k + cap_mgmt_cost_n
cap_ratio_s        = ref(cap_total_o) / machine_cost(R=37,672)
```

- 全部能力以「可解释表达式」实现，`lookup()` 回指基线实例、`ref()` 组上游引用链，执行时返回 **溯源四要素**（能力版本+输入维度+lookup 命中+计算值）。
- 参考 docx 公式：人工 E=D×C；辅助 K=H×G（海外再叠加 I×J×1.1×1.02）；管理 N=L×M；合计 O=E+F+K+N；占比 S=O/R；Bundle P、Upsell Q 基于 O(N)−O(3年)。

## 六、口径与边界说明（重要）

1. **F（备件直接成本）当前作为验证基准值** 存入 `warranty_cost.spare_direct`（来自《成本核算逻辑.xlsx》表内已算好的 3/4/5 年各条款口径），因此 `cap_total_o` 能在给定 F 下精确还原 O。
   - F 的完整自动建模依赖 docx §4.3 精细模型（良品损耗/不良品损耗/资金占用/保外成本），并受**各厂商返修政策/质保期条件分支**（如“自研板卡 30% 不能返修”“结构件全额进成本”“返款100%”等）影响，无法用统一模板一式套用。这是**下一步待实现**的能力（将整机 BOM + 部件故障率 + 厂商政策作为输入，逐件归集）。
   - 已为本体导入 `failure_rate_baseline`（部件故障率）与 `part_price`（备件单价），为 F 能力提供了输入基础。

2. **海外（欧洲·德国）行**未纳入本轮精确验证：其人工 H 取值使用“现场人工基线”（NBD现场=1940 / 4H现场=4166）与 ARMA/RMA 组合口径，需另行建模现场人工基线对象；备件辅助税率叠加 `+ I×J×1.1×1.02` 的逻辑亦需在能力中补充海外分支。

3. **成本核算逻辑.xlsx 未被当作实例导入**：仅抽取其“通用服务器原厂维保”主表的输入维度与结果值，用于构造 `warranty_cost` 验证基准并作为比对目标，符合“结果仅用于验证”的要求。
