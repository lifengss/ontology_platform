# MVP 交付与 PRD 需求对照分析

> 生成日期：2026-10-23
> 对照对象：
> - **PRD 基线**：`proj_wiki/企业业务本体平台MVP阶段PRD-产品需求文档.md`（211 行，§3 范围与版本边界、§5 功能清单、§6 详细需求、§8 版本规划、§9 验收）
> - **实际交付**：VS0–VS10 垂直切片 + 2026-10-21/22 用户反馈轮次（权威台账 `TASK_CHECKPOINT.md` §2–§18、`README.md` 垂直切片进度表）
> - **代码实证**：`backend/` 各模块（`modeling_translator` / `normalization` / `reasoning` / `mcp_client` / `action_engine` 等）

## 判定规则

| 类别 | 定义 |
|---|---|
| **A 细化** | PRD 有此需求、但只给了目标/抽象命名，实现补齐了机制（同一能力，做深做具体） |
| **B 额外新增** | PRD 没写。再细分 ↓ |
| **B1 MVP 覆盖不足** | MVP 自身目标/场景要它，PRD 漏列（不补则 MVP 目标不达或场景走不完） |
| **B2 后续版本提前** | 超出 MVP 最小闭环，可延后、不影响 MVP 价值验证 |

## A. 被细化的功能（PRD 有、设计颗粒度不足 → 实现补机制）

| # | 功能 | PRD 原文 | 设计时缺的颗粒度 → 实现的具体决策 |
|---|---|---|---|
| A1 | 手工建模（卡片表单） | §6.1"手工建模"、"业务层屏蔽 OWL 术语"(P0) | PRD 只给目标没给交互形态 → 对象/属性/关系卡片表单，中文名为主、OWL 仅高级选项 |
| A2 | 逆向/Schema 建模的具体载体 | §6.1"逆向建模（导入 Schema from 数据库表）/Schema 约束配置" | PRD 逆向=「数据库表」，但 ITBP 实际持有的是文档/表格 → 落地为 from-doc（txt/md/docx/xlsx/pdf）+ from-excel（Excel/CSV）；本质不变（从既有业务物产生成本体），输入形态调整（DB→文档/表格） |
| A3 | 推理链可视化 + 中文业务文案 | §6.2/UC6"推理链可追溯可可视化" | PRD 没说"业务可读" → `inference_trace`（OWL2-RL 规则步骤）+ `*_zh` 文案（前提/结论中文）；原始三元组对业务人员等于没可视化 |
| A4 | 归化管线与审核卡点 | §6.3"LLM/字段映射→候选→人工审核→落库" | 状态机（pending→approved/rejected）、单条/批量操作、批准前预览、SHACL 门控、Neo4j 失败降级 JSONL；"字段映射"细化为手工 field_map + LLM 自动推断（upload-smart）两模式 |
| A5 | SHACL 校验 + 版本快照 | §6.2"一致性校验+版本快照可回溯" | pyshacl 本地引擎（Jena 远程可切换）、快照/回溯机制、violations 按规则返回明细 |
| A6 | MCP Server 发布 | §6.4"一键发布，自动生成 ontology_query/inference_trace/instance_get" | 按本体粒度独立发布/取消 + 发布状态列表；**另加 `action_invoke` 工具**——PRD §6.4 只列 3 工具，但 §6.6 要求 Action"可经 MCP 工具触发"，两节之间 PRD 自身留了缝，由实现补上 |
| A7 | 外部 MCP 连接与读取健壮性 | §6.5"连接配置 UI+超时/重试/401 阻断" | 全 CRUD + 测试连接 + 凭据引用 + 读取映射候选；指数退避 ≤8s/≤3 次重试具体化 |
| A8 | Action 受控回写 | §6.6"定义/触发/回写+每次确认+幂等键+执行日志" | dry-run→确认令牌→confirm 回写；幂等键模板（`{key}`/JSONPath 双写法）；display-only 门禁；执行日志查询 |
| A9 | 凭据本地管理 | §6.5"本地 env/配置文件、不落库、不打印" | 本地引用文件 + 状态接口（是否设置/启用/加密）+ `CREDENTIAL_ENCRYPTION_ENABLED` 开关 |
| A10 | 可视化三视图+来源着色 | §6.7 | D3 schema/knowledge 双 tab、TBox+ABox、外部来源着色、实体树（含环安全修复） |
| A11 | 自定义 LLM endpoint | §6.3/§7"可配自托管模型 endpoint" | `LLM_ENDPOINT`/`LLM_MODEL` + Ollama 本地 + 自定义 endpoint |
| A12 | 实例存储与物化 | §7"模块化、Jena 可替换" | InstanceStore（JSONL 默认/Jena 预留）+ `rdf_sync` 全量 RDF 物化（命名图）与重建 |

> 其中 A6 的 `action_invoke` 值得单独点名：它不是拍脑袋加的，而是 **PRD 内部矛盾（§6.4 工具清单 vs §6.6 触发方式）的必然补齐**。

## B. 额外增加的需求（PRD 没写）

### B1. MVP 设计覆盖不足（PRD 漏项，但 MVP 自身目标/场景离不开）

| 功能 | 为什么是覆盖缺口 | PRD 侧证据 |
|---|---|---|
| **from-text（AI 自然语言生成本体）** | PRD 立了"低门槛建模"目标，但它给的 4 种方式全是结构化输入向（表单/DB 表/Schema），没有任何一条让"零技术背景业务人员直接建模"——**目标在 PRD，达标手段不在 PRD**。NL 生成是唯一真正兑现低门槛的入口 | UC1"低门槛建模"；§3 风险"ITBP 上手难、见效慢"及其缓解措施 |
| **enrich（基于上传材料扩展现有本体）** | PRD 只有"新建本体"，没有"对已有本体增量扩展"。但 §9.2 场景"一人一天建模一个部门本体"（L6 实证：2 万行 Word+Excel）必须靠"建模→查询验证→发现缺失→补充"的迭代闭环，单靠一次新建走不完 | §9.2"一人+1 天"；UC5"快速修改本体"；§3"需要看到建模的价值" |

> 附注：enrich 同时兑现了 PRD 第 4 种方式"混合建模"（文档+Excel+人工多源组合）的意图——它一半是 A（混合建模细化）、一半是 B1（"扩展已有"缺口），整体按 B1 计。

### B2. 后续版本需求被提前（超出 MVP 最小闭环，可延后）

| 功能 | 为什么可延后 | 与 V2 的关系 |
|---|---|---|
| **NL 查询（NL→SPARQL 前端自然语言查询）** | PRD 的价值验证路径是"外部 Agent 经 MCP 查询"（UC3、§9.2 对比法），**人侧 NL 查询不在这条验证路径上**，延后不影响 MVP 验证成立 | 可用性扩展（V2 清单里也没有，属"顺手做的增强"） |
| **影响推演（实例级 what-if 传导）** | PRD 的推理指 schema 层（概念约束/关系推导）；"订单延误→哪些计划节点受影响"是实例级高级推理，MVP 验证不需要它 | 高级能力；由用户直接点名（3.1）驱动 |
| **项目管理（多项目创建/归档/恢复/删除+统计）** | MVP 最小 = 1 个项目即可验证价值；多项目组织是组织便利 | **≠ V2 多租户隔离/RBAC/审批（这些确实没做）**，只是轻量前置 |
| **部门空间（namespace）组织功能** | PRD 明确"部门隔离→V2"；空间管理是组织登记，无隔离/权限/审批 | V2 部门组织的**轻量前置**（远轻于 V2 范围）；注意其底层 ID 命名空间（防对象/属性 id 冲突）属 A 类细化，不在此列 |

## 边界判断（分析中做的裁决，可推翻）

1. **from-doc 归 A 不归 B**：它本质是 PRD"逆向建模"的细化，但输入形态从 PRD 原文"数据库表"改成了"业务文档"。若严格按 PRD 字面，这是**形态扩展**、应升 B1。裁决理由：PRD 逆向的意图是"从既有业务物产而非白纸生成本体"，文档比 DB 表更贴合 ITBP 实际持有物，属意图内修正。
2. **NL 查询归 B2 不归 B1**：因 PRD 验证路径只认 Agent 查询。若认为"ITBP 自己能验证查询效果"是 MVP 可用性的硬需求，应升 B1——对 MVP 结论无实质影响，只影响"提前了哪些"的清单。
3. **部门空间拆分计**：ID 命名空间（技术防冲突）计 A，"部门空间"管理 UI 计 B2。若认为多部门组织是 MVP 需求，可整体升 B1；但 PRD §3 明确把部门相关划 V2，B2 更自洽。

---

## 一句话总结

交付 = **PRD P0 主链路全实现**（A 类细化 12 项，其中 `action_invoke` 是补 PRD 自身裂缝）+ **2 项 MVP 真缺口补齐**（NL 建模 from-text、enrich）+ **4 项提前/增强**（NL 查询、影响推演、项目管理、部门空间）。反向缺口：原 **1 个 P0 缺口**（Action 熔断/HTTP 回写无重试）已于 **2026-10-23 补漏闭环**（TASK_CHECKPOINT §19，`test_action_resilience.py` 7/7）；剩余反向项为 **2 个 P1 可延后**（schema 漂移停库、LinkML 网络模板）+ **stdio 部分**（http 已满足验收「stdio 或 http」）。
