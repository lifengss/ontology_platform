三、逻辑链（节点 · 边）

下图展示「通用服务器原厂维保」的取数与核算链路：输入维度 → 基线对象(lookup) → 能力(计算/ref) → 聚合输出。

四、取数与核算方法

  • 取数（lookup）：lookup('对象', {维度键}, '属性') 按维度在基线实例中回指取值；维度键如 u_group=1U/2U、customer=其他、region=国内、service_class=NBD。
  • 年限上浮：cap_onsite_rate_d 内 D4 = D3×1.4、D5 = D3×1.88（即 docx D4=D3+D3/3×1.2，D5=D3+…+D3/3×1.2×1.2）。
  • 核算（ref）：ref('cap_xxx') 串联上游能力，如 cap_total_o = cap_labor_cost_e + spare_direct + cap_spare_aux_k + cap_mgmt_cost_n。
  • 溯源四要素：每次执行返回 能力版本 + 输入维度 + lookup 命中记录(matched_record_id) + 计算值，供人工复核。

五、覆盖与限制

⚠ 源表公式引用错误（本次联测发现的源数据问题，已在平台按基准表为准修正，不迁就）
《成本核算逻辑.xlsx》「人员驻场核算」表「月成本」为手工单元格引用：
- 江苏行 `=[1]人员驻场成本!$E$3`（SV·中级·博辉=10000）→ 正确，与「SV中级驻场」一致；
- 北京行 `=[1]人员驻场成本!$C$10`，但 C10 是「STR·初级·华夏（北京）=9000」，与其标注的「STR中级驻场」错位——作者把行号指到初级行（第10行），正确应为第11行（STR·中级·华夏（北京）=13000）。
判定：这是源表引用行号偏移（差一行）导致的样例值错误，非建模/取数逻辑问题。联测以基准表（《成本基线.xlsx》人员驻场成本）为准：北京 STR 中级按基准 = 13000 × 12 = 156000；平台能力 `cap_station_cost` 按该口径精确命中。不建议按核算表错误值 9000/108000 迁就。

待业务裁定的源数据口径问题（非建模/取数问题）

1. 驻场「北京」：核算表月成本引用 人员驻场成本!$C$10（STR·初级=9000），与其标注「STR中级驻场」错位，应为 $C$11（STR·中级=13000）。→ 按基准表=13000→156000。
2. 单次维修 F 口径：备件成本表同 PN 有双工厂价（内存 V004051：1100厂=102 / 1600厂=146；主板 YZMB：1100厂=142 / 1600厂=190）。单次维修取 工厂=1600（146/190），焕新用仓库平均价(1100厂)。→ 已在平台按工厂 1600 口径落地。
3. 海外（欧洲·德国）现场服务率 D：结果表海外 D(4年)=0.3065、D(5年)=0.4115，不从海外基数 0.2157 按 ×1.4/×1.88 递增（应为 0.30191/0.40543），而是与国内基数 0.2189 的递增值一致——海外 3 年(0.2157)与 4/5 年(0.3065/0.4115) 基数不一致。需裁定：海外 4/5 年 D 取 0.2157 递增（基准表为准）还是取 0.3065/0.4115（与国内一致）。
