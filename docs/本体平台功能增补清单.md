## 二、应用便捷性增补（GAP-04 ~ GAP-07 / GAP-18）

### GAP-01　PUT 实例整体替换会清空单字段（P0）
- **问题**：`PUT /api/ingest/instances/{id}` 需传完整 `{"instance":{...}}`，只传单字段会把实例其余属性全部清空，存在误操作数据丢失风险。
- **影响**：业务/脚本误用导致数据丢失，不可逆。
- **修复方案**：
  - 后端：`backend/api/router_ingest.py` 的 PUT 处理改为「差量更新」语义——仅更新传入字段，未传字段保留；若确需整体替换，增加显式 `replace=true` 参数并强制校验。PATCH 保持字段级修改不变。
  - 前端：`frontend/app.js` 实例编辑默认走 PATCH；若保留 PUT，编辑保存前弹"将整体替换"强确认。
  - 兼容：老脚本仍能 PUT，但仅更新传入字段，行为变更需在 `docs/API-INTERFACE-DOC.md` 标注 breaking。
- **验收**：PUT 单字段后其余属性不变；PATCH 单字段生效；无替换标志时不触发清空。

### GAP-04　建模门槛高（P1）
- **问题**：建模前需人工整理"本体清单"（对象/属性/关系/主键/约束），把业务抽象成结构，业务人员负担重。
- **影响**：上手慢，与"ITBP 单人 X 小时搭完"价值目标冲突。
- **修复方案**：
  - 新增"数据表/文档 → 本体草稿"强引导：`backend/api/router_ontologies.py` 已有 from-excel/from-doc，增强为**上传即出草稿 + 逐项可编辑**，弱化"先设计再录"。
  - 前端 `frontend/app.js` 建模页加"从已有数据生成"入口，生成后进入对象/属性/关系列表式编辑。
  - 提供示例本体模板（含约束示例），一键复用后改。
- **验收**：上传一份数据表即可产出可编辑草稿本体，无需手写全量清单。

### GAP-05　数据-模型双向反复（P1）
- **问题**：导入素材时常发现模型缺口（缺字段/枚举缺值/约束过紧），需"建模页改→保存→校验→重新发布→再导入"来回折腾。
- **影响**：一条导入链路要跨多页重复操作。
- **修复方案**：
  - 后端：`backend/api/router_ingest.py` 校验失败时返回**带建议的结构化缺口**（缺字段/枚举缺值/约束冲突）。
  - 前端 `frontend/app.js` 导入页就地弹出"模型缺口"，提供"一键在模型上补字段枚举/放宽约束并重发布"按钮（走 `POST /api/ontologies/{oid}/changesets` 兼容变更），无需跳页。
- **验收**：导入校验失败即可原地修复模型并重发布，成功后继续导入。

### GAP-06　接口约定不直观（P1）
- **问题**：`object_type` 须放 body（放 query 被忽略）、`field_map` 必须非空（identity map 可）、分页用 `page/pageSize` 而非 `page_size/offset`、CSV 空字段被读成 `""` 触发 SHACL 报错。
- **影响**：集成方/脚本开发者频繁踩坑。
- **修复方案**：
  - 后端：`backend/schemas` 与 `backend/api/router_ingest.py` 增加**别名兼容**（接受 `page_size/offset` 作为别名；object_type 支持 query 与 body 双通道并给出清晰校验）；`backend/ingestion` 的 `_coerce_record_types` 对空串字段直接剔除而非保留（消除 `Literal("") not in list`）。
  - 文档：把上述已知坑写入 `docs/API-INTERFACE-DOC.md` 醒目位置，并提供 curl/示例。
- **验收**：误用 `page_size` 不再固定返回 50 条；空字段不触发枚举/必填报错；`field_map` 为空给明确 400 提示。

### GAP-07　无"当前项目"全局上下文（P1）
- **问题**：多项目隔离靠每条请求手传 `?project_id=`，跨页易切错项目。
- **影响**：数据混、操作错对象。
- **修复方案**：
  - 后端：`backend/api/auth_middleware.py` 或 `backend/api/dependencies.py` 支持从登录态取默认项目；`GET /api/projects` 提供当前身份默认项目。
  - 前端 `frontend/app.js`：顶栏全局项目选择器（记忆最近项目到 localStorage），请求统一注入 `project_id`。
- **验收**：切换一次项目后全页请求归一到该项目，无需逐接口传参。

### GAP-18　MCP 发布后初调 503（P2）✅ 2026-11-19
- **问题**：`POST /api/mcp/server/publish` 后立即调用 `/mcp/{pid}` 返回 503"启动中"，需人工轮询。
- **影响**：首次调用体验差。
- **修复方案**：
  - 后端：`backend/api/router_mcp.py` 发布流程同步拉起或返回就绪状态；`GET /api/mcp/status` 含 `ready`/`starting`，客户端据此重试而非硬编码轮询。
- **验收**：发布完成后首次调用即可用，或返回明确就绪状态。

## 三、友好性增补（GAP-02 / GAP-08 ~ GAP-13）

### GAP-02　错误文案技术化（P0）
- **问题**：错误如 `SHACL 违规`、`INCOMPATIBLE_REQUIRES_MAJOR`、`MISSING_INPUT_ATTR`、`Value Literal("") not in list` 直接抛给业务用户。
- **影响**：业务人员看不懂、无法自助，依赖技术人员。
- **修复方案**：
  - 后端：`backend/core/responses.py` 统一错误封装，为常见错误码映射**人话文案 + 修复建议**（如"该值不在允许枚举内，请选择：A/B/C"）。
  - 前端 `frontend/app.js`：错误 toast 展示"人话 + 修复建议 + 跳转处理入口"。
  - 验收用 `docs/本体平台QA全类别测试用例设计.md` 错误态用例核验。
- **验收**：上述错误码均展示业务可读文案与可执行建议。

### GAP-08　无角色工作流引导（P1）
- **问题**：页面按功能罗列，新手不知建模→导入→发布→调用顺序。
- **影响**：冷启动成本高。
- **修复方案**：
  - 前端 `frontend/app.js`：首页/空态加"ITBP 五步向导"（①选定项目②建模或模板③导入数据④发布 MCP⑤AI 平台调用），每步可跳转并显示当前进度。
- **验收**：首次进入可见向导，五步可各跳转。

### GAP-09　AI/文档生成 draft 无差异 diff/一键采纳（P1）
- **问题**：from-text/from-doc 生成 draft 后，需在表单里逐字段核对、手改。
- **影响**：审核工作量≈重做，生成能力价值打折。
- **修复方案**：
  - 后端：`backend/schemadiff.py` 已有 diff 能力，暴露"生成结果 vs 当前草稿"的结构化 diff 接口。
  - 前端 `frontend/app.js`：差异视图逐项"采纳/驳回"，一键采纳全部。
- **验收**：生成后可逐项 diff 决策，无需整表手抄。

### GAP-10　无权限 tab 直接隐藏（P1）
- **问题**：viewer 角色看到多个 tab 直接消失，无"为何看不到"。
- **影响**：用户困惑是否故障。
- **修复方案**：
  - 前端 `frontend/app.js`：无权限的 tab 改为显示 + 禁点 + 工具提示"需要 XX 权限"（或"无权限"）。
- **验收**：viewer 可见被禁项及原因提示。

### GAP-11　异步任务无进度（P1）
- **问题**：from-doc 等异步 job 仅一次 toast，无进度条、不可取消/重试。
- **影响**：长文档解析等待无反馈。
- **修复方案**：
  - 后端：`backend/api/router_ontologies.py` 返回 job 状态（queued/processing/done/failed）与进度；提供 cancel 接口。
  - 前端 `frontend/app.js`：右下角任务面板显示进度条、可取消、失败可重试、完成后通知。
- **验收**：解析期间可见进度，可取消/重试。
- **✅ 已交付（2026-11-19）**：
  - 后端 job 记录扩展 `status(pending/running/done/error/cancelled)/stage/progress/kind/file_names/draft_id/error/created_at/updated_at/retried_from`；`_JOBS_PARAMS` 留存原上传字节供重试；`_JOBS_CANCEL` 协作式取消事件。
  - 新端点：`GET /api/ontologies/jobs`（列表，注册于 `GET /{ontology_id}` 通配之前防吞路由）、`POST /jobs/{id}/cancel`（仅 pending/running，终态 409）、`POST /jobs/{id}/retry`（仅 error/cancelled，复用原参数新建 job 返 202，参数缺失 409）。
  - 前端：左下 `#taskPanel` 任务面板（进度条/阶段/取消/重试/清除/收起），2s 轮询列表接口，终态一次性 toast 通知；完成沿用 GAP-09 自动选中新草稿 + 差异审核；页面刷新后续显；`?api=` 查询参可显式指定后端基址（开发/沙箱）。
  - 测试：`backend/tests/test_gap11_job_lifecycle.py` 9 项；L5 全量 301/301 绿；浏览器冒烟 7 组（提交/进度/完成自动选中/取消冻结/重试续跑/渲染/刷新续显）。

### GAP-12　图谱三视图交互弱、大图慢（P1）✅ 2026-11-19
> 已交付（TASK_CHECKPOINT §83）：后端 `GET /api/graph/{id}/neighbors` 按需邻居查询（对象＝关系边无向 BFS＋实例抽样；实例＝所属对象＋同对象抽样）；前端视口虚拟化渲染（>150 节点只绘视口内节点/边）、缩放拖动（既有 d3.zoom）、类型/来源筛选 chips＋对象类型下拉、双击节点增量展开邻居＋重置展开。测试 `tests/test_gap12_graph_neighbors.py` 12/12；L5 全量 328/328。
- **问题**：数据量大时图谱卡顿，无缩放/拖动/按类筛选。
- **影响**：可视化可理解性下降。
- **修复方案**：
  - 前端 `frontend/app.js` + `backend/viz`：图视图虚拟化渲染（只渲染可视区）、画布缩放/拖动、按对象类型/来源着色筛选；数据量大时分页加载邻居。
  - `backend/viz` 提供按需邻居查询接口（避免一次拉全图）。
- **验收**：千级节点时拖动/缩放流畅，可按类型筛选。

### GAP-13　新项目空白（P1）✅ 2026-11-19
- **问题**：新项目全空白，无示例/模板一条龙。
- **影响**：冷启动难。
- **修复方案**：
  - 后端：`backend/template` 扩充行业模板；提供"示例项目"（预置示例本体+少量实例）。
  - 前端 `frontend/app.js`：空项目页显示"从示例模板创建/导入示例数据"一键入口。
- **验收**：一键创建含示例本体与实例的项目。

## 四、执行效率增补（GAP-03 / GAP-14 ~ GAP-17 / GAP-19）

### GAP-03　默认走慢性能路径（P0）
- **问题**：本地基准 Fuseki 推理 ≈62× 本地（约 20.9s vs 0.34s）；SHACL Jena 子进程 3.37s vs 本地 pyshacl 0.98s，且默认走慢引擎，基线未冻结。
- **影响**：真实使用命中慢路径，体验差。
- **修复方案**：
  - `backend/reasoning` + `backend/jena_adapter`：默认本地快路径；Fuseki 仅作为可切换增强；推理改为异步/后台执行 + 结果缓存。
  - 冻结性能基线与阈值（`scripts/bench_v2_16_reasoning.py` / `bench_v2_17_shacl.py`），设"可接受响应时间"目标（如查询 <1s、推理 <3s），超出告警。
- **验收**：默认路径时延恢复到快基准；性能阈值冻结并有回归监测。

### GAP-14　JSON 文件存储无索引/缓存（P1）✅ 2026-11-19
- **问题**：`backend/core/instance_store.py` 以 JSON 文件为主，无内存索引/缓存；大本体/大实例集查询慢，列表/树计数失真。
- **影响**：规模上来后变慢、计数不准。
- **修复方案**：
  - `backend/core/instance_store.py`：关键读路径（stable_key 查询、列表、计数）加内存索引（如 HF-13 的 `_build_stable_key_index` 扩展为通用）+ 轻量缓存；列表分页 + 总量缓存。
  - 树计数失真：`backend/core/storage.py` 计数改为数据库/索引聚合而非全量扫描。
- **验收**：大实例集列表/计数准确且响应明显提升。

### GAP-15　图谱库与 data/ 需手动 rdf-sync（P1）✅ 2026-11-19
- **问题**：发布/导入后，Jena 图可能滞后，需人工 `POST /api/graph/{oid}/rdf-sync`。
- **影响**：一致性靠人工触发，图谱查询可能拿到旧数据。
- **修复方案**：
  - `backend/jena_adapter`：在 publish/approve 后自动触发增量 rdf-sync；或提供一致性检查任务 + 后台定期对账 + 告警。
- **验收**：发布后无需手动 sync，图谱即时反映最新数据。

### GAP-16　外部 MCP 串行 + 10s 超时（P1）✅ 2026-11-19
- **问题**：多源联邦读取串行，且外部调用固定 10s 超时。
- **影响**：依赖多、源慢时整体响应慢。
- **修复方案**：
  - `backend/mcp_client` + `backend/content_access`：多源联邦读改**并行**（asyncio.gather）；超时按源配置；对读结果做缓存（TTL）。
- **验收**：多源联邦读并行使总时延降到接近最慢单源；可配超时与缓存。

### GAP-17　仅测试级 mock 压测（P1）✅ 2026-11-19
- **问题**：容量验证只有测试 mock（CCDC），无真实规模/并发压测。
- **影响**：说不清可扛多少 QPS/并发。
- **修复方案**：
  - 新增 `scripts/bench_capacity.py`：统一构建大本体（如 5 万实例）+ 并发压测（100/500 并发、查询/推理/导入混合），输出 QPS/P95/错误率，目标值冻结。
- **验收**：提供基准容量报告与可复跑脚本。

### GAP-19　无查询缓存/预聚合/并行批处理（P2）✅ 2026-11-19
- **问题**：高频查询无结果缓存，无预聚合，批量导入/校验串行。
- **影响**：高频/大数据场景吞吐受限。
- **修复方案**：
  - `backend/core`：通用查询结果缓存（按 project/ontology/query 哈希，TTL + 失效）；批量导入/校验改并行分块（复用 HF-11/13 分块思路）。
- **验收**：相同查询命中缓存显著提速；批量导入并行吞吐提升。

## 五、测试基建与工程健壮性（GAP-20 ~ GAP-23）

### GAP-20　测试套件鉴权 env 污染（P1）
- **问题**：全量 `pytest` 顺序跑时，`test_user_friendly`(5) + `test_v2_02_alignment`(5) 共 10 项失败，因多个测试模块直接写 `os.environ["ONTOLOGY_AUTH_ENABLED"]` 且未恢复 `false`，同进程污染后续基线用例收到 401。隔离单跑 14/14 全过。
- **修复方案**：
  - `backend/tests/`：凡设置 `ONTOLOGY_AUTH_ENABLED` 的用例（`test_password_policy`/`test_v2_02_alignment`/`test_user_management`/`test_v2_15_query`/`test_v2_22_trace`）改为 `monkeypatch.setenv`（自动恢复）或 `try/finally` 恢复为 `false`。
- **验收**：全量套件 0 顺序依赖失败，上述 10 项在全量中通过。

### GAP-21　PG/K8s 用例环境依赖（P1）
- **问题**：`test_v2_20_k8s` 的 4 项因 `INSTANCE_STORE_BACKEND=pg` 需连 `localhost:5432`，未起 Postgres 报 `Connection refused` 而失败/错误。
- **修复方案**：
  - `backend/tests/test_v2_20_k8s.py`：用例前探测 5432 可用性，不可用即 `pytest.skip`（带原因），并在 CI/本地文档说明需 `docker compose up postgres`。
- **验收**：缺 Postgres 时自动 skip 而非 fail；起 PG 后全过。

### GAP-22　套件未按"鉴权态/基线态"分包（P1）
- **问题**：鉴权态用例与基线态用例混在同一进程，冲突（GAP-20 根因之一）。
- **修复方案**：
  - `backend/conftest.py` / pytest 配置：用 mark（如 `@pytest.mark.auth`）标记鉴权用例，分两组运行（`pytest -m "not auth"` 为基线、`-m auth` 为鉴权），或独立 session 隔离。
- **验收**：基线组与鉴权组独立运行互为绿。

### GAP-23　前端/UI 无持续可复跑冒烟（P2）✅ 2026-11-19
- **问题**：UI 测试以里程碑验收脚本（`scripts/verify_m2*`、`verify_m3g_exit`）为主，无持续可复跑的前端冒烟（8 页加载 + 3 关键流）。
- **修复方案**：
  - 新增 `scripts/verify_ui_smoke.py`（复用 agent-browser 系统 Chrome 方案）：8 页加载、建模→导入→发布→图谱→MCP 关键流，作为每次回归的 UI 冒烟。
- **验收**：可独立复跑，作为回归门禁之一。
