# 平台修改建议：图谱页三视图初始化布局

> 范围：`frontend/app.js` 的 `drawGraph()`（3069-3180 行）、`drawTree()`（3184-3279 行）
> 关联后端：`backend/viz/viz.py` 的 `_schema_graph()` / `_knowledge_graph()`
> 现象：① 本体视图、② 知识图谱视图初始化后节点间距过大、节点与标签过小；③ 类树视图初始化不在画布中央

---

## 一、结论速览

| 视图 | 现象 | 根本原因 | 建议优先级 |
|---|---|---|---|
| ① 本体（schema） | 节点散得极远、缩成一堆小点、标签全隐藏 | 该图只有 **17 个对象节点 + 2 条关系边**（89 个属性不入图）→ 15 个孤立节点；孤立节点之间**只有斥力、没有约束力**，`forceManyBody` 又未设 `distanceMax`，被无限推远；`fitAll` 只能靠整体缩小来全览，缩完后节点 ~9px、标签阈值判定为隐藏 | P0 |
| ② 知识图谱（knowledge） | 同上，且更严重、首屏卡顿 | 2297 个实例节点全部入图，每个实例只挂 1 条 `instance_of` 边；一个 hub（如售后人工基线）挂 1372 个实例，物理上无法紧凑；2300 节点 × 300 tick 的力导向在浏览器里既慢又必然炸开 | P0（含性能） |
| ③ 类树（tree） | 整体偏上、顶部被裁掉、一缩放就跳位 | `g` 初始 transform 硬编码 `translate(90,16)`；而 `d3.tree().nodeSize()` 会把**根节点的 x 归零**、子节点 x 有正有负 → 负坐标部分（约 208px）跑到画布外；另外 zoom 的 transform 会**整体覆盖**这个初始值 | P0 |

## 二、视图 ①②：力导向图（本体 / 知识图谱）

### 2.1 根因拆解

**（1）力参数与图结构不匹配（主因）**

现状 `app.js:3095-3099`：

```js
.force('link', d3.forceLink(links).id(d => d.id).distance(d => d.kind === 'instance_of' ? 55 : 90))
.force('charge', d3.forceManyBody().strength(-220))
.force('center', d3.forceCenter(width / 2, height / 2))
.force('collide', d3.forceCollide(d => nodeRadius(d) + 6));
```

- `forceManyBody` **没有设 `distanceMax`**，默认作用距离为无穷远。孤立节点（无边的对象）之间没有任何吸引力，只被斥力推，最终会推到斥力可忽略的距离上——即"能推多远推多远"。
- `forceCenter` 只做**整体平移**（把质心搬到画布中心），**不产生向心收缩力**。所以它对"散得开"毫无帮助，只是保证散开后还在屏幕中间。
- 结果：17 个节点被撑到约 2000×1500 的尺度，`fitAll` 算出 scale ≈ 0.3，节点直径只剩 ~9px。

**（2）`fitAll` 与标签阈值互相叠加**

- `app.js:3129`：`scale = Math.max(0.05, Math.min(w/(dx+60), h/(dy+60), 1.25))`——只限制放大不超过 1.25，缩小没有舒适度保护。
- `app.js:3111`：标签显隐条件是 `nodeRadius(d) > 20 || nodeRadius(d) * viewScale > 14`。缩放后 `viewScale≈0.3`，需要半径 > 46px 才显示——而对象节点半径上限只有 38 → **标签全部隐藏**，只剩一堆无名的散点。这就是"看着费劲"的直接来源。

**（3）知识图谱的规模问题（独立且更严重）**

`backend/viz/viz.py:_knowledge_graph()` 把 **全部实例**一次性塞进 nodes/edges，无任何上限或聚合：

- 节点 2297 + 边 2297，每条 `instance_of` 的 `distance=55`，而售后人工基线一个对象下挂 1372 个实例——1372 个点要同时满足"距 hub 55px"+"互不重叠"，只能膨胀成一个巨大的环/云，再叠加 `charge(-220)` 进一步炸开。
- 性能：Barnes-Hut 每 tick O(n log n)，300 tick × 2300 节点，首屏会明显卡顿数秒。

### 2.2 修改建议

**P0-1：给斥力加作用域 + 换成真正的向心弹簧**

把 `forceCenter` 换成 `forceX/forceY`（弹簧产生真实收缩力），并按节点规模给定强度：

```js
const N = nodes.length;
const chargeStrength = N > 800 ? -35 : N > 300 ? -60 : N > 80 ? -90 : -130;
const chargeMaxDist  = N > 300 ? 220 : 420;   // 关键：限制斥力作用半径，团簇不再无限膨胀

const simulation = d3.forceSimulation(nodes)
  .force('link', d3.forceLink(links).id(d => d.id)
    .distance(d => d.kind === 'instance_of' ? (N > 300 ? 30 : 55) : 90)
    .strength(d => d.kind === 'instance_of' ? 0.9 : 0.5))     // 显式给定，别用 d3 默认的 1/min(deg)
  .force('charge', d3.forceManyBody().strength(chargeStrength).distanceMax(chargeMaxDist))
  .force('x', d3.forceX(width / 2).strength(0.06))            // 弱向心：孤立节点收拢
  .force('y', d3.forceY(height / 2).strength(0.06))
  .force('collide', d3.forceCollide(d => nodeRadius(d) + (N > 300 ? 3 : 6)));
```

要点说明：
- `distanceMax` 是收拢团簇**最有效**的一招，务必加；
- `forceX/forceY` 的 strength 取 0.05~0.08，过大图会塌成一团、过小不起作用；
- 大图（N>800）建议 `.alphaDecay(0.05)`（默认 0.0228）提前收敛，减少等待。

**P0-2：知识图谱必须做规模治理（否则参数怎么调都没救）**

二选一，建议选 A：

- **A（推荐，后端改动小）**：`_knowledge_graph()` 增加采样上限，按对象类型均匀抽样，默认每对象最多 50 个实例、全图最多 300；返回值补 `truncated: true, total_instances: 2297, shown: 300`。前端在图上加一行提示"已抽样显示 300 / 2297 条实例，点击对象节点可展开该对象全部实例"。
- **B（前端聚合模式，信息密度更高）**：knowledge 视图默认只画 17 个对象节点，节点半径 ∝ 实例数、标签带"对象名 ×1372"；点击某对象才把它的实例（前 100 条）展开成卫星点。展开/收起复用类树的 `_children` 折叠逻辑。

**P1-3：`fitAll` 改进**

```js
const scale = Math.max(0.05, Math.min(1.6, Math.min(width / (dx + pad * 2), height / (dy + pad * 2))));
```
- 放大上限从 `1.25` 提到 `1.6`，收拢后小图能被适度放大，字号可读；
- 首次 fit 建议**不要**用 400ms transition，直接 `svg.call(zoomBehavior.transform, t)`，避免"先炸开再缩回"的观感；或改为在 tick 中渐进 fit（前 ~60 tick 持续居中）。

**P1-4：标签显隐阈值放宽**

`app.js:3106` 的 `R_BASE = 20, R_ZOOM = 14` 改为 `R_BASE = 16, R_ZOOM = 9`；并增加规则：**kind === 'object' 的节点标签始终显示**（对象数量少，代价可忽略，收益是可读性）。

**P2-5：交互补充**

- 增加「适应画布」按钮（重新 fit 到全图/当前选中节点），并在类树展开/折叠后自动 refit；
- knowledge 视图增加"实例数量上限"下拉（100/300/1000/全部），全部时给出性能提示；
- 顺带说明：schema 视图目前**不含 89 个属性节点**（`_schema_graph` 只输出对象 + 关系），所以本体视图天然是"17 个点、2 条线"。如果希望本体视图更有信息量，可考虑把属性也纳入 schema 图（图会自然变密，顺带缓解稀疏感）——这是产品取向问题，需要你定。

## 三、视图 ③：类树（drawTree）

### 3.1 根因拆解

**关键点：`d3.tree().nodeSize([28, 230])` 的 x 坐标是"相对根节点归零"的。**

d3-hierarchy 在布局最后一步执行 `node.x = (node.x - root.x) * dx`，即根节点 x=0、兄弟节点在 0 的上下两侧展开。当前本体 17 个对象**全部没有 parent**（实测 `parent` 均为空），所以它们都挂在虚拟根 `__root__` 下、同为 depth=1 的叶子：

- x 范围 ≈ `[-224, +224]`（16 × 28 = 448，中心归零）
- 渲染时 `translate(d.y, d.x)` → 屏幕纵坐标 = `d.x`
- `g` 初始 transform 只有 `translate(90, 16)`（`app.js:3221`）→ 屏幕纵坐标 = `16 + [-224, 224]` = `[-208, 240]`

容器高约 500px，可见区间是 `[0, 500]`。于是：**顶部约 208px 被裁到画布外，底部空出 260px**——树明显偏上且缺头。这就是"初始化不在中央"。

横向同理偏左：虚拟根占 depth=0（屏幕 x=90，不渲染但占 230px 深度间距），真实根在 320，depth=2 在 550；`root.links()` 还会画出一条从虚拟根出发的多余引线。

第三个问题：`svg.call(d3.zoom().on('zoom', e => g.attr('transform', e.transform)))`（`app.js:3278`）——zoom 事件把 `g` 的 transform **整体替换**，初始的 `translate(90,16)` 立刻丢失，所以手动缩放/平移时会"跳一下"。

### 3.2 修改建议

**P0-1：初始位置改为"按包围盒居中"，并交给 zoomIdentity 托管**

替换 `app.js:3220-3221` 与 `3278`：

```js
const svg = d3.select('#graphContainer').append('svg').attr('width', width).attr('height', height);
const g   = svg.append('g');

const zoom = d3.zoom().scaleExtent([0.1, 4]).on('zoom', e => g.attr('transform', e.transform));
svg.call(zoom);

// 每次 update() 后调用：按树包围盒居中（可选地 fit 到容器）
function refit(animate) {
  const desc = root.descendants().filter(d => d.data.kind !== 'virtual');
  if (!desc.length) return;
  const xs = desc.map(d => d.y), ys = desc.map(d => d.x);          // 横向树：屏幕x=d.y，屏幕y=d.x
  const minX = Math.min(...xs), maxX = Math.max(...xs);
  const minY = Math.min(...ys), maxY = Math.max(...ys);
  const pad  = 40;
  const s = Math.max(0.1, Math.min(1,
    Math.min((width  - pad * 2) / (maxX - minX + 200),             // 200 ≈ 标签宽度预留
             (height - pad * 2) / (maxY - minY + 40))));
  const tx = width  / 2 - s * (minX + maxX) / 2;
  const ty = height / 2 - s * (minY + maxY) / 2;
  const t  = d3.zoomIdentity.translate(tx, ty).scale(s);
  if (animate) svg.transition().duration(300).call(zoom.transform, t);
  else svg.call(zoom.transform, t);
}
```

要点：
- 必须用 `zoom.transform` 设置初始 transform（而不是手写 `g.attr('transform', ...)`），这样 d3 会把居中量记进内部状态，后续缩放/平移都叠加在它之上，不会跳位；
- `scaleExtent` 下限从 `0.25` 放到 `0.1`，否则深树展开后 fit 不到；
- 在 `update()` 末尾调用 `refit()`，展开/折叠后自动回到可视区。

**P0-2：处理虚拟根**

- 过滤掉虚拟根的连线：`root.links().filter(l => l.source.data.kind !== 'virtual')`；
- 或布局后把所有节点的 `y` 整体减一个深度间距（`d.y -= 230`），消除左侧 230px 空白。推荐前者（更干净），或两者都做。

**P1-3：节点间距按内容自适应**

`nodeSize([28, 230])` 是写死的。建议：
- 纵向间距 28 → 32（矩形高 24，现在只剩 4px 间隙，折叠标记 `+N` 会贴边）；
- 深度间距 230 改为按最长标签估算：`const depthGap = Math.max(180, maxLabelChars * 12 + 80)`（中文 12px 字号约 12px/字），避免长对象名重叠。

**P1-4：容器尺寸兜底**

`width/height` 用 `container.getBoundingClientRect()` 取值，并在取不到高度（`clientHeight === 0`，页面刚切换时可能）时回退 500 之外，建议加一个 `requestAnimationFrame` 后再布局一次，避免首帧按 500px 算导致居中偏移。

## 四、验证清单

1. 本体视图：17 个节点应在画布中部聚成一团，节点直径 ≥ 20px，17 个对象名全部可见，不再需要手动放大。
2. 知识图谱：抽样模式下 ≤ 300 个实例，首屏 1 秒内稳定；若切到"全部"，需有明确的性能提示。
3. 类树：17 个根节点应垂直居中，最上/最下节点到容器上下边缘距离基本一致；缩放时不应发生跳位；点击节点展开后画布自动 refit。
