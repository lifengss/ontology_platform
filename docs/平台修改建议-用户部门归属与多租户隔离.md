# 平台修改建议：用户部门归属、租户隔离与管理员用户管理闭环

> 提出时间：2026-11-17
> 涉及需求：V2-05（RBAC）/ V2-06（多租户、部门隔离与共享等级）
> 状态：方案定稿，待实施

## 0. 版本与决策演进

| 版本 | 结论 | 说明 |
|---|---|---|
| v1 | 部门 = 租户别名 | **已废弃**。用户明确：一个租户可为多个部门做项目开发，**部门 ≠ 租户（1:N）**，二者独立建模、不互相派生。 |
| v2 | 用户增加独立 `department` 字段 + 管理员用户管理闭环 | 部门与租户解耦；补 Delete/禁用/Excel 导入。 |
| v3（本版，定稿） | 删除「禁用/删除」双操作独立可选 + 部门列表复用项目聚合 | 用户补充：删除不强制先禁用；「部门」下拉选项复用 `allDepartments()` 聚合（不新建部门表）。 |

## 1. 问题结论（已核实）

### 1.1 两种语义不同的维度（此前混淆）

| 概念 | 载体 | 语义 | 关系 |
|---|---|---|---|
| **租户 `tenant_id`** | 用户、项目均持有 | 组织/企业级**安全隔离边界**（`same_tenant` 判定） | 1 个租户可有多个部门 |
| **部门 `department`** | 项目持有（自由字符串） | 组织内**业务单元**/展示/筛选标签 | 1 个部门仅属于 1 个租户 |

**隔离判定走 `tenant_id`**（`backend/tenant.py` `same_tenant`、`router_projects.py:48` 按租户过滤），`department` 仅展示/筛选，无数据关联。

### 1.2 失效链

1. **前端创建用户不传 `tenant_id`**：`UserCreate`/`UserPatch` 支持 `tenant_id`（`schemas/auth.py:25,34`），但前端新增用户只提交 `{username, password, role}`（`app.js:6891`）→ 落缺省 `"default"`（`auth/__init__.py:393`）。
2. **项目继承创建人租户**：`router_projects.py:26` 项目 `tenant_id = user_tenant(user)`；因所有界面用户皆 `default`，界面创建的项目也全归 `default`。
3. **隔离判定恒真**：`same_tenant` 对大家均 `default` 恒真 → 跨部门隔离不生效；管理员只能靠 API 手动造非 `default` 数据。

### 1.3 用户管理能力缺口（本次补充确认）

| 能力 | 现状 | 缺口 |
|---|---|---|
| 管理员查看全量用户 | `GET /api/auth/users` 返回**全部**用户（`list_users` 不按租户过滤） | ✅ 无 |
| 修改用户角色/权限 | `PUT /api/auth/users/{id}` | ✅ 有（逐条保存，无批量） |
| 用户「部门」字段 | `UserCreate`/`UserPatch` **无 `department`**（`schemas/auth.py:20,28`）；`update_user` 白名单不含（`auth/__init__.py:407`） | ❌ 缺 |
| 删除用户 | `router_auth.py` 只有 POST/PUT/GET，**无 DELETE** | ❌ 缺 |
| 批量导入（Excel） | 无 `POST /api/auth/users/import` | ❌ 缺 |

### 1.4 普通用户 vs 管理员视角（已核实为现状，无需改）

- **前端**：`permission_matrix` 仅 `admin` 时把 `users`/`audit` 加入 `tabs`（`auth/__init__.py:462`）；前端 `applyPermissionMatrix`（`app.js:6803`）据 `op-hidden` 隐藏。普通用户看不到「用户与授权」tab。
- **后端**：`AUTH_ADMIN_PREFIXES = ("/api/auth/users", "/api/auth/roles", "/api/auth/audit", "/api/audit")`（`auth/__init__.py:63`），`required_action` 对 `/api/auth/users*` 一律要求 `admin` action。普通用户直接调 API 也 403。**双层保护已存在**。

> 即在权限隔离层，普通用户 vs 管理员**已正确区分**。本次补的是**管理员侧的用户管理能力**（部门字段/批量导入/删除），而非权限判定本身。

## 2. 方案选择（用户已确认）

1. **部门建模**：用户增加**独立 `department` 字符串字段**（如「研发部」「市场部」），仅作展示/归属标签；`tenant_id` 独立。**部门与租户不互相派生**。
2. **批量导入**：后端支持上传 **`.xlsx`** 批量添加用户（逐行：账号/密码/角色/部门/租户/权限），失败行返回明细。`openpyxl==3.1.5` 已在 `requirements.txt:34`，**无需新增依赖**。
3. **删除语义**：**禁用**与**删除**两种**独立**操作，**不强制先禁用**：
   - **禁用**（`disabled`）：可恢复（停用后不可登录，恢复后重新可用），保留数据。
   - **删除**：**完整删除用户数据与记录**（物理删除，含审计留痕）。
4. **部门列表来源**：用户「部门」下拉选项 = **复用现有 `allDepartments()` 聚合**（`app.js:196`，从项目提取 + 默认部门），**不新建部门表**；后端无部门接口。

## 3. 设计目标

1. **用户可归属部门**：用户界面可创建/编辑用户「部门」与「租户」，列表可见；部门下拉复用现有聚合。
2. **部门与租户独立**：`department`（展示）与 `tenant_id`（隔离）互不派生。
3. **管理员用户管理闭环**：全量列表 + Excel 批量导入 + 禁用/删除 + 修改角色/部门/权限。
4. **权限隔离不变**：普通用户仍看不到「用户与授权」，非 admin 调 `/api/auth/users*` 仍 403。
5. **向后兼容**：存量数据缺省 `default`/空部门，行为不变。

## 4. 数据模型

### 4.1 用户（需增 `department` 字段）

| 字段 | 类型 | 说明 | 变更 |
|---|---|---|---|
| `id` | str | 用户 id | 已有 |
| `username` | str | 账号 | 已有 |
| `password_hash` | str | PBKDF2 散列 | 已有 |
| `role` | str | `admin/modeler/reviewer/viewer` | 已有 |
| `grants` | list | 资源级授权 | 已有 |
| `tenant_id` | str | 租户归属，缺省 `default` | 已有（`_public_user` 已返回，`auth/__init__.py:264`） |
| `department` | str | **独立部门字段**，缺省空串 | **新增** |
| `disabled` | bool | 禁用标记 | 已有 |
| `locked_until` | int | 锁定截止 | 已有 |
| `failed_attempts` | int | 失败次数 | 已有 |
| `created_at` / `updated_at` | str | 时间戳 | 已有 |

### 4.2 项目（不改）

- `project.tenant_id`：租户归属（`project_store.py:45`，创建取创建人租户）。
- `project.department`：展示用部门名（`project_store.py:44`），**不与 `tenant_id` 做任何同步/派生**。

> **改动点**：项目「所属部门」仍为独立字符串，上一版「项目 department 与 tenant_id 跟随对齐」规则**取消**。

### 4.3 部门列表来源（复用聚合，不建表）

- 用户「部门」下拉选项 **复用 `allDepartments()`**（`app.js:196`）：`new Set([默认部门] ∪ state.projects.department ∪ homeProjects.department)`。
- 空项目时仅「默认部门」。后端**不新增**部门接口。

## 5. 后端改动

### 5.1 Schema（`backend/schemas/auth.py`）

- `UserCreate` 增加 `department: Optional[str] = None`。
- `UserPatch` 增加 `department: Optional[str] = None`。

### 5.2 用户服务（`backend/auth/__init__.py`）

- `create_user(...)`：新增 `department: str | None = None` 参数，写入 `"department": department or ""`。
- `update_user(...)`：`allowed` 白名单（`auth/__init__.py:407`）增加 `"department"`。
- `_public_user(...)`（`auth/__init__.py:258`）：返回中增加 `"department"`（`user.get("department", "")`）。
- 新增 `delete_user(user_id)`：物理删除 `auth_users` 记录。

### 5.3 路由（`backend/api/router_auth.py`）

- **DELETE `/users/{user_id}`**（仅 admin，`AUTH_ADMIN_PREFIXES` 已含 `/api/auth/users`）：
  - 目标用户不存在 → 404。
  - 审计 `user_deleted`（actor/target）。
  - 物理删除记录。
- **POST `/users/import`**（仅 admin，批量 Excel）：
  - 接收 `.xlsx` 上传（`UploadFile`，`python-multipart` 已有）。
  - 用 `openpyxl.load_workbook` 逐行解析（表头：账号/密码/角色/部门/租户/权限）。
  - 逐行 `create_user`，**失败行返回明细**（行号 + 原因），成功行统计。
  - 响应：`{created: n, failed: [{row, reason}], total}`。
  - 审计 `users_import`。
- **禁用/恢复**：复用现有 `PUT /users/{id}` 的 `disabled` 字段（`UserPatch.disabled`），语义即「可恢复的禁用」。

### 5.4 权限守卫（`backend/tenant.py`）

无需改。`same_tenant`/`user_tenant`/`ensure_project_access` 逻辑正确，用户 `tenant_id` 绑定后自然生效。

## 6. 前端改动（`frontend/index.html`、`frontend/app.js`）

### 6.1 「用户与授权」tab（`index.html:1554`）

1. **用户表新增「部门」列**：
   - `thead`（`index.html:1562`）加 `<th>部门</th>`；`colspan`（`app.js:6868`）相应 +1。
   - 行渲染（`app.js:6855`）加 `<td>` 显示 `u.department || '-'`。
2. **行内可编辑部门**：
   - 每行加部门下拉 `id="dept_${u.id}"`，选项复用聚合部门；`saveAuthUser`（`app.js:6872`）body 增加 `department`。
3. **新增用户表单加「部门」下拉**：
   - `index.html:1572` 加 `<label>部门<select id="newAuthDept">...</select></label>`（选项 = 聚合部门）；`createAuthUser`（`app.js:6885`）body 增加 `department`。
4. **新增「禁用/删除」按钮**：
   - 每行加「禁用/恢复」按钮：`saveAuthUser` 传 `disabled: true/false`。
   - 每行加「删除」按钮：`confirm` 后调 `DELETE /api/auth/users/{id}`。
5. **「批量导入」按钮**：隐藏 `<input type=file accept=".xlsx">`，上传后调 `POST /api/auth/users/import`，展示 `created/failed` 明细。

### 6.2 部门下拉选项函数（`app.js`）

- 新增 `authDepartmentOptions()`：复用 `allDepartments()` 返回的数组，供用户部门下拉渲染。

## 7. 数据迁移（用户选择：不迁移）

- 存量用户缺省 `tenant_id=default`、`department=""`，行为一致，不收紧。
- 若后续需给存量用户补 `department`，走一次性脚本（读 `auth_users` 写入），本方案不包含。

- 用普通用户（modeler/reviewer）登录，确认看不到「用户与授权」tab。

## 9. 风险与边界

1. **部门 ≠ 租户**：二者独立建模，`department` 仅展示/筛选，`tenant_id` 负责隔离。UI「部门」下拉跨租户展示由前端负责，后端不据此越权判定。
2. **物理删除风险**：删除清用户记录与审计目标引用。仅 admin 可删；删除前 `confirm`（文案提示「不可恢复」）。用户选择**不强制先禁用**。
3. **Excel 导入安全**：`.xlsx` 解析用 `openpyxl`；每行做与 `POST /users` 相同校验（账号唯一/密码 ≥8/角色合法/权限格式），失败行不阻断整体。
4. **MCP 静态 token**：`/mcp/{project}` 用项目静态 token 作租户边界，不携带访问者身份。本方案不改变此行为。
5. **`_public_user` 返回 `department`**：涉及 `GET /me`、`GET /users` 响应字段变化；据 `permission_matrix.tabs` 已保证仅 admin 访问用户列表，不影响普通用户。

## 10. 结论与建议

- **核心修复**：用户增加独立 `department` 字段，与 `tenant_id` 解耦（部门 ≠ 租户）。
- **管理员闭环**：新增 `DELETE /users/{id}`、`POST /users/import`（Excel），前端补删除/禁用/批量导入/部门列。
- **部门列表**：复用 `allDepartments()` 聚合，不新建部门表。
- **权限隔离**：普通用户 vs 管理员差异已是现状，无需改，仅补测试回归。
- **不迁移**：存量缺省 `default`/空部门，行为不变。
- **依赖**：`openpyxl` 已具备，无需新增。
