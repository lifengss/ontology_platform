# 企业业务本体平台 · 北向接口开发文档（能力层 / 业务逻辑层扩展）

> 适用范围：在**语义层（本体 + 实例）已就绪**的前提下，如何在之上**新增/扩展「能力层」（可复用的派生/断言计算）与「业务逻辑层」（编排工作流 + 受控回写）**。
> 配套：`API-INTERFACE-DOC.md`（全量接口）、`mcp_tools_contract.yaml`（MCP 工具契约）、`docs/成本核算模型` 相关（正向核算链路）。
> 版本：2026-11-16　|　同步本体 v3.9（22 对象）实测契约。

---

## 0. 分层定位与 no-code 红线（必读）

平台按**语义底座 + 能力层 + 业务逻辑层**分层，且**严格 no-code**：

| 层 | 承载 | 能否写脚本/代码 |
|---|---|---|
| 语义层 | 本体（TBox）+ 实例（ABox：对象/属性/关系/维表） | 建模/导入，无代码 |
| **能力层** | `capabilities`：`opl-expr` 表达式派生/断言/动作 | 仅**受限表达式**，无循环/递归/脚本 |
| **业务逻辑层** | `actions`（受控回写）+ `orchestration`（编排工作流） | 仅**控制节点 + Action 引用**，任何 code/script/表达式字段**一律拒绝** |

**no-code 红线（INV-3）**：
- 编排节点类型仅 `start / end / action / branch / confirm / capability_gap`；
- 参数值来源仅 `literal / field_ref / trigger_ctx`；
- 分支条件算子仅 `eq/ne/gt/ge/lt/le/contains/in_set/is_empty/is_not_empty` + `AND/OR`；
- 出现 `def / import / eval( / exec( / os.system / => / python -c` 等**代码特征 token 即拒绝**（`schemas/orchestration.py::CODE_PATTERN_TOKENS`）。

> **结论**：凡需要**循环、递归、排序、区间匹配、组合枚举、背包/最优化**的求解逻辑，**无法**在能力/动作层落地，须放**平台外脚本**（见 §5 边界示例）。这是平台刻意为之的设计（语义底座定位），不是缺陷。

## 1. 能力层扩展（`capabilities`）

能力 = 绑定到某对象类型的一段**受限表达式**，产出 `output_attribute`，可被其它能力 `ref()` 或 MCP `capability_call` 调用。

### 1.1 创建能力（`POST /api/capabilities`）

`CapabilityCreate` 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | str (1-64) | 能力唯一名，如 `cap_labor_cost_e`；用于 `ref()` 引用 |
| `display_name` | str? | 显示名 |
| `description` | str? | 说明 |
| `kind` | `derive` | `assert` | `act` | 默认 `derive`（派生值）；`act` 多用于触发回写侧 |
| `implementation` | `expression` | 目前仅 `expression` |
| `ontology_id` | str? | 能力所属本体 |
| `object_type` | str | 能力作用对象类型（如 `obj_maintenance_product`）——**determine `this` 属性取值来源** |
| `expression` | str | **白名单表达式**，见 §1.2 |
| `output_attribute` | str? | 输出属性 id（如 `attr_calc_o`），`execute` 后写入实例 |

例（真实，来自本工程）：

```json
{
  "name": "cap_total_cost_o",
  "kind": "derive",
  "implementation": "expression",
  "object_type": "obj_maintenance_product",
  "output_attribute": "attr_calc_o",
  "expression": "f = ref('cap_spare_direct_cost_q3')\nif(this.attr_has_aux_baseline,\n  round(if_null(ref('cap_labor_cost_e'), 0), 2) + round(if_null(f, 0), 2)\n    + round(if_null(ref('cap_spare_aux_cost_k'), 0), 2) + round(if_null(ref('cap_mgmt_cost_n'), 0), 2),\n  round(if_null(f, 0), 2))"
}
```

### 1.2 `opl-expr` 表达式语言（白名单 = 能力边界）

**支持**（`capabilities/expr_parser.py::WHITELIST_FUNCTIONS`）：

- 控制：`if / if_null / coalesce / ? :`（三元归一为 if）；短路求值
- 取值：`lookup(obj, {dims}, attr)`（严格，多命中报 `AMBIGUOUS`）、`lookup_first`（可排序）、`lookup_all`（多命中列表）、`coalesce_lookup`（优先级回退）
- 引用：`ref('cap_name'[, version])`（调用其它能力，构成链）
- 数值：`abs / round / min / max / str`
- 字符串/日期：`contains / starts_with / len / split / regex_match / upper / lower / date_add / date_diff`
- **声明式集合**（HF-07，无 lambda，字段名传参）：`sum / map / filter / group_by`（聚合仅 `sum/count`）
- 字面量：数字 / 字符串 / `true/false/null` / `{k: v}` 字典
- 属性：`this.<attr>`（实例属性）；绑定 `name = expr` 多行，最后一行为返回值

**不支持**：循环 `for/while`、递归（`MAX_DEPTH=64` 防环）、排序 `sort`、**区间匹配**（`lookup` 只按维度键精确匹配，无 `within_tol`）、**argmax / 组合枚举 / 背包最优化**。

**求值语义**（`expr_eval.py`）：`null` 传播（算术任一生效 null → null，显式 `if_null` 守卫）、除法 `DIV_ZERO`、`< >` 遇 null 报 `TYPE_ERROR`、`==/!=` 允许 null。定义期校验：白名单函数、参数个数、未知标识符、`ref()` 实参须为字符串、常量折叠除零。

### 1.3 校验 / 发布 / 执行

| 操作 | 端点 |
|---|---|
| 校验表达式 | `POST /api/capabilities/{cap_id}/validate`（或 `?draft_expression=<urlencoded>`） |
| 发布（active） | `POST /api/capabilities/{cap_id}/publish` |
| 执行（单条） | `POST /api/capabilities/{cap_id}/execute`，body `{instance_id, dry_run, inputs, channel}` |
| 批量执行 | `POST /api/capabilities/{cap_id}/execute-batch`（注意 HF-11：默认 limit=1000、建议分块 250/块） |
| 列版本/依赖 | `GET /api/capabilities/{cap_id}/versions`、`.../dependents`、`.../affected-instances` |

**执行语义（关键）**：
- `dry_run=True`：只算不写回，返回 `value` + `trace`（`inputs / null_inputs / lookups[{object_type,dims,matched_record_id,matched_code,selection_rule}] / refs`）——**trace 是逻辑链溯源与"是否直取"审计的现成通道**。
- `inputs` 为**覆盖 + 缺失回落实例存储值**（非整体替换）——可作为运行时维度覆盖（Q3/Q1 验证均用此）。
- `execute` 按**能力 id** 调用；按 name 会 NOT_FOUND。

## 2. 业务动作层扩展（`actions`，受控回写）

动作 = 把**已经算好的结果**（`input_map` 映射）通过既定渠道**回写到外部系统**，带风险分级/幂等/熔断/审计。

### 2.1 Action 定义（`POST /api/actions`）

`schemas/action.py` 关键字段：

| 字段 | 说明 |
|---|---|
| `kind` | `mcp_tool` | `webhook` | `rest` |
| `target_connection` | 目标 MCP 连接 / 外部系统 |
| `invoke` | `ActionInvoke`（调用细节，如 tool/url/method） |
| `input_map` | `dict[str,str]`：外部字段 ← 内部数据字段的映射 |
| `risk_level` | `low` / `medium` / `high`（V2-13 分级） |
| `idempotency_key` | 幂等键（已生效回写防重） |

### 2.2 执行与风险分级（`ActionEngine.execute`）

| 风险 | 行为 |
|---|---|
| `low` | 门禁（mapping_gate）通过 → **自动回写**；失败 → 不回写并记原因 |
| `medium` | AI 三条件评估；通过 → 自动回写；否则**升级人工确认**（返回 confirmation_token） |
| `high`（默认） | 返回 confirmation_token，**人工确认**后才回写 |

- `dry_run=True`：返回 `planned_payload` + 门禁预览（不吃写、不产生 token）。
- 回写后审计留痕（`action_id / idempotency_key / external_response / evaluation / trigger_source`）。
- **动作不产生、不计算数值**——它只承接"已算好的结果"的外发/落地。若要"算"，用能力层或平台外脚本。

## 3. 业务编排层扩展（`orchestration` 工作流）

编排 = 把**已发布的能力 / Action** 串成流程（顺序、条件分支、人工确认），供 `manual / event / cron` 触发。

### 3.1 节点类型（`WorkflowNode.kind`）

`start / end / action / branch / confirm / capability_gap`。

- `action`：引用已发布 Action（风险分级继承自 Action 层）。
- `branch`：条件分支，规则用受限算子 `eq/ne/gt/ge/lt/le/contains/in_set/is_empty/is_not_empty` + `AND/OR`；`is_default` 指定默认分支。
- `confirm`：人工确认节点（`confirm_title`）。
- `capability_gap`：AI/SOP 生成**未 grounded** 步骤；**存在即阻断发布**（保证不把未落地的能力缺口发布出去）。

### 3.2 参数/触发

- 参数值来源：`literal`（字面量）、`field_ref`（上游输出字段引用）、`trigger_ctx`（触发上下文），点分路径。
- 触发器：`manual / event（topic + required_ctx）/ cron（标准 5 段）`。
- 运行：`POST /api/orchestration/.../dry-run`（不产生外部调用）、`run`（正式执行）。

> **约定**：编排里**不能嵌入脚本**（no-code 红线）。需要"计算"时，把计算封装成**能力**（§1），再把该能力接入编排或由动作承接结果。需要"循环/枚举/优化"时，只能**平台外脚本**（§5）。

## 4. 北向接入：MCP 工具（供外部平台/Agent 调用）

MCP 端点 `/mcp/{project_id}` 暴露 6+ 工具（`docs/mcp_tools_contract.yaml`）：

| 工具 | 用途 |
|---|---|
| `ontology_query` | 查本体结构（对象/属性/关系），空 id 枚举已发布本体 |
| `instance_get` | 查已落库实例（`object_type/limit/offset/fields` 投影） |
| `capability_call` | **执行能力**（`capability` + `instance_id` + `dry_run` + `inputs`），返回四要素溯源 + `trace` |
| `term_lookup` | 数据字典查询（含外部系统只读） |
| `inference_trace` | OWL2-RL 推理链路 |
| `action_invoke` | 触发受控回写（`action_id` + `confirmation_token`） |

**北向扩展建议**：
- 对外暴露"能力"为主（`capability_call`），让外部平台把**语义层取值 + 能力计算**作为"事实来源"，外部再完成应用层决策（如反解/最优化）。
- 需要更强的"决策求解"时，新增 MCP 工具（如 `reverse_lookup/knapsack_solve`）——但**属代码改动**，须走审批与 `hotfix` 登记。

## 5. 能力边界与平台外承接（重要示例）

### 5.1 能在平台内做的（正向、单点、可派生）
- T1 单点查数：给定 `(机型,区域,条款)` → 能力链算出**单台成本**（人工/备件直接/备件辅助/管理/合计/占比）。
- T4 待核算补算：成本列全空的行，从基线 + BOM + 公式完整复算。
- T3 派生、T5 单机对比：汇率折算、O5−O3、占比 = O/R 等，均可用能力 `ref()` 链 + 查询完成。
- 基线/BOM 查数：`lookup` 各基线对象 + `sum/map` 聚合 BOM 行。

### 5.2 **不能**在平台内做的（需平台外脚本）
- **反解（T7）**：已知报价 → 反查机型/条款。需要"按值域区间匹配候选行"（`|成本−目标|≤0.01`），`opl-expr` 无区间匹配、无遍历候选枚举 → 平台外实现，平台提供`加成率(obj_rate_adjust)`与`单点成本(capability_call)`。
- **预算反推（T8）**：枚举 `机型×条款` 组合 + 背包取报价最高。需组合枚举 + argmax，能力层无法表达 → 平台外实现；平台提供候选成本（`capability_call`）与加成率。
- **条件聚合**（T2）：基于 D1 全量明细分组/中位数等，需全量行聚合；若 D1 未入平台则平台外完成。

### 5.3 平台外脚本工具（本工程交付）
- `cost_baseline_kit/tools_reverse.py`：反解（读 E2 → 平台 `obj_rate_adjust` 加成率 → 反解成本 → D1 候选匹配）；支持年限缺失时按 3/4/5 收敛、多解列全、无解拒答。
- `cost_baseline_kit/tools_budget.py`：预算（读 E3 → 候选组合枚举 → 加成率 → 标准报价 → 可行集取最优）；输出预算消耗率、剩余额度与归因（已吃满/跳档受限/顶配不足）。
- 二者通过**平台 `instance_get`（教训：加成率/报价读平台对象）+ `capability_call`（单点成本复算，可选）**取数，保持"语义层之上"。
- 全量自检：`tools_eval.py`（对 E2 50 单 / E3 24 单与 Q6/Q7 参考答案做开发期自检）。

## 6. 扩展工作流（Recommended）

1. **补齐语义层数据**：为缺的源数据建对象 + 导入实例（如 `obj_quote_record`、`obj_rate_adjust`；维表 `obj_machine_model/obj_region/obj_customer`；D1 明细视需要）。**请求类（E2/E3）建议不入库**，作为运行输入。
2. **用能力封装正向计算**：为每个可复用计算写能力（`expression`），用 `ref()` 连成链，`publish` 为 active。
3. **用动作承接结果外发**：需要回写外部系统时定义 `action`（选 `risk_level`，配 `input_map`/幂等键）。
4. **用编排串流程**：需要跨多步/条件/人工确认时建 `orchestration` 工作流（引用已发布能力/Action）。
5. **平台外承接决策求解**：反解/最优/背包等放外部脚本，平台提供取值与单点能力。
6. **变更治理**：凡影响已发布契约的 schema 变化，走 changeset（收紧约束触发 breaking → 升大版本 v4.0 + 审批）；改代码的扩展能力（新算子/新 MCP 工具）登记 `hotfix/hotfix.md`。

## 7. 变更治理与注意事项

- **changeset**：`POST /api/ontologies/{oid}/changesets`（body `{model: ...}`）；**收紧/删属性、改 pattern 收紧** 会触发 `INCOMPATIBLE_REQUIRES_MAJOR`（须升大版本 + 审批）。**放宽约束（如 pattern 置 null）同样被平台视为约束变化**，也可能判 breaking——新增对象时**一次性给足正确 schema**，避免事后调整。
- **对象必填字段**：`business_definition`（≥5 字符）、`stable_key`（须指向本对象某属性 id）；属性须带 `data_type/required/constraints`。
- **stable_key/编码 pattern**：`attr_*_code` 类常配 `^[A-Za-z0-9_\-]+$` 或 `^[A-Za-z0-9|\-]+$`——**注意兼容字符集**（曾因键串含中文/下划线不匹配 pattern 导致导入 0 条）。
- **MCP 鉴权**：`/mcp/{pid}` 用项目静态 token（`POST /api/mcp/server/token`，`Authorization: Bearer` 或 `?token=`）；`/api/*` 用全局登录 token（`POST /api/auth/login?mode=bearer`，8h 过期需重登）。
- **失败重试**：环境偶发 `PermissionError`/并发锁，能力 execute / instance_get 建议带重试；批量执行用分块 + 幂等。
