# 平台修改建议：实例列表被截断、树形导航栏计数失真

> 发现场景：服务产品成本本体导入 2297 条实例后，实例导入页左侧树形导航栏中
> 「售后人工成本基线」显示 100 条，其余 16 个对象全部显示 0 实例。
> 结论：**数据未丢失**（磁盘 2297 条完好），是三层叠加的读取/分页缺陷导致显示失真。

---

## 一、现象与实测

| 查询方式 | total | 返回内容 |
|---|---|---|
| 磁盘文件实际行数 | **2297** | 17 个 jsonl 文件，行数与导入量逐一吻合 |
| `GET /api/ingest/instances?project_id=..` | 1000 | 全部是 `obj_aftersales_labor_baseline` |
| `GET /api/ingest/instances?project_id=..&object_type=obj_customer` | **0** | 空（客户实际有 6 条） |
| `GET /api/ingest/instances?project_id=..&object_type=obj_material` | **0** | 空（物料实际有 93 条） |
| 前端树形导航栏 | 售后 100 / 其余 0 | 与上面一致 |

磁盘实测（`backend/data/projects/<pid>/instances/`）：

```
obj_aftersales_labor_baseline.jsonl  1372 行
obj_impl_labor_baseline.jsonl         244 行
obj_part_failure_baseline.jsonl       198 行
obj_machine_model.jsonl                53 行
obj_material.jsonl                     93 行
obj_resident_cost_baseline.jsonl      144 行
... （其余对象略）                    合计 2297 条
```

## 二、根因（三层叠加，按触发顺序）

### 第 1 层：`find()` 默认 limit=1000，`all()` 静默截断

`backend/core/instance_store.py:240-262`

```python
def find(self, object_type=None, filters=None, limit: int = 1000, offset: int = 0):
    ...
    matched = [r for r in candidates if _match(r)]
    return matched[offset : offset + limit]   # ← 截断

def all(self):
    return self.find()                         # ← :295-296，未传 limit，命中默认 1000
```

`all()` 语义应为「全量」，实际退化成「前 1000 条」。当前实例数 2297 已超限。

### 第 2 层：文件按字母序遍历，截断命中的恰好是同一个对象

`instance_store.py:252` 用 `sorted(self._dir.glob("*.jsonl"))` 遍历。
`obj_aftersales_labor_baseline.jsonl` 字母序排第一，且自身就有 1372 条，
于是前 1000 条**全部**来自这一个文件，其余 16 个对象的记录一条都没进入结果集。

### 第 3 层：路由在已截断的结果上做过滤

`backend/api/router_ingest.py:739-749`

```python
items = _instance_store_for(project_id).all()      # ← 已是截断后的 1000 条
if ontology_id:
    items = [it for it in items if it.get("ontology_id") == ontology_id]
if object_type:
    items = [it for it in items if it.get("object_type") == object_type]   # ← 在 1000 条售后里找客户 → 0
total = len(items)                                  # ← total 也随之失真
```

过滤没有下推到存储层，而是在截断后的快照上做，所以 `object_type=obj_customer` 恒为 0。

### 附加：单页上限 100，前端只取一页

- `backend/core/responses.py:95` `MAX_PAGE_SIZE = 100`，前端传 `pageSize=200` 会被夹到 100。
- `frontend/app.js:2518` 只请求第一页：

```js
// 后端 pageSize 上限 200（le=200）
const j = await api('/api/ingest/instances?ontology_id=' + ontologyId + '&pageSize=200');
```

注释（2506-2508）声称「一次拉全、切换对象零请求」，但实现只取单页，
实例数超过一页后树上计数只反映最新一页的内容。

> 另注：该请求未带 `project_id`。`project_id` 是 `Depends(project_id_param)` 必填依赖，
> 若未由前端 `api()` 统一注入，会退化为默认项目并查不到数据，建议一并确认。

## 三、修改建议（按优先级）

### P0 · 修复 `all()` 截断

`instance_store.py`：让 `all()` 返回真正全量，不受 `find()` 默认 limit 影响。

```python
def all(self) -> list[dict[str, Any]]:
    return self.find(limit=None)      # find 内需支持 limit=None 表示不截断
```

或更稳妥地给 find 一个大上限：

```python
def all(self) -> list[dict[str, Any]]:
    return self.find(limit=10 ** 9)
```

同时在 `find()` 里对 `limit=None` 分支不做切片。

### P0 · 路由过滤下推到存储层

`router_ingest.py:list_instances` 不再先 `all()` 再本地过滤，改为：

```python
filters = {}
if ontology_id:
    filters["ontology_id"] = ontology_id
if object_type:
    filters["object_type"] = object_type
items = _instance_store_for(project_id).find(filters=filters, limit=None)
```

`JsonlInstanceStore.find()` 已支持 `filters` 参数，直接可用。
这样 `total` 才是过滤后的真实总数，不再受截断影响。

### P1 · 新增轻量计数端点（推荐用于树形导航）

实例规模继续增长后，「拉全量到本地过滤」会越来越重。建议新增：

```
GET /api/ingest/instances/counts?ontology_id=..
→ { "obj_customer": 6, "obj_material": 93, ... }
```

后端按文件行数统计（`count(object_type)` 已有实现），几乎零成本。
前端树形导航栏直接消费该端点显示实例数，不必拉全量。

### P1 · 前端：要么翻页拉全，要么改用计数端点

- 方案 A（配合 P1）：树形导航调用 counts 端点；实例列表仍按页请求。
- 方案 B：若坚持「一次拉全」，需按 `total` 循环翻页直到取完，
  并给出明确的规模上限提示（例如超过 5000 条时提示改用筛选）。

当前 `app.js:2518` 的单页请求必须改掉，否则实例数超过 100 就会再次失真。

### P2 · 分页上限与语义澄清

- `MAX_PAGE_SIZE = 100` 与前端注释「上限 200」不一致，建议统一并同步注释。
- 建议在后端对「实例总数超过单页上限」给出明确信号（如响应头带 `X-Total-Count`），
  避免前端误以为取到了全量。

## 四、影响面提醒

同一条 `all()` 链路被多处复用，截断会影响的不只是树形导航，建议一并排查：

- 图谱页 knowledge 模式的节点数
- 「全部实例」列表与搜索/过滤结果
- 首页项目统计 `instance_count`
- 实例血缘 / 关系查询（前端注释 2507-2508 提到依赖这份全量缓存）

---

## 五、临时验证办法（不改代码核对真实数据）

磁盘文件是权威事实，可直接核对：

```
backend/data/projects/<project_id>/instances/<object_type>.jsonl
```

每个文件一行一条实例，行数即该对象实例数。当前本体合计 2297 条，与导入量一致。
