## 一、主表「通用服务器原厂维保」的结构理解（重大校正）

### 1.1 之前认知（不足）
- 曾把 A~S 列当成「最终输出成本 list」。
- 曾把 A 列「国内 / 欧洲（德国）」当成区域实体的枚举上限。

### 1.2 校正后理解
**主表是真·二维核算表（两行表头）**，A~S 不是「纯输出」，而是 **维度键 + 从基线取数的输入 + 本表公式计算的输出** 三类混合。下表为逐格核定结果（v2 更正 F / P / Q / R 四列性质）：

| 列 | 第1行(分组) | 第2行(列名) | 性质 | 实测公式（第 3 行） |
|---|---|---|---|---|
| A | 区域 | — | **用户输入项**（段标题） | `国内` |
| B | 服务类型 | — | 维度键 | `三年5×10×NBD` |
| C | 人工成本 | MA成本基线 | 取数（外链） | `='[1]售后人工成本基线（国内）'!$D$10` |
| D | — | 现场服务率 | 取数（外链）+ 年限上浮 | `=[1]现场服务率基线!$D$9` |
| E | — | MA人工成本 | **计算** | `=D3*C3` |
| F | 备件直接成本 | 备件直接成本 | **本表计算链的输出**（v1 误标为「取数」） | `=AA67`（引用本表场景块） |
| G | 备件辅助成本 | 辅助成本基线 | 取数（外链） | `=[1]备件辅助成本基线!$L$4` |

| K | — | 备件辅助成本 | **计算** | `=H3*G3`（国内）；海外见第四节 |
| L | 管理成本 | 管理成本基线 | 取数（外链） | `=[1]管理成本基线!$E$10` |

| N | — | 管理成本 | **计算** | `=L3*M3` |
| O | 成本合计 | — | **计算** | `=E3+F3+K3+N3` |

> **最终「成本 list」** = E、F、K、N 四项 + O 合计（+ S 派生占比）；C/D/G/L/R 是支撑它的取数/中间值。
> **实测锚点**：第 3 行 `O=209.83`、`R=37,672`、`S=0.557%`；主计算区为 **行 3~35 共 33 行**，A 列仅行 3「国内」、行 18「欧洲（德国）」两个标记，其余沿用上方。
> **这张表是「一台示例机型的核算模板/算例」，不是全量成本 list**——多机型 / 区域 / 客户 / 批次的下发清单是按此模板批量套算的产物（赛题包 `D1` 的 122,500 行即模拟该批量结果）。

### 1.3 关键校正点：A 列(区域)是用户输入项，不是枚举上限
- 两个段标题各自向下覆盖一段数据行（国内 15 行、欧洲德国 18 行，共 33 行），**只是示例/输入筛选**，不代表区域实体只能取这两个值。
- 真实区域/国家有 30+ 个（见 5.1 的 obj_region 修复）。**这是最典型的「把示例输出当取值维度限制」的认知误区。**

## 二、G（单台备件辅助成本基线）取值规则（v2 深化）

### 2.1 之前认知（不足）
- 曾不确定「国内有单台 ND / 单台 4H 两个值，该取哪个」。
- v1 归纳为「含 4H/2H 取 4H，否则取 ND；海外 RMA/ARMA 行取 RMA/ARMA」。

### 2.2 校正后理解：**G 由服务条款的「主体口径」决定，四档取数**

源表海外块（行 18~29）的 G 列公式给出了明确规律，取《成本基线.xlsx》「备件辅助成本基线」的四列之一：

| 行 | 服务条款 | G 取数列 | 口径 |
|---|---|---|---|
| 18~20 | 一年 ARMA + 二/三/四年 RMA（组合服务） | `单台(RMA)` N 列 | **组合服务取 RMA，不取 ARMA** |
| 21~23 | 三/四/五年 ARMA（纯 ARMA） | `单台(ARMA)` O 列 | 纯 ARMA 整段取 ARMA |
| 24~26 | 三/四/五年 5×9×NBD 现场 | `单台(ND)` L 列 | 现场 NBD 取 ND |
| 27~29 | 三/四/五年 7×24×4H 现场 | `单台(4H)` M 列 | 现场 4H 取 4H |

**为什么组合服务取 RMA 而不是 ARMA**：三年里两年跑的是 RMA，辅助成本（仓储/配送/正向逆向物流）是服务期内按次发生的持续成本，取覆盖期最长的口径；且德国单台 ARMA=794.21 > RMA=653.24，按 RMA 计不会因第一年的 ARMA 整体抬高。佐证：备件直接成本 F 那边反而做了真混合（F18=AG67，按年数加权），说明做表人清楚组合服务要混合，只是辅助成本上选择了简化。

**国内两档**：ND=88.74、4H=151.40，响应速度不同 → 单位备件与配送成本不同，含 4H/2H 取 4H、否则取 ND。

### 2.3 v2 对「待业务确认」的推进
- **海外标准行取 ND 还是 4H**：源表已有答案——按条款主体取（NBD 现场 → ND，4H 现场 → 4H），不需再猜。
- **2H 是否并入取 4H**：源表只有 ND/4H 两档、无「单台 2H」列；F 列明确 2H 与 4H 同价（`F9=F6`），G 列 2H 行的具体取法仍建议业务确认一句，但按「条款主体」原则应归入 4H 档。

## 三、【v2 新增】备件直接成本 F 的完整计算链（本次审核最大增量）

v1 与《数据缺口清单》把 F 理解为 `F = Σ(数量 × 单价 × 故障率)` 加几条附加规则。逐格核对后发现：**F 是源表内一条完整、可复算的三级链路，「平台算不出」是因为没导入数据，不是源表逻辑缺失。**

### 3.1 三层结构（全部在「通用服务器原厂维保」同一 sheet 内）

```
① 整机 BOM 静态区  U~Z 列，行 2~61
   V=部件PN  W=描述  X=数量  Y=单价  Z=X×Y 物料小计；Z62=SUM(Z2:Z61)=37,672
        ↓ AS3=Z53（按组抓取物料成本）；AT=故障率外链《部件故障率基线》
② 基础数据块  AN~BX 列（及 RMA 镜像块 BZ~DJ）
   一行 = 部件类型 × 厂商 × 保修期限 × 返修政策
   BD~BR 四项损耗 → BS~BU 逐年成本 → BV~BX 三年/四年/五年「累计」备件成本
        ↓ 回写
③ BOM 行右侧计算列  AA~AK，行 2~61
   AA=三年故障率；AB/AD/AF=三/四/五年备件成本；AG~AJ=不返还/RMA 口径
   AB62=SUM(AB2:AB61) 等 8 个合计行
        ↓
④ 场景块 66~69 行（口径取数表）→ 主计算区 F 列
```

### 3.2 「归集规则」（docx 4.1 原文）
> 只选取 CPU、内存、硬盘、GPU、网卡/智能网卡/RAID卡/SAS卡/HBA卡这几类物料；按厂商分组；**机型中未装配的厂商分组留空**。其余螺钉、标签、线缆、散热器、风扇、电源、机箱、背板、Riser 卡等通用件归入「其他部件」，仍按既有逻辑核算。

- **「归集」= AS 为该「物料类型×厂商」组下所有 BOM 部件成本之和**；本机每类恰好一个厂商一行，故 AS=该行 Z。
- **AS/AT 只有 5 行有值是明文规则的结果，不是数据缺失**：docx 4.4 归集核对表列的正是这 5 行（CPU\|Intel 200/0.00304/0.454、内存\|三星 4672/0.00396/3.831、硬盘 1932/0.01289/6.946、博科 160/0.00868/1.646、SND 501/0.00248/0.690），并注明「示例机型为机头（不含 GPU），故 GPU 各组留空」。其余厂商行（HYGON/海力士/西数/各类 GPU）是**预留槽位**。
- **「既有逻辑」** = 通用件就地算 `AB=Z×AA`、`AC=AA/3×1.1`、`AD=AB+Z×AC`；其中自研板卡/背板/Riser 卡额外乘 `30%`（对应「返料 30% 不能返修」）、结构件全额进成本——**不可套统一模板**。
- **最原始 BOM 三要素**：本表 U~X（PN/描述/数量）+ `成本基线.xlsx`「备件成本」表（Y 列单价由 XLOOKUP 按「工厂 1600 + PN」双条件查得）+「部件故障率」表（故障率）。
- **5 个手填单价 100**（印刷品/机箱/导风罩/标签/CPU）经用户定性为**避免真实价格泄露的人工脱敏改值，不是数据缺口**；不要向业务部追问这几颗 PN 的报价。CPU 单价被压到 100 使其下游备件成本绝对值极小，是脱敏的连带结果，不影响结构可复算性。

### 3.3 「回写」写到哪里
**不是写回 U~Z 静态 BOM**，而是在每行物料右侧新开的 **AA~AK 计算列**填上该行自己的备件成本。仅 5 个关键部件引用块的累计列（CPU→BV3、内存→BV8、硬盘→BV12、RAID卡→BV30、网卡→BV31），其余就地 `Z×AA` 现算。这样每个物料行同时携带「物料成本 Z」与「备件成本 AB」，`AB62` 求和即得整机三年备件成本。

### 3.4 场景块与 F 列口径（v1 完全未覆盖）

场景块第 66 行是列标签，67/68/69 行对应三/四/五年；**F 列不计算，只按服务条款查表**：

| 口径列 | 定义 | 三年实测值 | F 列引用它的条款 |
|---|---|---|---|
| AA | NBD 基准 = AB62 | 17.082 | 三/四/五年 5×10×NBD → `AA67/68/69` |
| AB | 4H = AA×1.15 | 19.644 | 4H → `F×1.15`（与 AB 列等价）；2H 同 4H |
| AC | 硬盘不返还 = AG59 | 24.899 | 硬盘介质保留 → `AC67/68/69` |
| AD | 数据不返还 = AG59+AG56+AG36+AG27 | 46.713 | 数据介质保留 → `AD67/68/69` |
| Y / Z | RMA=AH62 / ARMA=AA67 | 14.551 / 17.082 | 纯 ARMA → `Z67/68/69` |
| AG | 一年 ARMA + 二年 RMA 按年加权 | 15.395 | 海外组合服务 → `AG67/68/69` |

- **不返还口径改用 AG 列**（`AG=Z×AA` 全额新件，不走精细模型的残值/返修抵扣）：坏件客户留着不退回，厂商无法返修回收残值。三年硬盘不返还比 NBD 贵约 46%，数据不返还约 2.7 倍。
- **组合口径**：`AG67 = Z67/3 + Y67/3×2`；四/五年用增量式 `AG68=AG67+(Y68−Y67)`。
- 口径分流的业务含义：**同一台机器、同一份 BOM，服务承诺不同（响应多快 / 坏件退不退 / 用哪种返修方式），厂商承担的备件成本就不同**。这也是赛题把「条款」设为五键之一、让加成率随条款变化的原因。

### 3.5 对平台的含义
平台若要补齐 F 的重算，需要落地的不是「一张 BOM 表」，而是四类数据：① 整机 BOM 明细（PN/数量）；② 物料单价（按工厂+PN 查）；③ 部件故障率；④ **按物料类型×厂商的保修期限 / 返修政策 / 周转期 / 残值率等精细模型参数**，外加⑤ 场景块的条款口径矩阵。源表 U~Z、AN~DJ、66~69 三块已把这些全部写出来了，可直接作为建模依据。**具体怎么补，见下一节「三·补」。**

### E. 计算链在公式引擎中的表达（修正《计算能力与公式引擎》5.2）

该文档 5.2 把 F 写成 `F = sum(this.配置部件.map(p => p.单价 * p.故障率))`——这只覆盖了「其他部件」那一拨，会把关键件算错。按核定链路改为**两级**：

```
-- 第 1 级：每个 BOM 行算出三年备件成本（对应源表 AB 列）
for item in this.配置部件:
    if item.group_key != null:                 # 关键 5 类：引用分组累计列 BV
        item.spare_y3 = lookup(obj_spare_cost_group,
                              {group_key: item.group_key}, "attr_cum_y3")
    elif item.failure_rate_3y != null:          # 其他部件：就地算 Z×AA
        item.spare_y3 = item.line_cost * item.failure_rate_3y * item.special_factor
    else:
        item.spare_y3 = 0                      # 螺钉/标签/包装：故障率空

-- 第 2 级：汇总 + 按条款查场景表（对应 AB62 → 66~69 → F）
base_y3 = sum(this.配置部件.map(i => i.spare_y3))          # = AB62 = 17.082
F = lookup(obj_spare_cost_scenario,
           {scenario_code: 条款→口径映射, year: 年限}, "attr_value")
```

「条款 → 口径」是**映射表**（不是硬编码数值，符合「基线只能 lookup」铁律）：
`NBD→AA`、`4H/2H→AB`（或 `base×1.15`）、`硬盘介质保留→AC`、`数据介质保留→AD`、`纯 ARMA→Z`、`ARMA+RMA 组合→AG`、`现场 NBD→Z`、`现场 4H→Z×1.15`。

> 依赖：公式引擎 **G7 聚合与分组**能力（该文档已建议「从 P1 提到 P0」），本方案的第 1 级 `sum(map(...))` 直接依赖它。

### F. 分三步落地 + 验收锚点（数值均已由源表核定）

| 阶段 | 做什么 | 验收锚点 |
|---|---|---|
| **P0** | 导入 `obj_product_bom_item` + 复用单价/故障率，跑通第 1 级就地算 | `Z62=37,672`；`AB62=17.082`；CPU 行 `AB53=BV3=0.454`、硬盘行 `AB59=BV12=6.946` |

### G. 四条必须守住的红线

1. **脱敏值不还原**：5 个手填 100 是避免价格泄露的人工改值，按原值导入，不向业务部追问真实单价。
2. **lookup 必须带工厂**：物料单价按 `attr_material_code`（工厂+PN）查，印证差异表 D8 / 问题清单 C1；Y 列 XLOOKUP 实测即 `(A:A="1600")×(B:B=PN)` 双条件。
3. **「未装配槽位留空」≠ lookup 未命中**：归集规则明文留空，是合法状态；平台「lookup 未命中必须报错、不补默认值」的铁律在此处是**适用边界**，别把留空误判为失败。
4. **「其他部件」不套统一模板**：自研板卡 ×30%、结构件全额进成本，必须逐行带 `special_factor`；docx 第 57 段明确要求「以表内具体公式为准，不应直接套用统一模板」。

## 四、【v2 新增】备件辅助成本 K 的口径差异（真实源表 / docx / 赛题包）

### 4.1 真实公式与「设计了但没喂数」
源表海外行（K18，德国）实际公式：

```
K = H × G + I × J × 1.1 × 1.02
```

| 变量 | 含义 | 取数位置 |
|---|---|---|
| H | 现场服务率（海外） | 本表 H 列，基础率取自《成本基线.xlsx》现场服务率基线海外块 |
| G | 单台备件辅助成本基线 | 「备件辅助成本基线」海外块 L/M/N/O 列（按条款主体，见第二节） |
| I | 备件消耗（金额） | `=AL62` —— **AL62 是无表头、无公式、无值的空白单元格**，AL 列整列为空，故 I≡0 |
| J | 综合税率 | 外链「备件辅助成本基线」P 列（德国 0.19、美国 0.10、巴西 1.02…） |

- 由 I≡0 可推：I19=I18+I18/3×1.1=0、I20=I19+I18/3×1.1×1.1=0，**整条 I 链全为 0**；第二项恒为 0，**真实海外行实际就是 K = H×G**（德国验证 0.2157×653.24=140.87 ✓）。
- 因此 **税率 J 与 1.1、1.02 两个系数在交付表上从未生效**，整套「叠加税/保险」机制是设计了但没喂数的状态。AL 列只是恰好与合计行同行号、紧挨 AK62 右边一格，此前把它解读为「场景汇总块」是过度解读。

### 4.2 三处口径不一致（平台实现时务必分辨）

| 来源 | 海外 K 公式 | 说明 |
|---|---|---|
| **真实源表**（求值后） | `K = H × G` | I≡0，税项未生效 |
| **赛题包生成端** `cfg.aux_cost` | `K = H × G × (1+税率) × 1.02` | 把税率与汇率缓冲乘在**整个** H×G 上；属仿真数据的有意设定，文档 `R-06` 已写清、三方自洽，不改 |
| **docx 文字描述** | 「在基线上叠加额外税/保险等系数」 | 描述的是公式设计意图（针对备件消耗 I 项加税），**不能按文字直接实现** |

> **对平台的直接风险**：若按 docx 那句「叠加税/保险」去实现海外 K，会凭空多出 5%~100%+（巴西税率 1.02 翻倍）；正确做法是以表内求值结果 `K=H×G` 为准。
