## 结论与部署建议

- 时延目标冻结在最小并发档（单请求稳态口径，与 GAP-03 一致）；其余档为吞吐观测。
- 单请求热路径剖析：list ~16ms / stats ~20-35ms（快照＋排序视图缓存命中）。
- 本基准交付过程中发现并修复 4 个真实性能问题：① rdflib/pyparsing SPARQL 解析
  非线程安全（并发 422，加模块级解析锁＋双检缓存＋语法校验结果缓存）；
  ② 实例列表/统计每请求全量物化 O(N)（快照缓存＋排序视图缓存）；
  ③ 知识图谱每请求全量构造（响应缓存按数据版本失效）；
  ④ GAP-15 后台对账循环全量重建 TTL 与压测互相污染（压测环境禁用）。
- Windows 基准口径：uvicorn 多进程 accept 倾斜（无 SO_REUSEPORT），数字随场景波动；
  生产建议 Linux + uvicorn workers=N(核数)，500 并发档时延受 GIL/worker 数结构性约束。
